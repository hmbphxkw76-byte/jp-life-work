# 输入润色与确认门禁

`AGENTS.md` 硬性规约：任务型输入必须先润色、再确认、后执行。本 skill 给出模板与边界。

## 触发

- **触发**：用户要求 Agent 执行动作（写码 / 改文件 / 跑命令 / 生成报告 / 调研 / 提交 / 推送等）。
- **不触发（直接回答，不进入本门禁）**：纯提问、确认（「确认」「继续」「好的」）、补充信息、闲聊，
  以及**句末为问号（`？` / `?`）的疑问句**。
- **强制触发**：不可逆或影响共享状态的操作（push、删文件、改 main、发外部消息）——即使用户语气随意；
  但若该输入句末为问号，按「不触发」直接回答。
- **判定口径**：以输入整体意图为准；「是否要求执行动作」与「句末是否问号」均为机械判定，任意 IDE / 模型一致执行。

## 三步

### 1. 润色（不执行）

重构为五段：

```
【目标】<一句话说要达成什么>
【背景】<必要上下文：仓库 / 文件 / 前序约定>
【约束】<边界、禁忌、必须遵守的规范（AGENTS.md / 命名 / 来源分级等）>
【期望输出】<交付物、格式、验收标准>
【原意核对】<是否改变原意；歧义点列出请裁定>
```

- 保持原意；补充的是结构，不是替用户改需求。
- 不新增用户没要的任务，不删减用户的要求。
- 歧义不擅自假设，列入【原意核对】。

### 2. 展示（停住）

完整展示：

```markdown
## 待确认提示词

**【目标】** …
**【背景】** …
**【约束】** …
**【期望输出】** …
**【原意核对】** …

请回复「确认执行」，或直接给出修改版。
```

展示后结束回合：不调用工具、不执行、不预写文件。

### 3. 执行（严格按最终版）

- 以用户**最后给出**的版本为准（含修改版）；不再二次润色。
- 严格执行，不自行扩展、不改写、不增补。
- 遇到必须由用户决策的分叉：停下询问。
- 若确认版有误 / 不可行：停下说明，请用户重新确认，不擅自改。

## 反例

- 收到任务就直接开跑，事后再解释。
- 展示后顺手把第一步做了。
- 确认后「顺便」加了用户没要的东西。
- 把用户的修改版又润色一遍再执行。
