# 日本 防灾·安全·治安 首期基线报告提示词（市场指标监测型）

> **用途**：执行「日本 防灾·安全·治安 监测机制」的**机制建立**任务：产出首期基线报告与配套指标登记册，作为后续月度监测与事件触发的对比锚与制度基础。
> **现状**：本业务线基线将于 2026-11 产出（[reports/{{YYYY-MM}}-<slug>.md](../reports/{{YYYY-MM}}-<slug>.md)，v1.0）。**正常运行永不重跑基线提示词**；仅在①报告与登记册全部丢失（灾难恢复），或②经维护规范批准的十节结构重排时启动。
> **产出**：md 源稿，落盘 `{{OUTPUT_PATH}}`；指标活值与研究边界档案回写 `{{REGISTRY_PATH}}`。
>
> **继承声明（四层体系）**：本文件 = [通用基座](../../src/report_templates/prompt-generic-base.md) × [监测报告通用规范](../../src/report_templates/monitoring-common-spec.md) × [基线报告类型模板（市场指标监测型）](../../src/report_templates/market-monitoring/prompt-baseline-setup-template.md) × [业务专属配置](./business-config.md)。冲突时以本文件为准。

## 一、项目专属硬性约束

1. **受众与结论边界**：面向已在日或拟赴日的外国人；输出防灾与安全的情报渠道、应急联络与条件化建议，**不构成法律意见**；不替代官方预警与应急指令。
2. **来源语言规则**：日文官方一手 + 英文权威优先；中文来源仅作线索。
3. **术语口径**：避難指示 ≠ 避難勧告 ≠ 警戒レベル；防災メール ≠ 防災行政无线 ≠ 多言語防災気象情報；110 ≠ 119；災害用伝言ダイヤル 171 ≠ 救急安心センター #7119。
4. **边界纪律**：就医与急救医疗口径链接 15；在留风险、取消・退去与灾害时外国人支援政策环境链接 08 / 09；地域防灾情报渠道正文链接 13；多文化共生政策正文链接 12；家族带同与育儿链接 18。
5. **类型机制适配**：本业务线为个人安全与防灾决策支持，非市场定价监测；市场指标监测型的 K/RL 阈值信号、供给情景重算、五态合成等机制不适用（无价格 / 成交 / 供给类指标），改以[业务配置第八节](./business-config.md)追踪表 + 第七节触发器 + 监测日历承载监测职能。

## 二、来源优先级

见[业务配置第五节](./business-config.md)：① 総務省消防庁 / 気象庁 / 内閣府・防災庁 / 外務省 / 警察庁 ＞ ② 地方自治体 ＞ ③ 観光庁 Safety tips / JNTO / NHK WORLD-JAPAN / 地域国際化協会 ＞ ④ 媒体（仅线索）。每条数据附官方原文 URL 与版本日期。

## 三、基线锚定与重启条件

- 基线报告一经产出即为对比锚：十节结构、口径裁决与已核实结论由后续月 / 年报告完整继承。
- **正常运行不重跑**。重启仅限两种情形：①灾难恢复（报告与登记册全部丢失）；②十节结构经维护规范批准重排。重排须在[业务配置](./business-config.md)版本记录留痕，并同步评估各周期提示词。

## 四、报告结构

十节固定骨架见[基线类型模板第三节](../../src/report_templates/market-monitoring/prompt-baseline-setup-template.md)，本主题固化标题见[业务配置第 3.2 节](./business-config.md)：

| 节 | 模块 |
|---|---|
| 1 | 执行摘要：结论先行 |
| 2 | 持续监测机制设计 |
| 3 | 多维指标体系与来源 |
| 4 | 首期基线数据（2026-11-14） |
| 5 | 先行指标判读 |
| 6 | 信号规则与决策框架 |
| 7 | 月 / 季 / 年监测日历 |
| 8 | 数据治理：来源分级、口径优先与核验状态 |
| 9 | 风险、局限与监测盲区 |
| 10 | 交付物与后续运行方式 |

- 十节标题为固化锚，逐字继承，不得增删节或调整顺序。
- 内容必须覆盖防灾体制、避难与情报、治安与人身、领事保护、应急联络五维，不得写成单纯「电话清单」。

## 五、追踪表与边界档案

按[业务配置第八节](./business-config.md)的 12+1 项追踪指标逐项核对并填写「是否更新」；运行后回写 `{{REGISTRY_PATH}}` 的核心指标与[研究边界档案](./business-config.md)（领域边界、五维分层、主体清单与入选标准、口径清单）。未核实项注明「待核实」，不补值、不外推；prompt 模板内不填活值。

## 六、执行方式（建议）

1. 并行启动 2–4 个研究子代理：① 气象与避难；② 自治体防灾与多语言情报；③ 治安与领事保护；④ 应急联络与急救分诊。全部限定日 / 英来源、逐点引用，每条数据附可直接访问的 URL。
2. 主代理合并差异，冲突口径保留双份引用，无法核实项单列「待复核清单」。
3. 与 12 / 13 / 15 / 08 交叉核对（只读锚，不回写）。

## 七、渲染与交付

- 交付格式：md 源稿；后续周期运行可用 `python src/prompts-tools/tools/md2html.py` 生成同目录自包含 HTML，并过 `python src/prompts-tools/tools/lint_reports.py`。
- 基线导航采用简化锚点目录，不强制 `.report-nav`。
- 落盘后将[业务配置第一节](./business-config.md)的 `{{BASELINE_REPORT_PATH}}` 指向本报告（重建场景）。
