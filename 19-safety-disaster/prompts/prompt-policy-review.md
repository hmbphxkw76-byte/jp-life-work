# 日本 防灾·安全·治安 月度监测与事件触发提示词（市场指标监测型）

> **用途**：运行期统一入口，覆盖月度监测 / 事件触发解读 / 年度台账复盘 / 个人情况变化四类节拍。以一手 / 权威来源为依据、以指标登记册为编号骨架、以上一期报告与首期基线为对比锚，完成「核验 → 判定 → 偏离 → 缺口 → 观察」闭环。
> **产出**：月度报告落盘 `{{OUTPUT_PATH}}`（`reports/{{YYYY-MM}}-<slug>.md`）；事件触发解读件 `reports/{{YYYY-MM}}-<slug>.md`（命名不在标准正则内时 `validate.py` 仅 WARN 不阻断，属预期）。
>
> **继承声明（四层体系）**：本文件 = [通用基座](../../engine/report_templates/prompt-generic-base.md) × [监测报告通用规范](../../engine/report_templates/monitoring-common-spec.md) × [月度报告类型模板（市场指标监测型）](../../engine/report_templates/market-monitoring/prompt-monthly-monitor-template.md) × [业务专属配置](./business-config.md)。冲突时以本文件为准。

## 运行变量（每次运行前填写）

```
{{CURRENT_DATE}}         = 本次执行日期，格式 YYYY-MM-DD
{{CYCLE}}                = 月度监测 / 事件触发 / 年度复盘 / 个人情况变化
{{TRIGGER_TYPE}}         = 事件触发时填（新政策 / 修订 / 细则 / 统计发布 / 大规模灾害 / 个人情况变化）
{{PREVIOUS_REPORT_PATH}} = 上一期报告路径（如无则空，仅锚定基线）
{{BASELINE_REPORT_PATH}} = reports/{{YYYY-MM}}-<slug>.md
{{REGISTRY_PATH}}        = data/safety_disaster_indicator_registry.md
{{OUTPUT_PATH}}          = reports/{{YYYY-MM}}-<slug>.md
{{REPORT_VERSION}}       = 本次版本号，格式 vYYYY.MM.DD
```

固定值（不填，读自业务配置第一节）：`{{REGION}}`、`{{TOPIC}}`、`{{FRESHNESS_PRIORITY}}`、`{{SOURCE_LANGUAGE_RULE}}`、`{{REPO_RAW_URL_BASE}}`。

**任务目标**：完成月度核验闭环；按[业务配置第七节](./business-config.md)触发器判定；无触发且窗口未到时不启动，不得虚构变化。

## 一、节拍与触发

- **T+0 / T+1 判定**：气象与防灾类来源按官方发布节奏核对最新一期标题与发布日期；与上期同日或仅隔 1 日时，明确写「本期为 T+1 刷新，官方发布窗口未开，价值在于核验、口径澄清」，不得为制造变化而虚构变化。
- **触发器**（[业务配置第七节](./business-config.md)）：
  - 気象庁警報・警戒レベル体系或配信渠道变化；
  - 自治体防災計画・避難所・防災メール / 防災行政无线变化；
  - 多言語防災気象情報 / Safety tips / 情報難民政策变化；
  - 消防庁救急安心センター / 救急体制变化；
  - 警察庁犯罪统计 / 特殊诈欺与生活安全政策变化；
  - 外務省海外安全情报 / 领事保护机制变化；
  - 大规模灾害 / 突发事件 → 事件触发解读；
  - 个人定居地 / 通勤路线 / 家庭构成变化 → 个人情况变化件；
  - 12 / 13 / 15 / 08 已修正事实清单追加 → 对应文档回写。
- **无触发 → 降级为核验 / 收敛型轻运行。**

## 二、项目专属硬性约束

1. **受众与结论边界**：输出防灾与安全的情报渠道、应急联络与条件化建议，不构成法律意见；不替代官方预警与应急指令。
2. **来源语言规则**：{{SOURCE_LANGUAGE_RULE}}（仅英文 / 日文来源，杜绝中文来源；见[业务配置第一节](./business-config.md)）。
3. **口径纪律**：避難指示 ≠ 避難勧告；防災メール ≠ 防災行政无线 ≠ 多言語防災気象情報；110 ≠ 119；171 ≠ #7119。
4. **边界纪律**：就医与急救医疗口径链接 15；在留风险与取消・退去链接 08 / 09；地域防灾渠道正文链接 13；多文化共生政策正文链接 12；家族带同与育儿链接 18。
5. **类型机制适配**：无 K/RL 阈值信号与供给情景；信号判定以[业务配置第八节](./business-config.md)追踪表 + 监测日历承载。

## 三、各模块更新要点

按[业务配置第 3.3 节](./business-config.md)的维度逐模块实例化：

- **防灾体制**：自治体防灾计划、避難所、防灾行政无线；动态获取避難所位置与风险地图。
- **避难与情报**：気象警報・警戒レベル、防災メール、多言語防災気象情報、Safety tips、情報難民支援。
- **治安与人身**：警察庁犯罪统计、特殊诈欺与生活安全窗口。
- **领事保护**：外務省海外安全情报、在外公館、护照与遗失。
- **应急联络**：110 / 119 / 災害用伝言ダイヤル 171 / 救急安心センター #7119 / JNTO Visitor Hotline。

## 四、基线锚定与防回退

- 读取 `{{PREVIOUS_REPORT_PATH}}`（如无则空）与 `{{BASELINE_REPORT_PATH}}`，继承结构与全部已核实结论。
- 逐条继承「已修正事实清单」，产生修正后追加（格式见[通用基座第五节](../../engine/report_templates/prompt-generic-base.md)）；严禁重新引入已被推翻的说法；无来源不得入清单。
- 上年判断逐条复判，原文保留。

## 五、追踪表与登记册联动

按[业务配置第八节](./business-config.md)的 12+1 项追踪指标逐项核对并填写「是否更新」；运行前从 `{{REGISTRY_PATH}}` 读活值 → 复核有效性 → 运行后回写。产出数据变更摘要与待复核清单；未核实项单列「待复核清单」。prompt 模板内不填活值。

## 六、执行方式（建议）

1. 按维度并行启动研究子代理（气象与避难 / 自治体防灾与多语言情报 / 治安与领事 / 应急联络），全部限定日 / 英来源、逐点引用。
2. 主代理读取 `{{PREVIOUS_REPORT_PATH}}` 与基线做差异合并，继承已修正事实清单，应用第三节要点。
3. 冲突数据保留双份引用；无法核实项单列「待复核清单」。
4. 回写报告与登记册；如需 HTML，运行 `python engine/tools/md2html.py` 并运行 `python engine/tools/lint_reports.py` 校验。

## 七、渲染与交付

- 交付格式：md 源稿；月度报告含顶部导航（`.report-nav`），`.nav-url` = `{{REPO_RAW_URL_BASE}}` + `/reports/{本期文件名}`。
- HTML 须通过 `lint_reports.py` 标签配对校验。
- 基线报告常驻 `reports/` 顶层不归档；报告按周期保留（月度 18 / 季度 24 / 年度 60 个自然月，超出移入 `reports/archives/`）。

## 八、质量自检（通用清单之外的本主题专属项）

- [ ] 电话与渠道口径准确（110 / 119 / 171 / #7119 / Visitor Hotline），未混用
- [ ] 避難指示 / 避難勧告 / 警戒レベル 已区分
- [ ] 防災メール / 防災行政无线 / 多言語防災気象情報 已区分
- [ ] 追踪表 12+1 项均已核对并填写「是否更新」
- [ ] `{{REGISTRY_PATH}}` 已读已写，变更摘要与登记册一致
- [ ] 数据缺口状态标签规范（未发布 / 缺席 / 未取得 / 未重算 / 无官方值 / 未核验）
- [ ] 数据变更摘要与待复核清单已产出

## 落盘后审计（提交前必做）

落盘后依次运行 `python engine/tools/audit_preflight.py --report <报告相对路径>`、`python engine/tools/audit_check.py --report <报告相对路径>`，修正全部 P0/P1 后执行 `python engine/tools/audit_pipeline.py --submit --report <报告相对路径>` 提交审计（未通过初审不得合并）。
