## 一、项目专属硬性约束

1. **官方原文铁律**：媒体 / 自媒体转述仅作线索；引用逐条附官方原文 URL 与版本日期。中文来源（商务部、国家移民管理局、gov.cn、npc.gov.cn）为 A 级一手；日文来源（出入国在留管理庁、厚生労働省、e-Gov、OTIT）为 A 级一手。无官方依据的金额 / 期限 / 要件一律写「⚠ 待核实」，禁止补值、不外推。
2. **只盯官方文本**：不采集舆论反应；原文有歧义处并列多解，不静默择一。
3. **结论边界**：不构成法律意见或税务意见；合规应对建议标「建议」；重大合规决策提示咨询执业法律 / 税务专业人士。
4. **术语口径**：送出機関 ≠ 認定送出機関；对外劳务合作 ≠ 劳务派遣；保証金 ≠ 違約金 ≠ 解約金；黑名单 ≠ 官方公示；技能実習 ≠ 特定技能 ≠ 育成就労；备案 ≠ 许可；受入計画 ≠ 支援計画。
5. **边界纪律**：在留资格制度正文归 08；行业监测 / 薪资 / 驾照归 01；渠道矩阵与雇主生态正文归 02；法规条文深度解读归 09；赴日落地归 14；退出 / 转型 / 回国归 16。

## 二、来源优先级

见[业务配置第五节](./business-config.md）：① 中国商务部 / 国家移民管理局 / gov.cn / npc.gov.cn；①′ 出入国在留管理庁 / 法務省 / e-Gov / 厚生労働省 / 外国人技能実習機構 ＞ ② 地方商务主管部门 / 地方入管 / 都道府県労働局 / ハローワーク / 地方自治体 ＞ ③ 驻日使领馆 / 中国驻外使领馆 ＞ ④ 行业机构（OTIT / JITCO）＞ ⑤ 媒体（仅线索）。每条数据附官方原文 URL 与版本日期。

## 三、基线锚定与重启条件

- 基线报告一经产出即为对比锚：中日监管框架地图、核验路径、解读规则与已核实结论由后续事件触发解读完整继承。
- **正常运行不重跑**。重启仅限两种情形：①灾难恢复（报告与登记册全部丢失）；②九节结构经维护规范批准重排。重排须在[业务配置](./business-config.md)第十二节版本记录留痕，并同步评估解读提示词。

## 四、报告结构

九节固定骨架见[基线类型模板（职业就业调研型）第三节](../../src/report_templates/employment-research/prompt-baseline-setup-template.md)，本主题映射见[业务配置第 3.3 节](./business-config.md)：

| 节 | 模块 |
|---|---|
| 1 | 核心结论（摘要） |
| 2 | 行业与政策发展趋势（中日中介监管框架与无资质法律后果） |
| 3 | 招募渠道与中介市场（核心模块：渠道矩阵 + 骗术图谱） |
| 4 | 渠道与主体类型细分 |
| 5 | 资质要件与核验技能 |
| 6 | 官方名单与公示（含黑名单） |
| 7 | 合同逐条审查清单与行动建议（建议章） |
| 8 | 数据可靠性与局限说明 |
| 9 | 参考来源清单 |

- 九节标题为固化锚，逐字继承，不得增删节或调整顺序。
- 内容必须覆盖「招募·渠道 / 资质·核验 / 合同·风险·后果」三段；不得把主题写成单纯防骗清单。

## 五、追踪表与边界档案

按[业务配置第八节](./business-config.md)的 10+1 项追踪指标逐项核对并填写「是否更新」；运行后回写 `{{REGISTRY_PATH}}` 的核心指标与[研究边界档案](./business-config.md)（领域边界、三段分层、主体清单与入选标准、口径清单）。未核实项注明「待核实」，不补值、不外推；prompt 模板内不填活值。

## 六、执行方式（建议）

1. 原文回溯先行：逐渠道核对中日官方原文，完成台账登记后才进入解读环节。
2. 并行启动 2–4 个研究子代理：① 中国侧（商务部名单 / 620 号令 / 841 号令 / 备案办法）；② 日本侧（ISA 認定送出機関 / OTIT / 特定技能）；③ 合同与费用（厚生労働省 / e-Gov 労働基準法）；④ 黑名单与救济（行政処分公表 / 咨询窗口）。全部限定官方来源、逐点引用，每条数据附可直接访问的 URL。
3. 主代理合并差异，冲突口径保留双份引用，无法核实项单列「待复核清单」。
4. 与现行制度冲突的解读须并列新旧对照（如技能実習 → 育成就労的 2027-04-01 切换）。

## 七、渲染与交付

- 交付格式：md + 同目录自包含 HTML（`python src/prompts-tools/tools/md2html.py`）；HTML 须通过 `python src/prompts-tools/tools/lint_reports.py`。
- 基线导航采用简化锚点目录，不强制 `.report-nav`。
- 落盘后将[业务配置第一节](./business-config.md)的 `{{BASELINE_REPORT_PATH}}` 指向本报告（重建场景）。
