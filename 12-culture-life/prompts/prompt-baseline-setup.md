## 一、项目专属硬性约束

1. **受众与结论边界**：面向在日本从事货运司机工作、需要职场文化适应与日常生活落地的读者；经验类内容须与制度类内容分离存放并标注个案（见[业务配置第二节](./business-config.md)）。
2. **来源语言规则**：制度类须日文官方原文；经验类不限（标注为个案）。
3. **术语口径**：法规义务 ≠ 职场惯例；健康保险 ≠ 国民健康保险；敷金 ≠ 礼金；「先輩後輩」等文化描述标注为一般化观察。
4. **边界纪律**：维权流程链接 09、地域选择与生活成本链接 13 / 07、税费社保年金链接 07、现场安全制度链接 02、在留手续链接 08；本报告只写生活制度 + 手续 + 适应框架。
5. **内容边界**：保险费率、自付上限、给付比例等活值只入 `{{REGISTRY_PATH}}`，正文只写制度结构与查询入口；租金行情活值归 13 / 07 登记册。

## 二、来源优先级

见[业务配置第五节](./business-config.md)：① 厚労省 / 総務省 / 自治体 ＞ ② JILPT / 公共機関调查 ＞ ③ 地域自治体多语言生活指南 ＞ ④ 在日生活门户与社区（经验类，标注个案）。每条数据附完整 URL，每格活值附 `[来源, 年份]`。

## 三、基线锚定与重启条件

- 基线报告一经产出即为对比锚：结构、口径裁决与已核实结论由后续周期更新完整继承。
- **正常运行不重跑**。重启仅限两种情形：①灾难恢复（报告与登记册全部丢失）；②九节结构经维护规范批准重排。重排须在[业务配置](./business-config.md)第十二节版本记录留痕，并同步评估周期更新提示词。
- 现状：首期基线保留现行结构（业务固化锚），结构映射见[业务配置第 3.2 节](./business-config.md)。

## 五、追踪表与边界档案

按[业务配置第八节](./business-config.md)的 7 项追踪指标逐项核对并填写「是否更新」；运行后回写 `{{REGISTRY_PATH}}` 的核心指标与[研究边界档案](./business-config.md)（领域边界、制度分层、主体清单与入选标准、口径清单）。未核实项注明「待核实」，不补值、不外推；prompt 模板内不填活值。

## 六、执行方式（建议）

1. 并行启动 1–2 个研究子代理：① 劳动制度与职场调查；② 生活手续与自治体支援。全部限定日 / 英来源、逐点引用，每条数据附可直接访问的 URL。经验类内容作为个案沉淀单独标注。
2. 主代理合并差异，冲突口径保留双份引用，无法核实项单列「待复核清单」。
3. 与 09-politics-law（维权流程）、07-economy-finance（税费社保年金）、02-career-driver（现场安全）、08-visa-immigration（在留手续）交叉核对边界（只读锚，不回写）。

## 七、渲染与交付

- 交付格式：md + 同目录自包含 HTML（`python src/prompts-tools/tools/md2html.py`）；HTML 须通过 `python src/prompts-tools/tools/lint_reports.py`（免责声明双条件）。
- 基线导航采用简化锚点目录，不强制 `.report-nav`。
- 落盘后将[业务配置第一节](./business-config.md)的 `{{BASELINE_REPORT_PATH}}` 指向本报告（重建场景）。

## 八、质量自检（通用清单之外的本主题专属项）

- [ ] 法规义务与职场惯例已区分，习惯性做法未表述为法定要求
- [ ] 经验类内容全部标注为个案，未与制度类事实混存
- [ ] 与 09-politics-law、08-visa-immigration 的联动触发器正确
- [ ] 医疗章节未硬编码费率 / 上限，活值均落在 `{{REGISTRY_PATH}}`
- [ ] 追踪表 7 项均已核对并填写「是否更新」
- [ ] `{{REGISTRY_PATH}}` 已读已写：变更摘要与登记册一致；prompt 模板自身无硬编码活值
- [ ] HTML 通过 lint（免责声明双条件 + 标签配对）
