# 日本 · 物流行业 · 年度刷新提示词（行业深度研究型）

> **用途**：每年固定窗口对物流行业全景做全量刷新；行业结构性事件触发器命中时提前插刷对应模块。可直接复制，替换顶部变量后提交给 AI 执行。
> **产出**：刷新版报告落盘 `{{OUTPUT_PATH}}`（`reports/{{YYYY-MM}}-<slug>.md` + 同名 HTML）；插刷件 `reports/{{YYYY-MM}}-<slug>.md`（命名不在标准正则内，validate 仅 WARN 不阻断，属预期）。
>
> **继承声明（四层体系）**：本文件 = [通用基座](../../engine/report_templates/prompt-generic-base.md) × [监测报告通用规范](../../engine/report_templates/monitoring-common-spec.md) × [年度刷新类型模板（行业深度研究型）](../../engine/report_templates/industry-research/prompt-annual-refresh-template.md) × [业务专属配置](./business-config.md)。冲突时以本文件为准。

---

## 运行变量（每次运行前填写）

```
{{CURRENT_DATE}}         = 本次执行日期，格式 YYYY-MM-DD
{{PREVIOUS_REPORT_PATH}} = 上一年度刷新版路径（首年刷新时为空，仅锚定基线）
{{BASELINE_REPORT_PATH}} = reports/{{YYYY-MM}}-<slug>.md
{{REGISTRY_PATH}}        = data/logistics_industry_indicator_registry.md
{{OUTPUT_PATH}}          = reports/{{YYYY-MM}}-<slug>.md
{{REPORT_VERSION}}       = 本次版本号，格式 vYYYY.MM.DD
```

**任务目标**：完成「口径复核 → 数据刷新 → 格局更新 → 趋势复判」闭环；上年趋势判断逐条对照实际进展（命中 / 部分命中 / 未命中），复判结论与依据并列，**上年判断原文保留不删除**；继承已修正事实清单；无触发且窗口未到时不启动，不得虚构变化。

## 一、节拍与触发

年度刷新 + 重大事件插刷设计见[年度刷新类型模板第一节](../../engine/report_templates/industry-research/prompt-annual-refresh-template.md)。业务触发器清单（`事件 → 受影响模块`）见[业务配置第七节](./business-config.md)：

```
- 物流白書 / 交通白書新版发布 → 01 产业概览
- EC / 冷链 / 3PL 市场规模权威新估计 → 02 增长赛道
- `2024年問題` 对策新进展（锚 01 #9） → 01 / 04
- 自动驾驶 / 自动化重大政策进展（本主题写产业影响；技术细节联动 05） → 03
- SPPI 月次更新（锚 01 #8） → 04 行业数据跟踪
- 行业结构性事件（大型合并 / 大型倒産 / 监管重构 / 技术代际切换） → 对应模块提前插刷
```

## 二、项目专属硬性约束

1. **中性立场**：不给投资评级、不出具 Go/No-Go 决策建议；趋势复判结论与依据并列。
2. **口径纪律**：多口径并列不合并；口径修订留痕；EC 物流 / 冷链 / 3PL、SPPI / WebKit、TDB / TSR 不得混用。
3. **边界纪律**：技术路线与制度细节归 05、技能岗位归 06、在留制度归 08、法规条文归 09。
4. **交叉验证锚**：宏观数字与 01-ssw-driver 最新报告 / 登记册 #7 / #8 / #9 只读核对；冲突回官方原文复核，由 01 主责更新，本主题不得独立回写。

## 三、各模块更新要点

按[业务配置 3.3 节](./business-config.md)的结构映射逐模块实例化：

- **产业概览（对应产业链图谱 / 规模与格局 / 头部玩家）**：物流白書最新版规模与结构数据；事业者数与中小区分；头部玩家清单复核与进出登记（附来源）。
- **增长赛道（对应规模与格局 / 驱动与风险）**：EC / 冷链 / 3PL 规模与增速的最新权威估计，多口径并列并标注口径与年份；驱动因素证据更新。
- **自动化与技术趋势（对应驱动与风险 / 趋势判断）**：仓储自动化普及数据、无人配送实证、政策进展的**产业影响**；技术路线与法规细节只给结论并链接 05。
- **行业数据跟踪（对应数据治理与局限 / 参考来源清单）**：SPPI、倒産件数、運賃上涨率、司机缺口等时序更新；时间序列表结构保持。

> 若本期按九节骨架重排：九节标题逐字继承基线（或经批准的骨架），不得增删节或调整顺序；重排须在[业务配置](./business-config.md)版本记录留痕。

## 四、基线锚定与防回退

- 读取 `{{PREVIOUS_REPORT_PATH}}`（首年刷新为空）与 `{{BASELINE_REPORT_PATH}}`，继承结构与全部已核实结论。
- 逐条继承「已修正事实清单」，产生修正后追加（格式见[通用基座第五节](../../engine/report_templates/prompt-generic-base.md)）；严禁重新引入已被推翻的说法；无来源不得入清单。
- 上年趋势判断逐条复判，原文保留；不得删除或改写上年判断。

## 五、追踪表与登记册联动

按[业务配置第八节](./business-config.md)的四维度逐项核对并填写「是否更新」；运行前从 `{{REGISTRY_PATH}}` 读取活值与研究边界档案 → 复核有效性 → 运行后回写（口径变更留痕、玩家进出登记）。数据变更摘要至少覆盖全部研究维度与口径清单；未核实项单列「待复核清单」。

## 六、执行方式（建议）

1. 按研究维度并行启动研究子代理（产业概览 / 增长赛道 / 自动化 / 行业数据），全部限定日 / 英来源、逐点引用，每条数据附可直接访问的 URL。
2. 主代理读取 `{{PREVIOUS_REPORT_PATH}}` 与基线做差异合并，继承已修正事实清单，应用第三节更新要点。
3. 冲突口径保留双份引用；无法核实项单列「待复核清单」。
4. 回写报告与登记册后运行 `python engine/tools/md2html.py` 重新生成 HTML，并运行 `python engine/tools/lint_reports.py` 校验。

## 七、渲染与交付

- 交付格式：md + 同目录自包含 HTML；年度刷新报告含顶部九锚点导航（`.report-nav`），`.nav-url` = `{{REPO_RAW_URL_BASE}}` + `/reports/{本期文件名}`。
- HTML 须通过 `lint_reports.py` 标签配对校验。
- 基线报告常驻 `reports/` 顶层不归档；年度刷新版按保留策略执行（年度保留 5 期，超出移入 `reports/archives/`）。

## 八、质量自检（通用清单之外的本主题专属项）

- [ ] 结构逐字继承基线（或经批准的九节骨架），无增删节、无顺序调整
- [ ] 已修正事实清单已继承并续写，无回退
- [ ] 上年趋势逐条复判，原文保留，反向声音至少 2 条
- [ ] EC 物流、冷链、3PL 已区分；SPPI 与 WebKit 未混算；倒産标注 TDB / TSR 口径
- [ ] 与 01-ssw-driver 最新报告 / 登记册 #7 / #8 / #9 交叉验证一致，未越界回写
- [ ] 与 05 / 06 / 08 / 09 分工正确，未重复展开
- [ ] 追踪表 4 项均已核对并填写「是否更新」
- [ ] `{{REGISTRY_PATH}}` 已读已写，变更摘要与登记册一致
- [ ] 数据变更摘要与待复核清单已产出
- [ ] HTML 通过 lint（标签配对）

## 落盘后审计（提交前必做）
