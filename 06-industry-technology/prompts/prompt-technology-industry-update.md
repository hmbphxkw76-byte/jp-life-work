## 一、主题专属硬性约束

通用约束（逐点引用、事实与推断分离、口径标注等）自动继承通用规范第一至四节。本主题额外强制：

1. **受众定位**："阶段 4 技术/数字化扩展"准备库：物流数字化技能地图、数字化岗位与转型路径、数字化劳动市场与岗位行情。与 04-industry-logistics（产业趋势）、05-industry-autonomous（自动化）互补：本主题写**个人技能与岗位对接**；03 章只写"技能-岗位-行情"，在留资格与日语审查要件一律交叉引用 visa-immigration 手册 05 章，禁止重写。
2. **术语口径区分**（正文中不得混用）：
   - WMS ≠ TMS ≠ WCS；
   - 「オペレーター」≠「システム担当」≠「改善/分析岗」；
   - 技能等级自评须注明评估标准版本。

## 二、来源优先级（通用框架的本主题实例化，冲突时报双份并标注）

① 国土交通省/経済産業省（物流 DX 政策、GX、IT 人材需給試算；meti.go.jp）＞ ② IPA（DX 動向・IT 人材调查系列；ipa.go.jp）、厚生労働省（外国人雇用実態調査、賃金構造基本統計調査；mhlw.go.jp）＞ ③ 日本ロジスティクスシステム協会、WMS/TMS 主要厂商（Netsuite、楽天ロジスティクス、CASSA 等）官方资料 ＞ ④ 求人门户与薪资调查（doda.jp、levtech.jp、求人ボックス等；预期指标）＞ ⑤ 技术学习平台（官方文档优先）

**来源台账域名（03 章行情类必查）**：ipa.go.jp、meti.go.jp、mhlw.go.jp、jisa.or.jp（経産省对外发布载体之一）、doda.jp、levtech.jp、求人ボックス（xn--pckua2a7gp15o89zb.com）。薪资/缺口数值更新后回写 `{{REGISTRY_PATH}}`。

## 四、更新协议 + 事件触发器表

刷新窗口与差异对比规则继承通用模板。本主题**必查重大事件触发器**（命中任一项即触发对应文档重点更新；无触发则降级为核验/收敛型轻运行，**不得为制造变化而虚构变化**）：

```
- 物流 DX 政策/补贴新动向 → 01
- 目标数字化岗位采用条件变化 → 02
- 新工具/系统技能需求出现 → 01/02
- 个人技能里程碑（证书/项目完成） → 01/02
- IPA/経産省 IT 人材需給・DX 動向调查发布/年度更新（含 2030 缺口推计修订） → 03
- doda/レバテック等薪资调查年度发布/更新 → 03
- 外国人 IT 就业统计/政策变化（厚労省雇用実態調査、在留・日语要件相关） → 03（在留要件变化本身 → visa-immigration 手册 05 章）
```

## 七、执行方式（建议）

1. 启动 1–2 个并行研究子代理：① 物流 DX 政策与技能需求；② 数字化岗位求人抽样。触发 03 章事件时追加：③ IT 人材需給/薪资带/外国人就业行情核对（meti/ipa/mhlw/doda/レバテック）。全部限定日/英来源、逐点引用，**每条数据必须附可直接访问的 URL**；求人门户数据标注为预期指标。
2. 子代理返回后，由主代理读取 `{{HANDBOOK_PATH}}`（单份知识手册）与受影响章节当前版本做差异合并，**继承已修正事实、应用第四、五节更新要点**。
3. 对冲突数据保留双份引用；对无法核实项单列"待复核清单"。
4. 回写完成后运行 `python prompts/tools/md2html.py 06-industry-technology/reports` 重新生成 HTML；运行 `python prompts/tools/archive_reports.py` 执行保留策略。
