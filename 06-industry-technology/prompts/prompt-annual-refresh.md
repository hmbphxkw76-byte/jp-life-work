# 日本 · 技术与数字化 · 年度刷新提示词（行业深度研究型）

> **用途**：每年固定窗口对技术与数字化全景做全量刷新；行业结构性事件触发器命中时提前插刷对应模块。可直接复制，替换顶部变量后提交给 AI 执行。
> **产出**：刷新版报告落盘 `{{OUTPUT_PATH}}`（`reports/{{YYYY-MM}}-<slug>.md` + 同名 HTML）；插刷件 `reports/{{YYYY-MM}}-<slug>.md`（命名不在标准正则内，validate 仅 WARN 不阻断，属预期）。
>
> **继承声明（四层体系）**：本文件 = [通用基座](../../src/report_templates/prompt-generic-base.md) × [监测报告通用规范](../../src/report_templates/monitoring-common-spec.md) × [年度刷新类型模板（行业深度研究型）](../../src/report_templates/industry-research/prompt-annual-refresh-template.md) × [业务专属配置](./business-config.md)。冲突时以本文件为准。

## 运行变量（每次运行前填写）

```
{{CURRENT_DATE}}         = 本次执行日期，格式 YYYY-MM-DD
{{PREVIOUS_REPORT_PATH}} = 上一年度刷新版路径（首年刷新时为空，仅锚定基线）
{{BASELINE_REPORT_PATH}} = reports/{{YYYY-MM}}-<slug>.md
{{REGISTRY_PATH}}        = data/technology_industry_indicator_registry.md
{{OUTPUT_PATH}}          = reports/{{YYYY-MM}}-<slug>.md
{{REPORT_VERSION}}       = 本次版本号，格式 vYYYY.MM.DD
```

**任务目标**：完成「口径复核 → 数据刷新 → 格局更新 → 趋势复判」闭环；上年趋势判断逐条对照实际进展（命中 / 部分命中 / 未命中），复判结论与依据并列，**上年判断原文保留不删除**；继承已修正事实清单；无触发且窗口未到时不启动，不得虚构变化。

## 一、节拍与触发

年度刷新 + 重大事件插刷设计见[年度刷新类型模板第一节](../../src/report_templates/industry-research/prompt-annual-refresh-template.md)。业务触发器清单（`事件 → 受影响模块`）见[业务配置第七节](./business-config.md)：

```
- 物流 DX 政策 / 补贴新动向 → 01
- 目标数字化岗位采用条件变化 → 02
- 新工具 / 系统技能需求出现 → 01 / 02
- 个人技能里程碑（证书 / 项目完成） → 01 / 02
- IPA / 経産省 IT 人材需給・DX 動向调查发布 / 年度更新（含 2030 缺口推计修订） → 03
- doda / レバテック等薪资调查年度发布 / 更新 → 03
- 外国人 IT 就业统计 / 政策变化（厚労省雇用実態調査、在留・日语要件相关） → 03（在留要件变化本身 → 08）
```

## 二、项目专属硬性约束

1. **中性立场**：不给投资评级、不出具 Go/No-Go 决策建议；趋势复判结论与依据并列。
2. **口径纪律**：多口径并列不合并；口径修订留痕；WMS / TMS / WCS、IT 人才缺口情景值、转职登录者 / 官方赁金 / 企业公开值不得混用。
3. **边界纪律**：产业趋势归 04、自动化技术归 05、在留制度与日语审查要件归 08、法规条文归 09、资格教育归 10。
4. **交叉验证锚**：与 04 / 05 最新报告只读核对；冲突回官方原文复核，不得独立回写他主题。

## 三、各模块更新要点

按[业务配置 3.3 节](./business-config.md)的结构映射逐模块实例化：

- **物流数字化技能地图（对应产业链图谱 / 头部玩家）**：三层技能框架更新、物流系统概念（TMS / WMS / CRM / EDI）、证明方式与资源入口。
- **数字化岗位与转型路径（对应驱动因素与风险 / 趋势判断）**：公司内转岗 / 跳槽 / SaaS 厂商三条路径、JD 关键词对照、评估节点。
- **日本数字化劳动市场与岗位行情（对应市场规模与格局 / 数据治理与局限）**：IT 人材需給推计与缺口数、薪资带新值（賃金構造基本統計調査 / doda / レバテック）、外国人就业统计与日语门槛分布；在留资格与日语审查要件只交叉引用 08 手册 05 章。

> 若本期按九节骨架重排：九节标题逐字继承基线（或经批准的骨架），不得增删节或调整顺序；重排须在[业务配置](./business-config.md)版本记录留痕。

## 四、基线锚定与防回退

- 读取 `{{PREVIOUS_REPORT_PATH}}`（首年刷新为空）与 `{{BASELINE_REPORT_PATH}}`，继承结构与全部已核实结论。
- 逐条继承「已修正事实清单」，产生修正后追加（格式见[通用基座第五节](../../src/report_templates/prompt-generic-base.md)）；严禁重新引入已被推翻的说法；无来源不得入清单。
- 上年趋势判断逐条复判，原文保留；不得删除或改写上年判断。

## 五、追踪表与登记册联动

按[业务配置第八节](./business-config.md)的六维度逐项核对并填写「是否更新」；运行前从 `{{REGISTRY_PATH}}` 读取活值与研究边界档案 → 复核有效性 → 运行后回写（口径变更留痕、主体进出登记）。数据变更摘要至少覆盖全部研究维度与口径清单；未核实项单列「待复核清单」。

## 六、执行方式（建议）

1. 按研究维度并行启动研究子代理（DX 政策与技能 / 岗位抽样 / 行情核对），全部限定日 / 英来源、逐点引用，每条数据附可直接访问的 URL；求人门户数据标注为预期指标。
2. 主代理读取 `{{PREVIOUS_REPORT_PATH}}` 与基线做差异合并，继承已修正事实清单，应用第三节更新要点。
3. 冲突口径保留双份引用；无法核实项单列「待复核清单」。
4. 回写报告与登记册后运行 `python src/prompts-tools/tools/md2html.py` 重新生成 HTML，并运行 `python src/prompts-tools/tools/lint_reports.py` 校验。

## 七、渲染与交付

- 交付格式：md + 同目录自包含 HTML；年度刷新报告含顶部九锚点导航（`.report-nav`），`.nav-url` = `{{REPO_RAW_URL_BASE}}` + `/reports/{本期文件名}`。
- HTML 须通过 `lint_reports.py` 标签配对校验。
- 基线报告常驻 `reports/` 顶层不归档；年度刷新版按保留策略执行（年度保留 5 期，超出移入 `reports/archives/`）。

## 八、质量自检（通用清单之外的本主题专属项）

- [ ] 结构逐字继承基线（或经批准的九节骨架），无增删节、无顺序调整
- [ ] 已修正事实清单已继承并续写，无回退
- [ ] 上年趋势逐条复判，原文保留，反向声音至少 2 条
- [ ] WMS / TMS / WCS 已区分；「オペレーター」/「システム担当」/「改善・分析岗」已区分
- [ ] IT 人才缺口情景值未合并；转职登录者 / 官方赁金 / 企业公开值未混算
- [ ] 技能等级自评均注明评估标准版本
- [ ] 与 04 / 05 最新报告交叉验证一致，未越界回写
- [ ] 追踪表 6 项均已核对并填写「是否更新」
- [ ] `{{REGISTRY_PATH}}` 已读已写，变更摘要与登记册一致
- [ ] 03 章在留资格与日语审查要件未重写，仅交叉引用 08 手册 05 章
- [ ] HTML 通过 lint（标签配对）
