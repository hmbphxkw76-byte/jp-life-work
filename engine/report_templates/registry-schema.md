# 指标登记册 Schema 规范（registry-schema）

> **定位**：`report_templates/` 通用层的**登记册结构标准**。规定指标登记册（`data/*_indicator_registry.md`）活值表的 Schema 定义、口径字段语义与判定规则，供登记册编写、`info_quality_check.py`（C-08 / C-10 / C-13）与人工审计共同消费。
> **上位依据**：[通用基座 · 第七节 指标台账协议](./prompt-generic-base.md)、[监测报告通用规范](./monitoring-common-spec.md)。
> **程序化实现**：`engine/tools/info_quality_check.py` 的 `_live_table()` / `_registry_calibers()` / `registry_latest_date()` / `check_value_sync()`。

---

## 一、Schema 定义

登记册**第一节为活值表**（标题或表头含「指标」）。**v2 标准表（12 列）为唯一事实源**：新增登记册一律使用 v2；存量 v1 表按 §五 迁移规则过渡。程序按表头自动分支（`_live_table()`）。

### v2 标准表（唯一标准，12 列）

| 列 | 必填 | 语义 |
|---|---|---|
| `#` | 是 | 追踪指标编号（与报告「数据变更摘要」行号一一对应） |
| `指标` | 是 | 指标名（跨主题同名指标须能对齐） |
| **`口径`** | 是 | 指标统计口径的标准表述（C-10 直接比较此列） |
| `研究阶段` | 是 | 基线 / 周期 / 事件触发等 |
| `最新值 / 规则` | 是 | 活值或规则描述（含单位 / 时点） |
| `来源机构` | 是 | 机构名 |
| `来源 URL` | 是 | 完整可访问 URL |
| `版本日期` | 是 | 来源版本发布日期（`YYYY-MM-DD`） |
| `核验日期` | 是 | 本项目核验日期（`YYYY-MM-DD`；C-08 取此列最新值） |
| `核验状态` | 是 | 已核验 / 部分核验 / 待核实 |
| `关联章节` | 否 | 报告章节锚点 |
| `更新时间` | 是 | 登记册行更新时间（`YYYY-MM-DD`） |

### v1 旧表（存量过渡，迁移前）

| 列 | 必填 | 语义 |
|---|---|---|
| `#` | 是 | 追踪指标编号 |
| `指标` | 是 | 指标名 |
| `优先数据源` | 是 | 机构 / 载体（C-10 旧表比较基准） |
| `最新值（来源/年份）` | 是 | 活值；口径若内嵌须写成「口径：…」 |
| `基准版本` | 是 | 版本号（形如 `v2026.11.12_5`；C-08 旧表解析其中日期） |

> **口径清单**（`### 口径清单`）与**历史版本快照**（`## 历史版本快照`）为辅助 / 冻结内容，不参与 C-10 口径一致性判定。
> v1 → v2 映射规则见 §五；迁移完成后全库统一为 v2。

---

## 二、口径判定规则（C-10）

- **新表**：直接比较「口径」列（归一化后）。
- **旧表**：比较「优先数据源 + 最新值内嵌口径」——以「优先数据源」为基准，若「最新值」含显式「口径 / 定义：…」标注则并列填入；其余内嵌表述不单独抽取（沿用既有逻辑，避免误判）。
- 仅解析活值表；同名指标在 ≥ 2 个主题登记册中口径不一致 → C-10（P2）。

## 三、时效判定规则（C-08）

- 直接读取登记册字段化日期：新表取「核验日期」「版本日期」列；旧表取「基准版本」中的 `vYYYY.MM.DD`。
- 以全部活值行的**最新日期**为基准，超出 12 个月窗口 → C-08（P2）。
- 登记册无可用字段化日期时不判定（不再回退「报告期间 + 更新标记」旧逻辑）。

## 四、报告 ↔ 登记册数值一致性（C-13）

- 全量覆盖 `VALUE_SYNC_TOPICS`（2026-11-16 起为 `None`，即全部业务主题；00 决策层无登记册自动跳过）。
- 以登记册活值表「最新值」列为基准抽取数值型数字；报告「数据变更摘要」同编号行缺失该数值 → C-13（P1）。
- 仅比数值存在性，不做单位 / 口径换算；年份、1–2 位数字、`YYYY.M` 版本串与括号内文献号不参与。
- **判定内核单一事实源**：`info_quality_check.value_sync_gaps(registry_text, report_text)`；C-13 与 `audit_preflight` 的 PF-REGVAL 均调用它，不得另写规则。
- **左移预检（PF-REGVAL，P1）**：`audit_preflight.py` 在报告落盘前单份快检；未建「数据变更摘要」活值表的历史报告豁免至 `audit_preflight.REGVAL_ROLLOUT_DEADLINE`，豁免清单随预检报告公示。

## 五、迁移规则

- 新增登记册一律使用 v2 标准表；存量 v1 表按下表迁移，迁移完成后全库统一为 v2。
- **v1 → v2 列映射**：

| v1 列 | → v2 列 | 规则 |
|---|---|---|
| `#` / `指标` | `#` / `指标` | 原样迁移 |
| `优先数据源` | `口径` + `来源机构` | 机构名入「来源机构」；载体 / 统计口径入「口径」 |
| `最新值（来源/年份）` | `最新值 / 规则` | 原样（保留来源 / 年份标注） |
| `基准版本`（`vYYYY.MM.DD_n`） | `版本日期` / `核验日期` / `更新时间` | 取日期部分入「核验日期」「更新时间」；「版本日期」取来源发布日，缺失填 `—` |
| —（新增） | `研究阶段` | 填「周期」（月度核验）/「基线」 |
| —（新增） | `来源 URL` | 从同主题报告来源章节取完整 URL；缺失填 `—（见报告来源章节）` |
| —（新增） | `核验状态` | 含 `⚠` / 「待核实」/「推断」→ `待核实`；含「部分」→ `部分核验`；其余 → `已核验` |
| —（新增） | `关联章节` | 填 `数据变更摘要` |

- Schema 变更须同步更新本文件与 `info_quality_check.py` 的解析分支，并在版本记录留痕。
