# 监测报告通用规范（渲染 / 排版 / 交付）

> **用途**：本项目所有监测报告共享的 HTML 渲染、表格排版、来源链接、图表与交付规范。13 类类型模板（28 份）与本文件冲突时，以类型模板及业务提示词为准；本文件只规定**跨类型、跨业务线一致**的最低渲染标准。

---

## 1. 交付格式与命名规则

- **双格式交付**：每份报告默认 = 同名 `.md` 源 + 自包含 `.html`；纯图表型简报可只出 HTML（由业务配置声明）。
- **命名规则**：

| 报告类型 | 文件名 | 落盘位置 |
|---|---|---|
| 月度报告（通用） | `{YYYY-MM}-<主题slug>.md` + 同名 `.html` | `{业务目录}/reports/` |
| 季度报告 | `{YYYY-MM}-<主题slug>`（`YYYY-MM` = 季度末月，`2026-Q4` → `2026-12`） | 同上 |
| 年度报告 | `{YYYY-MM}-<主题slug>`（`YYYY-MM` = 12 月） | 同上 |
| 项目制 / 事件触发件 | `{YYYY-MM-DD}-<主题>.md`（日期 = 事件或执行日） | 同上 |

> 主题 slug = 主题目录名去 `NN-` 前缀（`01-ssw-driver` → `ssw-driver`）。命名由 `validate.py` 校验（`YYYY-MM-<slug>` 与目录一致、md / html 成对）；项目制 / 事件触发件不在标准正则内，仅 WARN 不阻断。报告已统一按自然月聚合，旧 `_baseline_report` / `_monthly` / `_quarterly` / `_annual` 命名不再使用。

- HTML 必须自包含：全部样式与 JS 内联，ECharts 内联加载，**不依赖外部数据文件**。

---

## 2. ECharts 图表规范（研报风）

- 风格：白底 / 浅底、深色字、无花哨渐变；配色限 navy / red / green / amber。
- 标题必须含**单位与来源**；每个图下有 `chart-note` 说明口径与限制（含统计周期、是否自算）。
- **不得把不同统计域的数值画成一条连续时间序列**；不同口径数值并列或分轴，并注明「不可相减」。
- 图表数量下限由各类型模板与业务配置规定；通用要求每张图可独立核对数据来源。
- 假设性测算图必须标注「假设性测算」并写明全部假设。

---

## 3. 表格结构与列宽

- `<thead>` / `<tbody>` 必须成对且标签完整；禁止畸形写法（如 `<th scope="col"ead>`）与重复 `</tbody>`；每行单元格数与表头列数一致。
- 每个 `<th>` 声明 `style="width:N%"`（同表头之和 100%）；表格加 `class="fixed"`。
- **表格语义（WCAG 2.1 AA）**：每个 `<th>` 必须声明 `scope`——简单表（单表头行、无分层、无行标题）用 `scope="col"`；首列为行标题时行首 `<th>` 用 `scope="row"`。复杂 / 多层表须含 `<caption>`。
- **复杂 / 多层表判定**（满足任一）：表头行数 >1、`<thead>` 含 `colspan` / `rowspan`（列结构分层）、首列为行标题。判定口径单一事实源为 `engine/tools/_common.py::is_complex_html_table`，`md2html` 渲染与 `lint_reports` 校验共用。
- **`<caption>` 文案**：`表 N：<表前最近标题（h1–h6）纯文本>`；无前置标题时取表头首行文本（各列以 ` / ` 连接）。`N` 为报告内表格序号（从 1 起）。
- **禁止列宽塌缩**：末列不得被压成竖排文字（中文逐字换行）。多列表（≥7 列）为高风险表，须逐表校验。
- 表格内**不设独立「完整 URL」列**；来源链接按第 4 节承载。

---

## 4. 来源链接呈现

两种承载方式，同一报告可混用，但同一张表只用一种：

**A. 表头弹层式**：来源清单类表格，表头加 `class="src-head" tabindex="0"`，悬停 / 聚焦展开 `.src-pop` 弹层，集中列出本期全部来源链接（每条 `target="_blank" rel="noopener"`，链接文本为机构 / 文件名）。

**B. 行内链接式**：数据表的「指标名称」或「机构名称」本身即链接：`href` 写完整 URL，链接文字保持指标名 / 机构名原样（不把 URL 当链接文本），文字后加 `↗`；多来源行在每个机构上分别加链接。

通用要求：

- 全部链接 `target="_blank"` + `rel="noopener"`。
- 行内引用 `[Source: 完整URL, 年份]` 保持完整可访问。
- URL 必须写入来源清单、台账或数据底表，报告中不得出现「断头数字」（有数无源）。
- 链接样式（行内式）：navy 色、虚线下划线、末尾 `↗`、hover 背景浅蓝。

---

## 5. 固定顶部导航与锚点

- 周期报告（月 / 季 / 年）强制：报告页含 `<nav class="report-nav" aria-label="报告导航">`（置于 `<header>` 之后、`<main>` 之前）。
  - `.nav-url`：标签「报告 URL」+ 本报告仓库原始文件完整链接（`{{REPO_RAW_URL_BASE}}` + 业务目录相对路径，基址由业务配置定义）。
  - `.nav-tabs`：锚点标签与报告章节一一对应；标签文案与章节标题一致；`href="#sN"` 与对应 `<h2 class="sec" id="sN">` 逐字对应。
  - 样式与交互：sticky 常驻、平滑滚动、`scroll-margin-top:100px`、窄屏换行。
- 基线报告保留其原有简化锚点导航（`<nav aria-label="报告导航">` + 锚点链接），不强制升级为 `.report-nav`；已产出的基线报告不得改动。

---

## 6. 自定义 hover URL 提示（使用行内链接式的报告）

- 不使用浏览器原生 `title`；使用自定义 tooltip：`position: fixed`、深色背景白色文字、最大宽度 560px、`word-break: break-all`、跟随鼠标、自动避开视口边缘、鼠标移出 / 滚动 / 缩放时隐藏、键盘聚焦链接时也显示。
- 提示内容为链接的完整 `href`；交互脚本放在独立 IIFE 中，ECharts 加载失败时仍可运行。

---

## 7. 响应式与打印

- 最大宽度约 1160px；移动端表格横向滚动；移动端图表高度 320px。
- 打印时保留表格边框与来源备注，不依赖 hover。

---

## 8. 可访问性与校验

- 内联 JS 必须通过 `node --check`；表格 / div 标签配对；锚点有效；浏览器打开预览无控制台 error。
- HTML 可访问性校验：`python engine/tools/lint_reports.py`（按可用性执行；本地环境缺脚本时以人工清单替代，见第 9 节）。

---

## 9. 人工校验清单（脚本缺失时的回归替代）

- [ ] 所有锚点跳转准确；导航标签与章节标题逐字一致
- [ ] 所有表格 `<thead>` / `<tbody>` 成对、列宽声明、无竖排塌缩
- [ ] 来源链接可点击访问；弹层链接数与来源条目一致
- [ ] 图注含单位、来源、统计周期、口径警示
- [ ] 浏览器打开无控制台 error
