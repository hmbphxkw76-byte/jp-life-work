# 监测报告通用基座（类型中立）

> **用途**：本项目所有监测报告提示词的**第一层继承基座**。定义跨报告类型、跨业务线共享的质量规则、运行变量框架、来源分级框架与执行协议。本文件为通用模板，**不含任何业务限定性内容**（地区、物业类型、机构清单均由业务层配置实例化）。
>
> **继承体系（四层）**：业务提示词 = [本文件（通用基座）](./prompt-generic-base.md) × [监测报告通用规范](./monitoring-common-spec.md) × 报告类型模板（按 [类型注册表](./template-registry.md) 分目录存放）× 业务专属配置（`{地区}/{业务类型}/prompts/business-config.md`）。冲突优先级：**业务提示词 ＞ 类型模板 ＞ 本文件 ＞ 通用规范**。

## 一、文档体系与新增业务线指引

### 1.1 目录结构约定

```
jp-life-work/
├── engine/
│   ├── report_templates/                     # 通用层（禁止出现业务关键词）
│   │   ├── prompt-generic-base.md            # 通用基座（本文件，类型中立）
│   │   ├── monitoring-common-spec.md         # 监测报告通用规范（跨类型共享最低渲染标准）
│   │   ├── template-registry.md              # 类型注册表（分类架构接入点）
│   │   ├── report-classification.md          # 行业主流分类体系（六族十二类）
│   │   ├── registry-schema.md                # 指标登记册 Schema 规范
│   │   ├── compliance-rules.json             # 合规校验规则（12 类 × 周期）
│   │   ├── fact-card-standard.md             # 事实卡片标准
│   │   ├── l5-semantic-review.md             # L5 语义复核提示词
│   │   ├── handbook-split-standard.md        # 知识手册拆分操作规范
│   │   └── <类型ID>/                          # 类型模板目录（如 market-monitoring/）
│   │       ├── prompt-baseline-setup-template.md
│   │       └── prompt-<cycle>-template.md
│   └── tools/                                 # 工具链（validate / md2html / compliance_check / audit_*）
└── NN-<slug>/                                # 业务层（主题目录，如 01-ssw-driver；旧两层 {REGION}/{PROPERTY}/ 仍兼容）
    ├── prompts/
    │   ├── business-config.md                # 业务专属配置（变量 / 来源 / 口径 / 阈值）
    │   └── prompt-<cycle>.md                 # 业务周期提示词（继承对应类型模板）
    ├── data/                                 # 指标台账
    ├── reports/                              # 报告产出
    └── handbook/                             # 知识手册（可选，见 handbook-split-standard.md）
```

- `engine/report_templates/` 内任何文件**严禁**出现具体地区名、业务类型名、专属机构名、专属指标数值。
- **链接深度口径**：业务提示词（位于 `NN-<slug>/prompts/`）对通用层的引用统一写 `../../engine/report_templates/...`；脚手架 / 泛用版内嵌提示词的链接同样按此口径（复制后位置）书写。类型模板之间互引用用 `../`。
- 通用逻辑修改只改通用层根部文件，自动对所有业务线生效；类型模板修改只对该类型业务线生效；业务线之间互不影响。类型清单与新增类型接入步骤见[类型注册表](./template-registry.md)。

### 1.2 新增业务线步骤（不改通用模板）

1. 建立 `NN-<slug>/` 主题目录（如 `01-ssw-driver`），含 `prompts/`、`data/`、`reports/`（可选 `script/`、`handbook/`）；旧两层 `{REGION}/{PROPERTY}/` 仍被工具链兼容。
2. 撰写 `business-config.md`：填入变量区、来源优先级实例化、术语口径、受众定位、信号阈值。
3. 按业务类型注册的节拍设计建立周期提示词（头部继承声明指向 `../../engine/report_templates/<类型ID>/` 下对应类型模板，类型清单见[类型注册表](./template-registry.md)），正文只写业务专属内容。
4. 首期运行基线提示词，建立台账与基线锚。

## 二、通用运行变量框架

所有周期提示词的「运行变量」区必须包含以下变量（值由业务配置或运行时填写）：

```
{{REGION}}               = 报告覆盖地区（业务配置固定值）
{{TOPIC}}                = 监测主题 / 物业类型（业务配置固定值）
{{CURRENT_DATE}}         = 本次执行日期，格式 YYYY-MM-DD
{{CADENCE}}              = 周期：月 / 季 / 年（基线报告为机制建立期）
{{BASELINE_DATE}}        = 首期基线日期（仅基线报告必填）
{{REGISTRY_PATH}}        = 指标台账路径（业务配置固定值，业务目录相对路径）
{{REGISTRY_FORMAT}}      = 登记载体格式（如 xlsx-ledger）
{{BASELINE_REPORT_PATH}} = 首期基线报告路径（周期报告必填）
{{PREVIOUS_REPORT_PATH}} = 最近一期同周期报告路径（基线报告无此项）
{{OUTPUT_PATH}}          = 本期报告落盘路径
{{OUTPUT_REGISTRY}}      = 新版台账落盘路径（仅年度复盘必填）
{{REPORT_VERSION}}       = 本期版本号
{{FRESHNESS_PRIORITY}}   = 时效优先级（业务配置固定值，默认：最新官方页 > 上期值 > 预测值）
{{SOURCE_LANGUAGE_RULE}} = 来源语言规则（业务配置固定值，如：仅英文 / 仅日文官方+英文权威）
{{REPO_RAW_URL_BASE}}   = 仓库原始文件基址（业务配置固定值，用于来源链接拼接）
{{REGISTRY_FILE}}      = 登记册文件名（业务配置固定值，用于构造台账路径）
```

**类型专属变量（由类型模板扩展，统一登记于此；命名一律用 `{{}}` 双花括号）**：

```
{{CADENCE}}       取值：月 / 季 / 年（基线报告为机制建立期）
{{EVENT_NAME}}     = 本次触发事件名称（事件触发型）
{{STUDY_TYPE}}     = 本次专题类型（项目制：概念测试 / 满意度复测 / 画像刷新 / 决策路径）
{{PROJECT_TYPE}}   = 本次项目类型（项目制：新项目论证 / 项目复盘）
{{TRIGGER_TYPE}}   = 本次触发类型（事件触发 / 定期复核 / 新政策 / 修订 / 细则 / 年度复盘）
{{YEAR}} / {{NEXT_YEAR}} / {{YYYY}} / {{YYYY-MM}} = 命名用时间变量（由 {{CURRENT_DATE}} 推导）
```

**变量纪律**：

- prompt 模板内严禁填写指标活值；运行前从 `{{REGISTRY_PATH}}` 读取、运行后回写。
- 路径变量一律使用业务目录相对路径（如 `reports/…`、`data/…`），保证业务线可整体迁移。
- 引用仓库原始文件链接时使用 `{{REPO_RAW_URL_BASE}}` 基址变量（值在业务配置中定义），不在通用模板硬编码仓库地址。

## 三、通用硬性约束（所有报告自动继承）

以下约束为最低标准，业务配置可加严、不得放宽：

1. **逐点引用**：每个关键数字、每条结论必须可回溯到「来源机构 · 统计周期 · 发布日期 · 核验状态」，正文以来源注承载。
2. **事实与推断分离**：事实（有来源）与推断（机制分析）明确区分；自算值标「自算」，预测值标「预测值（F）」，计划值标「计划值」。证据类型按[置信度分级标准](./confidence-grade-standard.md) §2.1 标注（官方统计 / 政策原文 / 自算 / 推断 / 预测 / 转述）；单一来源的结论须显式标「单源」。
3. **口径标注**：同一指标多口径并列呈现，不得静默择一或取均值；术语口径不得混用（具体口径清单由业务配置定义）。
4. **数据纪律**：不编造任何缺失数据、日期、URL、机构名；数据未发布时使用最近已发布值并注明，不补值、不外推；「没有数据」写成可核验的陈述。
5. **结论边界**：不给出具体买卖价位、杠杆比例、仓位建议；只给「条件 → 周期判读 → 框架性含义 → 风险提示」。
6. **受众定位**：由业务配置定义；通用层默认要求报告明确声明其受众与视角。
7. **模块边界声明集中**：报告 / 骨架中的「含 / 不含 / 口径」边界声明统一集中在单独章节（如「零、模块边界声明」），不在各节重复；由 `skeleton_builder.py` 生成时自动集中。
8. **必需要素齐全**：每份报告须含「数据可靠性与局限说明」「置信度标注」「信息差与未核验清单」「决策建议」四类二级章节；关键结论 / 数字按[置信度分级标准](./confidence-grade-standard.md)（来源 S/A/B/C × 时效 新/中/旧 × 核验 已核验/部分核验/待核实 → 两位分级码）标注，结构口径见 `engine/tools/structure_check.py`。

## 四、来源分级通用框架

通用分级为四层，具体机构清单由业务配置「来源优先级」实例化：

| 层级 | 范围 | 采信规则 |
|---|---|---|
| ① 官方一手 | 央行 / 统计局 / 主管部门 / 国际组织 | 唯一可直接采信层，标「已核验」 |
| ② 行业机构 | 权威研究机构官方研究页 / PDF | 可采信；PDF 须记录发布日期与页码；预测分歧并列 |
| ③ 挂牌门户 | 门户 / 中介挂牌数据 | 仅作卖方预期或市场情绪，不得替代成交 / 登记数据 |
| ④ 媒体转述 | 通讯社、媒体转载 | 只用于发现线索；数值标「需核实原文」，须回官方页校验 |

- 冲突时按业务配置的优先级链裁决；无法裁决时并列呈现并标注。
- `{{SOURCE_LANGUAGE_RULE}}` 强制执行；不符合语言规则的来源一律排除。**全库统一规则**（单一事实源 `engine/config/source-policy.json`）：仅英文 / 日文来源——① 官方权威（日本政府省厅・e-Gov・统计、国际机构、其他国家政府官方）；② 主流投资平台 / 顾问机构；③ 主流新闻媒体（英文 / 日文）；杜绝中文来源（含中文媒体及其中英文版、中国机构中英文版），不得引用、不得作线索、不得设例外。由 `engine/tools/source_language_gate.py` 硬门禁（规则逐字一致 + 许可表述扫描 + 变更报告中文域名黑名单）。

**来源批评四问（逐条来源自问，n21）**：对每条来源标注——

1. **发布者与立场**：谁发布、有无利益关联（商业 / 官方 / 中立）；
2. **一手性**：一手 / 转引 / 转载；
3. **独立性**：独立 / 非独立 / 不明；
4. **可否三角验证**：关键结论是否有 ≥2 独立来源互证；单源结论须显式标注「单源」。

来源类型 / 独立性 / 转述层级字段见[登记册 Schema](./registry-schema.md) v2 扩展列；
L5 语义复核新增「独」项（见 [l5-semantic-review.md](./l5-semantic-review.md)）。

## 五、基线锚定协议（防已修正事实回退）

- 周期报告每次运行必须**读取 `{{PREVIOUS_REPORT_PATH}}`**（首期除外）与 `{{BASELINE_REPORT_PATH}}`，继承其结构、口径裁决与全部已核实结论。
- 每条已核实结论随「已修正事实清单」持续追加，格式：

```
【已修正事实清单 — 首期为空，产生修正后逐条补记，格式如下】
- ❌ 不得再称"…"——正确结论为…。[Source: URL, 年份]
```

- 后续报告如需修正，只能在自身周期内追加，不得回退基线或更早周期的修正记录。
- 基线报告的结构与结论一经产出即为锚，变更须走类型模板的维护规范并联动评估全部周期提示词。

## 六、更新协议框架

- **刷新窗口与差异对比**规则按报告类型模板执行。
- **重大事件触发器**：每条业务线在业务配置中维护触发器清单（格式：`事件 → 受影响模块`）。命中任一触发器即触发对应模块重点更新；**无触发则降级为核验 / 收敛型轻运行，不得为制造变化而虚构变化**。
- 与上期同日或仅隔 1 日时，明确写「本期为 T+1 刷新，官方发布窗口未开，价值在于核验、口径澄清与阈值距离」。
- 时效取舍遵循 `{{FRESHNESS_PRIORITY}}`；同一指标多版本并存时以官方最新发布为准，旧值仅作对比锚。

## 七、指标台账协议（登记载体）

- 活值统一维护于 `{{REGISTRY_PATH}}`：运行前读登记载体 → 核验 → 运行后回写登记载体 → 回写报告变更摘要；prompt 模板内不重复维护数值。
- 每期运行须逐项核对追踪表并填写「是否更新」；未变动项保留登记载体值并注明「截至 {{CURRENT_DATE}} 无更新」。
- 台账修改采用增量方式：复制旧版 → 修订 → 另存新版本，不覆盖历史值；报告层补充与台账更新严格区分。

## 八、通用 Agent 执行约定

- 所有步骤遵循「检查 → 执行 → 验证」；重复执行不产生副作用。
- 覆盖输出前先备份；不删除历史报告。
- 不修改只读附件；如需引用，先复制到可编辑目录。
- 不创建与任务无关的文件；中间脚本放在临时目录或 `.ref` 子目录。
- 所有计算必须有公式或口径说明；自算值标「自算」。
- 所有计划值、预测值不得与实绩混算；所有媒体转述必须标「需核实原文」。
- 所有口径冲突必须并列，不得静默择一。
- 报告完成后必须执行该报告类型模板的质量自检清单。
- **生成前信息核验（闸0）**：生成正文前先跑 `python engine/tools/generation_gate.py --topic <主题目录名>`，确认「可生成」；阻断时先修信息资产（登记册 / 来源 / 提示词），不得带病生成。提交前另由 pre-commit 内容硬门禁（`engine/scripts/precommit_content_gate.py`）拦截未核验内容。
- **交付与审计协议（唯一口径，提示词 / AGENTS / CI 三体系一致）**：报告交付物 = `reports/YYYY-MM-<slug>.md` 源稿 + 同名自包含 `.html`。落盘后、提交前必须按序完成（缺一不得提交）：
  1. **HTML 生成**：`python engine/tools/md2html.py`（仓库根目录执行；任务工作树内运行，共享检出目录禁止），随后 `python engine/tools/lint_reports.py --new-only` 校验交付物；
  2. **生成后自动验证（无人值守入口）**：`python engine/tools/auto_verify.py --report <报告相对路径>`——依次执行 V1–V5 规则集，通过则幂等写回报告「## 自动验证结果」章节、重新生成 HTML 并自动 `audit_pipeline --submit`；失败退出码 1 并打印逐条定位，不写回、不提交（可用 `--dry-run` 只验证 / `--no-submit`）；
  3. **落盘前自检**：`python engine/tools/audit_preflight.py --report <报告相对路径>`（P0/P1 必须修正）；
  4. **多层级校验**：`python engine/tools/audit_check.py --report <报告相对路径>`（L1–L5，P0/P1 必须修正）；
  5. **提交审计**：`python engine/tools/audit_pipeline.py --submit --report <报告相对路径>`（第 2 步已通过时自动完成，可复核）。
  合并门禁：`python engine/tools/audit_pipeline.py --gate`（PR / main 推送；受检报告须 `audited` + 指纹匹配 + 有效 L5 证据）。CI 侧 `html-sync` 负责推送后确定性重生成，`audit-gate` 负责门禁与全量校验。流程与状态见《审计报告标准化管理体系》。

## 九、通用质量自检（各类型模板在此之上追加）

- [ ] 每个关键数字标注来源机构 · 统计周期 · 发布日期 · 核验状态
- [ ] 区分实际值 / 预测值（F）/ 计划值
- [ ] `{{REGISTRY_PATH}}` 已读已写；prompt 模板自身无硬编码活值
- [ ] 已修正事实清单已从上期 / 基线继承并续写
- [ ] 渲染与排版符合[监测报告通用规范](./monitoring-common-spec.md)
- [ ] 已产出「数据变更摘要」与「待复核清单」
- [ ] 必需要素齐全：数据可靠性与局限说明 / 置信度标注 / 信息差与未核验清单 / 决策建议
- [ ] 关键结论 / 数字已按置信度分级标准标注两位分级码（结构校验 `structure_check.py` 0 缺失）
- [ ] 已运行 `md2html.py` 生成同名 HTML 并通过 `lint_reports.py --new-only`
- [ ] 已运行 `generation_gate.py --topic <主题>` 且可生成（闸0 通过）
- [ ] 已运行 `auto_verify.py --report`（V1–V5 通过，报告含「## 自动验证结果」）
- [ ] 已运行 `audit_preflight.py --report` 且无 P0/P1
- [ ] 已运行 `audit_check.py --report` 并修正全部 P0/P1
- [ ] 已 `audit_pipeline.py --submit` 提交初审（未通过初审不得合并）
- [ ] 合并门禁 `audit_pipeline.py --gate` 通过（变更报告均已审计且证据有效）
