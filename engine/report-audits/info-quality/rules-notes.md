# 信息质量判定口径说明（决策记录）

> 用途：记录 `info_quality_check.py` 各判定规则与项目架构约定的对齐决策，供审计与后续复核。
> 最近更新：2026-11-14（首轮全量评估后清零）

## 1. C-03 跨文档重复：仅针对研究正文

**决策**：跨文档重复检测仅作用于 `reports/*.md`（研究正文）；`prompts/`、`operations-guide.md`、`handbook/` 中的共享模板句不计为缺陷。

**理由**：本项目采用「自包含业务包」架构——每个主题拥有自己的业务配置、提示词、操作指南与手册，跨主题复用统一的模板句（任务目标、交付格式、继承声明、来源规则、检查清单等）是设计要求，删除会破坏自包含性。研究正文则必须主题独立，交叉重复才是缺陷。

**实施**：`check_cross_topic()` 中，同文档内重复检测覆盖全部 md；跨文档索引仅构建自 `u["reports"]`。

## 2. C-07 来源标注：认可五类形式

**决策**：以下任一形式即计为「已标注来源」：① URL；② 「来源」字样；③ `[机构名]` 行内标签；④ 登记册指针（含「登记册」）；⑤ 手册指针（含「手册」）。

**理由**：报告正文的引用惯例是「行内机构标签 / 登记册指针 + 文末来源清单」，仅认 URL 会系统性低估覆盖率（首轮曾把 20 份报告全部误判）。

**实施**：`_has_source()`。

## 3. C-10 登记册口径一致性：仅解析活值表

**决策**：仅解析各登记册「## 核心指标」活值表；「## 历史版本快照」等冻结存档不参与判定。

**理由**：历史快照保留初始基线口径，与现行口径存在差异属预期，不应判为冲突。首轮曾因此误报 16 号主题。

**实施**：`re.search(r"##\s*核心指标(.*?)(?=\n##\s|\Z)", text, re.S)`。
