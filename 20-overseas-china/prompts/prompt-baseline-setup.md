> **用途**：执行「中国 中国侧行前与回国衔接 政策解读机制」的**机制建立**任务：产出首期监管框架基线报告与配套政策台账。
> **现状**：本业务线基线将于 2026-11 产出（[reports/{{YYYY-MM}}-<slug>.md](../reports/{{YYYY-MM}}-<slug>.md) + 同名 HTML，v1.0）。**正常运行永不重跑基线提示词**；仅在①报告与登记册全部丢失（灾难恢复），或②经维护规范批准的九节结构重排时启动。
> **产出**：md 源稿 + 同目录自包含 HTML，落盘 `{{OUTPUT_PATH}}`；政策台账回写 `{{REGISTRY_PATH}}`。

> **继承声明（四层体系）**：本文件 = [通用基座](../../engine/report_templates/prompt-generic-base.md) × [监测报告通用规范](../../engine/report_templates/monitoring-common-spec.md) × [基线报告类型模板（政策法规解读型）](../../engine/report_templates/policy-analysis/prompt-baseline-setup-template.md) × [业务专属配置](./business-config.md)。冲突时以本文件为准。

## 一、项目专属硬性约束

1. **官方原文铁律**：媒体转述仅作线索；引用逐条附官方原文 URL 与版本日期。中文来源仅作线索定位，引用须回溯官方原文。
2. **只盯官方文本**：不采集舆论反应；原文有歧义处并列多解，不静默择一。
3. **结论边界**：不构成法律意见或税务意见；合规应对建议标「建议」；重大合规决策提示咨询执业法律 / 税务专业人士。
4. **术语口径**：护照 ≠ 在留资格；户籍注销 ≠ 户籍恢复；居住证 ≠ 户口；中国社保 ≠ 日本年金；公证 ≠ 认证；附加证明书 ≠ 领事认证；驾照转回 ≠ 驾照互认。
5. **边界纪律**：日本侧离日执行归 16-exit-transition-return（只读引用）；在留资格 / 永住 / 归化 / 再入国制度正文归 08-visa-immigration；对外劳务合作与中介合规归 17-migration-compliance；赴日落地与住房 / 保险归 14-life-operations；日本驾照 / 学历归 10 / 01；法规条文深度解读归 09。

## 二、来源优先级

见[业务配置第五节](./business-config.md)：① 外交部 / 驻外使领馆、国家移民管理局、公安部、商务部、教育部留学服务中心、人社部、国家卫健委、司法部 ＞ ② 国务院 / 中国政府网、地方人民政府与政务服务平台 ＞ ③ 日本外务省 / 出入国在留管理庁（只读引用）＞ ④ 银行 / 运营商 / 公证处 / 翻译机构官网（仅执行流程）＞ ⑤ 媒体（仅线索）。每条数据附官方原文 URL 与版本日期。

## 三、基线锚定与重启条件

- 基线报告一经产出即为对比锚：监管框架地图、解读规则与已核实结论由后续事件触发解读完整继承。
- **正常运行不重跑**。重启仅限两种情形：①灾难恢复（报告与登记册全部丢失）；②九节结构经维护规范批准重排。重排须在[业务配置](./business-config.md)第十二节版本记录留痕，并同步评估解读提示词。

## 四、报告结构

九节固定骨架见[基线类型模板第三节](../../engine/report_templates/policy-analysis/prompt-baseline-setup-template.md)：

| 节 | 模块 |
|---|---|
| 1 | 执行摘要 |
| 2 | 政策台账与监测机制 |
| 3 | 监管框架总览 |
| 4 | 重点政策逐条解读 |
| 5 | 影响对象矩阵 |
| 6 | 合规应对建议（建议章） |
| 7 | 生效时间线 |
| 8 | 数据治理与局限 |
| 9 | 参考来源清单 |

- 九节标题为固化锚，逐字继承，不得增删节或调整顺序。
- 内容必须覆盖行前（中国侧）与归国（回国后衔接）两段，并含横切（领事保护）；不得把主题写成单纯归国清单，也不得复制 16 的日本侧离日执行。

## 五、追踪表与边界档案

按[业务配置第八节](./business-config.md)的 12+1 项追踪指标逐项核对并填写「是否更新」；运行后回写 `{{REGISTRY_PATH}}` 的核心指标与[研究边界档案](./business-config.md)（领域边界、两段分层、主体清单与入选标准、口径清单）。未核实项注明「⚠ 待核实」，不补值、不外推；prompt 模板内不填活值。

## 六、执行方式（建议）

1. 原文回溯先行：逐渠道核对官方原文，完成台账登记后才进入解读环节。
2. 并行启动 2–4 个研究子代理：① 护照 / 户籍 / 居住证；② 档案 / 社保 / 健康证；③ 无犯罪记录 / 公证认证 / 翻译件；④ 驾照转回 / 学历认证 / 领事保护。全部限定官方来源、逐点引用，每条数据附可直接访问的 URL。
3. 主代理合并差异，冲突口径保留双份引用，无法核实项单列「待复核清单」。
4. 与 16-exit-transition-return 日本侧结论交叉验证时只读引用，本主题不得独立回写 16。

## 七、渲染与交付

- 交付格式：md + 同目录自包含 HTML（`python engine/tools/md2html.py`）；HTML 须通过 `python engine/tools/lint_reports.py`。
- 基线导航采用简化锚点目录，不强制 `.report-nav`。
- 落盘后将[业务配置第一节](./business-config.md)的 `{{BASELINE_REPORT_PATH}}` 指向本报告（重建场景）。

## 落盘后审计（提交前必做）
