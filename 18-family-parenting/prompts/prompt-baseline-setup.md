# 日本 家族·育儿·人生事件 首期基线报告提示词（职业就业调研型）

> **用途**：执行「日本 家族·育儿·人生事件 调研机制」的**机制建立**任务：产出首期基线（深度调研）报告与配套指标登记册，作为后续所有周期更新的对比锚与制度基础。
> **现状**：本业务线基线将于 2026-11 产出（[reports/{{YYYY-MM}}-<slug>.md](../reports/{{YYYY-MM}}-<slug>.md)，v1.0）。**正常运行永不重跑基线提示词**；仅在①报告与登记册全部丢失（灾难恢复），或②经维护规范批准的九节结构重排时启动。
> **产出**：md 源稿，落盘 `{{OUTPUT_PATH}}`；指标活值与研究边界档案回写 `{{REGISTRY_PATH}}`。
>
> **继承声明（四层体系）**：本文件 = [通用基座](../../engine/report_templates/prompt-generic-base.md) × [监测报告通用规范](../../engine/report_templates/monitoring-common-spec.md) × [基线报告类型模板（职业就业调研型）](../../engine/report_templates/employment-research/prompt-baseline-setup-template.md) × [业务专属配置](./business-config.md)。冲突时以本文件为准。

**任务目标**：产出九节基线报告（核心结论、家族·育儿政策与制度趋势、家庭经济·扶养与支援、家庭形态与服务主体细分、家庭事件办理的能力要求、育儿相关资格与凭证、家庭落地路径建议、数据可靠性与局限、参考来源清单）与登记册首建；**官方原文铁律**：全部引用回溯官方原文并附 URL 与版本日期；运行后回写 `{{REGISTRY_PATH}}`；基线报告**无上期报告**，不读取 `{{PREVIOUS_REPORT_PATH}}`。

## 一、项目专属硬性约束

1. **官方原文铁律**：媒体转述仅作线索；引用逐条附官方原文 URL 与版本日期。中文来源仅作线索定位，引用须回溯日 / 英原文。
2. **只盯官方文本**：不采集舆论反应；原文有歧义处并列多解，不静默择一。
3. **结论边界**：不构成法律意见或税务意见；应对建议标「建议」；重大决策提示咨询执业弁護士 / 行政書士 / 税理士。
4. **术语口径**：家族滞在 ≠ 特定技能 1 号带同；扶养要件 ≠ 收入证明口径；包括许可 ≠ 个别许可；保育所 ≠ 認定こども園 ≠ 幼稚園；出産育児一時金 ≠ 児童手当 ≠ 児童扶養手当；定住者 ≠ 永住者。
5. **边界纪律**：永住・归化・在留资格制度正文归 08；学制与就学手续正文归 10；分娩就医与保险正文归 15；税制 / 年金 / 扶养控除正文归 07；住民与行政 90 天清单归 14；法规条文深度解读归 09。

## 二、来源优先级

见[业务配置第五节](./business-config.md)：① 出入国在留管理庁 / 法務省 / e-Gov ＞ ② 厚生労働省 / 内閣府 / 文部科学省 / 日本年金機構 ＞ ③ 総務省 / 地方自治体 ＞ ④ 家庭裁判所 / 多语言窗口 / 地域国際化協会（仅执行流程）＞ ⑤ 媒体（仅线索）。每条数据附官方原文 URL 与版本日期。

## 三、基线锚定与重启条件

- 基线报告一经产出即为对比锚：九节结构、口径裁决与已核实结论由后续更新完整继承。
- **正常运行不重跑**。重启仅限两种情形：①灾难恢复（报告与登记册全部丢失）；②九节结构经维护规范批准重排。重排须在[业务配置](./business-config.md)版本记录留痕，并同步评估周期提示词。

## 四、报告结构

九节固定骨架见[基线类型模板第三节](../../engine/report_templates/employment-research/prompt-baseline-setup-template.md)，本主题固化标题见[业务配置第 3.2 节](./business-config.md)：

| 节 | 模块 |
|---|---|
| 1 | 核心结论（摘要） |
| 2 | 家族·育儿政策与制度趋势 |
| 3 | 家庭经济·扶养与支援（核心模块） |
| 4 | 家庭形态与服务主体细分 |
| 5 | 家庭事件办理的能力要求 |
| 6 | 育儿相关资格与凭证 |
| 7 | 家庭落地路径建议（结论章） |
| 8 | 数据可靠性与局限说明 |
| 9 | 参考来源清单 |

- 九节标题为固化锚，逐字继承，不得增删节或调整顺序。
- 内容必须覆盖带同 / 养育 / 家庭事件 / 长期四段，不得写成单纯「育儿清单」。

## 五、追踪表与边界档案

按[业务配置第八节](./business-config.md)的 12+1 项追踪指标逐项核对并填写「是否更新」；运行后回写 `{{REGISTRY_PATH}}` 的核心指标与[研究边界档案](./business-config.md)（领域边界、四段分层、主体清单与入选标准、口径清单）。未核实项注明「待核实」，不补值、不外推；prompt 模板内不填活值。

## 六、执行方式（建议）

1. 原文回溯先行：逐渠道核对官方原文，完成台账登记后才进入解读环节。
2. 并行启动 2–4 个研究子代理：① 家族滞在与配偶就劳；② 生育给付与保育；③ 子女教育与在留衔接；④ 婚姻家庭与继承。全部限定日 / 英来源、逐点引用，每条数据附可直接访问的 URL。
3. 主代理合并差异，冲突口径保留双份引用，无法核实项单列「待复核清单」。
4. 与现行制度冲突的解读须并列新旧对照；无法核实项单列「待复核清单」。

## 七、渲染与交付

- 交付格式：md 源稿；后续周期运行可用 `python engine/tools/md2html.py` 生成同目录自包含 HTML，并过 `python engine/tools/lint_reports.py`。
- 基线导航采用简化锚点目录，不强制 `.report-nav`。
- 落盘后将[业务配置第一节](./business-config.md)的 `{{BASELINE_REPORT_PATH}}` 指向本报告（重建场景）。

## 落盘后审计（提交前必做）

落盘后依次运行 `python engine/tools/audit_preflight.py --report <报告相对路径>`、`python engine/tools/audit_check.py --report <报告相对路径>`，修正全部 P0/P1 后执行 `python engine/tools/audit_pipeline.py --submit --report <报告相对路径>` 提交审计（未通过初审不得合并）。
