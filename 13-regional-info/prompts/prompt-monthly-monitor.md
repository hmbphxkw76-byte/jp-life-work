# 日本 · 地域信息 · 月度监测提示词（市场指标监测型）

> **用途**：周期性（每月）刷新月度监测简报。以一手 / 权威来源为依据、以指标登记册为编号骨架、以上一期报告与首期基线为对比锚，完成「核验 → 判定 → 偏离 → 缺口 → 观察」闭环。
> **产出**：月度报告落盘 `{{OUTPUT_PATH}}`（`reports/{{YYYY-MM}}-<slug>.md` + 同名 HTML）。
>
> **继承声明（四层体系）**：本文件 = [通用基座](../../engine/report_templates/prompt-generic-base.md) × [监测报告通用规范](../../engine/report_templates/monitoring-common-spec.md) × [月度报告类型模板（市场指标监测型）](../../engine/report_templates/market-monitoring/prompt-monthly-monitor-template.md) × [业务专属配置](./business-config.md)。冲突时以本文件为准。

---

## 运行变量（每次运行前填写）

```
{{CURRENT_DATE}}         = 本次执行日期，格式 YYYY-MM-DD
{{PREVIOUS_REPORT_PATH}} = 上一期月度报告路径（首期月度为空，仅锚定基线）
{{BASELINE_REPORT_PATH}} = reports/{{YYYY-MM}}-<slug>.md
{{REGISTRY_PATH}}        = data/regional_indicator_registry.md
{{OUTPUT_PATH}}          = reports/{{YYYY-MM}}-<slug>.md
{{REPORT_VERSION}}       = 本次版本号，格式 vYYYY.MM.DD
```

固定值（不填，读自业务配置第一节）：`{{REGION}}`、`{{TOPIC}}`、`{{FRESHNESS_PRIORITY}}`、`{{SOURCE_LANGUAGE_RULE}}`、`{{REPO_RAW_URL_BASE}}`。

**任务目标**：完成月度核验闭环；按[业务配置第七节](./business-config.md)「月度」触发器判定；无触发且窗口未到时不启动，不得虚构变化。

## 一、节拍与触发

月度运行以核验与判定为主（见[月度类型模板第一节](../../engine/report_templates/market-monitoring/prompt-monthly-monitor-template.md)）：

- **T+0 / T+1 判定**：统计类来源按官方发布节奏核对最新一期标题与发布日期，判断当期版本归属。与上期同日或仅隔 1 日时，明确写「本期为 T+1 刷新，官方发布窗口未开，价值在于核验、口径澄清与阈值距离」，不得为制造变化而虚构变化。
- **触发器**（[业务配置第七节](./business-config.md)「月度」）：目标地域岗位密度 / 条件显著变化；防灾气象预警体系与配信渠道变化。**无触发 → 降级为核验 / 收敛型轻运行。**

## 二、项目专属硬性约束

1. **受众与结论边界**：面向拟在日本选择就业地 / 定居地的读者；输出地域选择框架、地域差对比与决策输入，不给落户价位、不给单一「最优地域」结论；个人地域选择为自记录个案，标注记录日期。
2. **来源语言规则**：统计类须日文官方原文；门户数据仅预期指标。
3. **口径纪律**：登记口径 ≠ 挂牌口径；勤務地 ≠ 注册地 ≠ 通勤圈；都道府県 ≠ 市町村；预期指标（门户挂牌）≠ 实际成交 / 登记值。
4. **边界纪律**：薪资地域差链接 07、求职渠道地域策略链接 02、保险与就医流程链接 12、就学手续与学制链接 10、灾害时外国人支援政策环境链接 09。
5. **类型机制适配**：无 K/RL 阈值信号与供给情景；信号判定以[业务配置第八节](./business-config.md)追踪表 + 监测日历承载。

## 三、各模块更新要点

按[业务配置第 3.2 节](./business-config.md)的结构映射逐模块实例化：

- **地域选择框架（对应多维指标体系与来源 / 信号规则与决策框架）**：7 维评分框架（岗位供给 / 薪资×成本 / 外国人支援 / 同胞密度 / 交通 / 灾害风险 / 生活品质）、候选地域速览、决策流程；动态获取目标地域岗位密度（HelloWork 地域件数）、薪资地域差（锚 01 登记册）、生活成本地域差；保持评分维度与权重。
- **地域间公共服务差异视角（对应多维指标体系与来源）**：医疗资源地域差（医师数 / 病床数）、教育资源地域差（外国人儿童就学把握体制 / 日语指导体制）；动态获取厚労省 / 文科省统计年度发布；保持差异视角表（推断标注）。
- **地域生活笔记（对应首期基线数据 / 风险局限与监测盲区）**：定居地档案、生活发现、防灾与安全、地域防灾情报渠道、季度观察；动态获取自治体多语言支援、防灾情报渠道可用性；更新个人笔记（个案标注）；保持笔记结构与防灾情报渠道表。

## 四、基线锚定与防回退

- 读取 `{{PREVIOUS_REPORT_PATH}}`（首期月度为空）与 `{{BASELINE_REPORT_PATH}}`，继承结构与全部已核实结论。
- 逐条继承「已修正事实清单」，产生修正后追加（格式见[通用基座第五节](../../engine/report_templates/prompt-generic-base.md)）；严禁重新引入已被推翻的说法；无来源不得入清单。
- 求人定位类修正以 01-ssw-driver 最新报告文首清单为单一事实源；本主题只读同步。

## 五、追踪表与登记册联动

按[业务配置第八节](./business-config.md)的 4 项追踪指标逐项核对并填写「是否更新」；运行前从 `{{REGISTRY_PATH}}` 读取活值与研究边界档案 → 复核有效性 → 运行后回写。数据变更摘要至少覆盖全部 4 项；未核实项单列「待复核清单」。prompt 模板内不填活值。

## 六、执行方式（建议）

1. 按调研维度并行启动研究子代理（目标地域岗位密度与薪资地域差 / 生活成本与自治体外国人支援），全部限定日 / 英来源、逐点引用，每条数据附可直接访问的 URL；门户数据标注为预期指标。
2. 主代理读取 `{{PREVIOUS_REPORT_PATH}}` 与基线做差异合并，继承已修正事实清单，应用第三节更新要点。
3. 冲突数据保留双份引用；无法核实项单列「待复核清单」。
4. 回写报告与登记册后运行 `python engine/tools/md2html.py` 重新生成 HTML，并运行 `python engine/tools/lint_reports.py` 校验。

## 七、渲染与交付

- 交付格式：md + 同目录自包含 HTML；月度报告含顶部导航（`.report-nav`），`.nav-url` = `{{REPO_RAW_URL_BASE}}` + `/reports/{本期文件名}`。
- HTML 须通过 `lint_reports.py` 标签配对校验。
- 基线报告常驻 `reports/` 顶层不归档；月度报告按保留策略执行（保留 12 期，超出移入 `reports/archives/`）。

## 八、质量自检（通用清单之外的本主题专属项）

- [ ] 地域数据均注明都道府県 / 市町村口径；登记口径与挂牌口径已区分
- [ ] 勤務地、注册地、通勤圈已区分；"地方" vs "东京圈"薪资对比均同岗位分层
- [ ] 追踪表 4 项均已核对并填写「是否更新」
- [ ] `{{REGISTRY_PATH}}` 已读已写，变更摘要与登记册一致
- [ ] 数据缺口状态标签规范（未发布 / 缺席 / 未取得 / 未重算 / 无官方值 / 未核验）
- [ ] 数据变更摘要与待复核清单已产出
- [ ] HTML 通过 lint（标签配对）

## 落盘后审计（提交前必做）
