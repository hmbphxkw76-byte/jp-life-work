# 日本 · 地域信息 · 首期基线报告提示词（市场指标监测型）

> **用途**：执行「日本 地域信息 监测机制」的**机制建立**任务：产出首期基线报告与配套指标登记册，作为后续月 / 季 / 年报告的对比锚与制度基础。
> **现状**：本业务线基线已于 2026-11 产出（[reports/{{YYYY-MM}}-<slug>.md](../reports/{{YYYY-MM}}-<slug>.md) + 同名 HTML，v1.0，数据基准 2026-11-12）。**正常运行永不重跑基线提示词**；仅在①报告与登记册全部丢失（灾难恢复），或②经维护规范批准的十节结构重排时启动。
> **产出**：md 源稿 + 同目录自包含 HTML，落盘 `{{OUTPUT_PATH}}`；指标活值与研究边界档案回写 `{{REGISTRY_PATH}}`。
>
> **继承声明（四层体系）**：本文件 = [通用基座](../../src/report_templates/prompt-generic-base.md) × [监测报告通用规范](../../src/report_templates/monitoring-common-spec.md) × [基线报告类型模板（市场指标监测型）](../../src/report_templates/market-monitoring/prompt-baseline-setup-template.md) × [业务专属配置](./business-config.md)。冲突时以本文件为准。

```

{{BASELINE_DATE}}        = 2026-11-12（首期已产出；重建时改为重建日期）
{{OUTPUT_PATH}}          = reports/{{YYYY-MM}}-<slug>.md
{{REGISTRY_PATH}}        = data/regional_indicator_registry.md
{{REPORT_VERSION}}       = v1.0（首期固定；灾难恢复重建时递增）
```

**任务目标**：产出市场指标监测型基线报告（执行摘要、持续监测机制设计、多维指标体系与来源、首期基线数据、先行指标判读、信号规则与决策框架、月·季·年监测日历、数据治理、风险局限与监测盲区、交付物与后续运行方式）与研究边界档案首建；多口径并列不合并；运行后回写 `{{REGISTRY_PATH}}`；基线报告**无上期报告**，不读取 `{{PREVIOUS_REPORT_PATH}}`。

## 一、项目专属硬性约束

1. **受众与结论边界**：面向拟在日本选择就业地 / 定居地的读者；输出地域选择框架、地域差对比与决策输入，**不给落户价位、不给单一「最优地域」结论**；个人地域选择为自记录个案，标注记录日期（见[业务配置第二节](./business-config.md)）。
2. **来源语言规则**：统计类须日文官方原文；门户数据仅预期指标。
3. **术语口径**：登记口径（地価公示）≠ 挂牌口径（賃貸门户）；勤務地 ≠ 注册地 ≠ 通勤圈；都道府県 ≠ 市町村；"地方" ≠ "东京圈"薪资对比须同岗位分层。
4. **边界纪律**：薪资地域差链接 07、求职渠道地域策略链接 02、保险与就医流程链接 12、就学手续与学制链接 10、灾害时外国人支援政策环境链接 09；本主题只写地域选择框架 + 地域差对比 + 生活笔记。
5. **类型机制适配**：本业务线为个人地域决策支持，非市场定价监测；市场指标监测型的 K/RL 阈值信号、供给情景重算、五态合成等机制不适用（无价格 / 成交 / 供给类指标），改以[业务配置第八节](./business-config.md)追踪表 + 第七节触发器 + 监测日历承载监测职能。

## 二、来源优先级

见[业务配置第五节](./business-config.md)：① 国交省 / 総務省統計局 / 気象庁 / 防災庁 / 厚労省 / 文科省 / 各都道府県・市町村 ＞ ② HelloWork 地域检索 / JETRO ＞ ③ 賃貸・生活门户（预期指标）＞ ④ 地域媒体。每条数据附完整 URL，每格活值附 `[来源, 年份]`。

## 三、基线锚定与重启条件

- 基线报告一经产出即为对比锚：结构、口径裁决与已核实结论由后续月 / 季 / 年报告完整继承。
- **正常运行不重跑**。重启仅限两种情形：①灾难恢复（报告与登记册全部丢失）；②十节结构经维护规范批准重排。重排须在[业务配置](./business-config.md)第十二节版本记录留痕，并同步评估各周期提示词。
- 现状：首期基线保留现行结构（业务固化锚），结构映射见[业务配置第 3.2 节](./business-config.md)。

## 四、报告结构

十节固定骨架见[基线类型模板第三节](../../src/report_templates/market-monitoring/prompt-baseline-setup-template.md)：

| 节 | 模块 |
|---|---|
| 1 | 执行摘要：结论先行 |
| 2 | 持续监测机制设计 |
| 3 | 多维指标体系与来源 |
| 4 | 首期基线数据 |
| 5 | 先行指标判读 |
| 6 | 信号规则与决策框架 |
| 7 | 月 / 季 / 年监测日历 |
| 8 | 数据治理：来源分级、口径优先与核验状态 |
| 9 | 风险、局限与监测盲区 |
| 10 | 交付物与后续运行方式 |

- 已产出的 2026-11 基线：按[业务配置 3.2 节](./business-config.md)的映射表对应到现行结构，**不改写正文**。
- 若经批准重建：十节标题为固化锚，逐字继承，不得增删节或调整顺序。
- **本业务线适配**：第 5 / 6 节以「监测项判读 + 决策框架」实例化（无阈值信号），第 7 节监测日历按统计发布节奏 + 个人决策时点编排。

## 五、追踪表与边界档案

按[业务配置第八节](./business-config.md)的 4 项追踪指标逐项核对并填写「是否更新」；运行后回写 `{{REGISTRY_PATH}}` 的核心指标与[研究边界档案](./business-config.md)（领域边界、统计域分层、主体清单与入选标准、口径清单）。未核实项注明「待核实」，不补值、不外推；prompt 模板内不填活值。

## 六、执行方式（建议）

1. 并行启动 2 个研究子代理：① 目标地域岗位密度与薪资地域差；② 生活成本与自治体外国人支援。全部限定日 / 英来源、逐点引用，每条数据附可直接访问的 URL；门户数据标注为预期指标。
2. 主代理合并差异，冲突口径保留双份引用，无法核实项单列「待复核清单」。
3. 与 01-ssw-driver（求人四元组）、07-economy-finance（薪资地域差）交叉核对（只读锚，不回写）。

## 七、渲染与交付

- 交付格式：md + 同目录自包含 HTML（`python src/prompts-tools/tools/md2html.py`）；HTML 须通过 `python src/prompts-tools/tools/lint_reports.py`。
- 基线导航采用简化锚点目录，不强制 `.report-nav`。
- 落盘后将[业务配置第一节](./business-config.md)的 `{{BASELINE_REPORT_PATH}}` 指向本报告（重建场景）。

## 八、质量自检（通用清单之外的本主题专属项）

- [ ] 地域数据均注明都道府県 / 市町村口径
- [ ] 登记口径（地価公示）与挂牌口径（賃貸门户）已区分
- [ ] 勤務地、注册地、通勤圈已区分（继承 01-ssw-driver 求人四元组教训）
- [ ] "地方" vs "东京圈"薪资对比均同岗位分层
- [ ] 追踪表 4 项均已核对并填写「是否更新」
- [ ] `{{REGISTRY_PATH}}` 已读已写：变更摘要与登记册一致；prompt 模板自身无硬编码活值
- [ ] HTML 通过 lint（标签配对）
