# 日本 · 地域信息 · 季度分析提示词（市场指标监测型）

> **用途**：周期性（每季度）刷新季度分析报告。对监测主题做多维全景研判，更新地域差对比、决策输入与观察清单，完成数据治理与下季度观察清单。
> **产出**：季度报告落盘 `{{OUTPUT_PATH}}`（`reports/{{YYYY-MM}}-<slug>.md` + 同名 HTML）。
>
> **继承声明（四层体系）**：本文件 = [通用基座](../../src/report_templates/prompt-generic-base.md) × [监测报告通用规范](../../src/report_templates/monitoring-common-spec.md) × [季度报告类型模板（市场指标监测型）](../../src/report_templates/market-monitoring/prompt-quarterly-analysis-template.md) × [业务专属配置](./business-config.md)。冲突时以本文件为准。

---

## 运行变量（每次运行前填写）

```
{{CURRENT_DATE}}         = 本次执行日期，格式 YYYY-MM-DD
{{QUARTER}}              = 被分析季度，自然季（如 2027-Q1）
{{PREVIOUS_REPORT_PATH}} = 上一期季度报告路径（首期季度为空，仅锚定基线）
{{BASELINE_REPORT_PATH}} = reports/{{YYYY-MM}}-<slug>.md
{{REGISTRY_PATH}}        = data/regional_indicator_registry.md
{{OUTPUT_PATH}}          = reports/{{YYYY-MM}}-<slug>.md
{{REPORT_VERSION}}       = 本次版本号，格式 vYYYY.MM.DD
```

固定值（不填，读自业务配置第一节）：`{{REGION}}`、`{{TOPIC}}`、`{{FRESHNESS_PRIORITY}}`、`{{SOURCE_LANGUAGE_RULE}}`、`{{REPO_RAW_URL_BASE}}`。

**任务目标**：完成季度全景研判闭环；按[业务配置第七节](./business-config.md)「季度」触发器判定；无触发且窗口未到时不启动，不得虚构变化。

## 一、节拍与触发

季度为市场指标监测型的主研判节拍（见[季度类型模板第一节](../../src/report_templates/market-monitoring/prompt-quarterly-analysis-template.md)）：

- **全景研判**：覆盖业务配置声明的全部维度（地域选择 7 维 + 公共服务差异），逐维交叉核验统计来源，区分并列表述不同统计口径。
- **触发器**（[业务配置第七节](./business-config.md)「季度」）：地域生活支援制度变化（自治体）；医师数等医疗·教育资源统计年度发布（厚労省 / 文科省）。**无触发 → 降级为核验 / 收敛型轻运行。**

## 二、项目专属硬性约束

1. **受众与结论边界**：面向拟在日本选择就业地 / 定居地的读者；输出地域选择框架、地域差对比与决策输入，不给落户价位、不给单一「最优地域」结论；个人地域选择为自记录个案，标注记录日期。
2. **来源语言规则**：统计类须日文官方原文；门户数据仅预期指标。
3. **口径纪律**：登记口径 ≠ 挂牌口径；勤務地 ≠ 注册地 ≠ 通勤圈；都道府県 ≠ 市町村；预期指标 ≠ 实际成交 / 登记值；广域口径与窄域口径不得直接合并。
4. **边界纪律**：薪资地域差链接 07、求职渠道地域策略链接 02、保险与就医流程链接 12、就学手续与学制链接 10、灾害时外国人支援政策环境链接 09。
5. **类型机制适配**：本业务线无价格 / 成交 / 供给类指标，市场指标监测型的结构红线（RL 系）、供给情景重算、五态合成不适用；改以追踪表 + 监测日历 + 条件化决策框架承载。

## 三、各模块更新要点

按[业务配置第 3.2 节](./business-config.md)的结构映射逐模块实例化：

- **地域选择框架（对应多维指标体系与来源 / 信号规则与决策框架）**：7 维评分框架与候选地域速览；逐维更新读数（岗位供给 / 薪资×成本 / 外国人支援 / 同胞密度 / 交通 / 灾害风险 / 生活品质）；决策流程保持。
- **地域间公共服务差异视角（对应多维指标体系与来源）**：医疗资源地域差、教育资源地域差；逐项更新官方统计读数与口径；并列呈现不同口径。
- **地域生活笔记（对应首期基线数据 / 风险局限与监测盲区）**：定居地档案、生活发现、防灾与安全、地域防灾情报渠道、季度观察；更新个人笔记（个案标注）。

## 四、基线锚定与防回退

- 读取 `{{PREVIOUS_REPORT_PATH}}`（首期季度为空）与 `{{BASELINE_REPORT_PATH}}`，继承结构与全部已核实结论。
- 逐条继承「已修正事实清单」，产生修正后追加（格式见[通用基座第五节](../../src/report_templates/prompt-generic-base.md)）；严禁重新引入已被推翻的说法；无来源不得入清单。
- 与首期基线的偏离逐项说明（复核确认 / 修订 / 结构性 / 版本修正 / 无新期）；「零偏离」须解释含义。

## 五、追踪表与登记册联动

按[业务配置第八节](./business-config.md)的 4 项追踪指标逐项核对并填写「是否更新」；运行前从 `{{REGISTRY_PATH}}` 读取活值与研究边界档案 → 复核有效性 → 运行后回写。数据变更摘要至少覆盖全部 4 项；未核实项单列「待复核清单」。prompt 模板内不填活值。

## 六、执行方式（建议）

1. 按调研维度并行启动研究子代理（目标地域岗位密度与薪资地域差 / 生活成本与自治体外国人支援），全部限定日 / 英来源、逐点引用，每条数据附可直接访问的 URL；门户数据标注为预期指标。
2. 主代理读取 `{{PREVIOUS_REPORT_PATH}}` 与基线做差异合并，继承已修正事实清单，应用第三节更新要点。
3. 冲突数据保留双份引用；无法核实项单列「待复核清单」。
4. 回写报告与登记册后运行 `python src/prompts-tools/tools/md2html.py` 重新生成 HTML，并运行 `python src/prompts-tools/tools/lint_reports.py` 校验。

## 七、渲染与交付

- 交付格式：md + 同目录自包含 HTML；季度报告含顶部导航（`.report-nav`），`.nav-url` = `{{REPO_RAW_URL_BASE}}` + `/reports/{本期文件名}`。
- HTML 须通过 `lint_reports.py` 标签配对校验。
- 基线报告常驻 `reports/` 顶层不归档；季度报告按保留策略执行（保留 8 期，超出移入 `reports/archives/`）。

## 八、质量自检（通用清单之外的本主题专属项）

- [ ] 地域数据均注明都道府県 / 市町村口径；登记口径与挂牌口径已区分
- [ ] 勤務地、注册地、通勤圈已区分；"地方" vs "东京圈"薪资对比均同岗位分层
- [ ] 与首期基线的偏离逐项说明；口径冲突并列呈现
- [ ] 追踪表 4 项均已核对并填写「是否更新」
- [ ] `{{REGISTRY_PATH}}` 已读已写，变更摘要与登记册一致
- [ ] 数据变更摘要与待复核清单已产出
- [ ] HTML 通过 lint（标签配对）
