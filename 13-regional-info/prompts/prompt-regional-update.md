# 12 地域信息 · 动态更新提示词

> **用途**：周期性刷新「地域信息」知识库，动态获取地域岗位密度、生活成本、外国人支援的最新官方口径，保持地域选择框架与生活笔记同步。可直接整体复制，替换顶部变量后提交给 AI 执行。
>
> **继承声明（三层体系）**：本文件 = [通用基座](../../prompts/通用基座/prompt-generic-base.md) × [知识库主题更新类型模板](../../prompts/知识库主题更新/prompt-knowledge-topic-update-template.md) × 本主题专属配置。冲突时本文件优先。

---

## 运行变量（每次运行前填写）

```
{{TOPIC_DIR}}            = 13-regional-info（固定）
{{HANDBOOK_PATH}}        = 13-regional-info/reports/日本地域信息知识手册.md
{{DOC_LIST}}             = 手册内对应章节（由主题提示词第五节声明）
{{CURRENT_DATE}}         = 本次运行日期 YYYY-MM-DD
{{FRESHNESS_PRIORITY}}   = 数据时效优先级窗口（默认：统计类近 12 个月内优先；挂牌行情标注采集日期）
{{SOURCE_LANGUAGE_RULE}} = 统计类须日文官方原文；门户数据仅预期指标
{{REGISTRY_PATH}}        = ../data/regional-indicator-registry.md —— 4 项指标活值登记册，每次运行先读后写
{{REVIEWS_DIR}}          = ../reviews/ —— 每期运行复盘存放处（可选）
```

## 一、主题专属硬性约束

通用约束（逐点引用、事实与推断分离、口径标注等）自动继承通用规范第一至四节。本主题额外强制：

1. **受众定位**：就业地选择与地域生活库：地域选择框架（岗位密度、薪资、生活成本、外国人支援）+ 地域生活笔记。地域数据须注明都道府県/市町村口径。
2. **术语口径区分**（正文中不得混用）：
   - 登记口径（地価公示）≠ 挂牌口径（賃貸门户）；
   - 勤務地 ≠ 注册地 ≠ 通勤圈（继承 monitors 求人四元组教训）；
   - "地方"≠"东京圈"的薪资对比须同岗位分层。

## 二、来源优先级（通用框架的本主题实例化，冲突时报双份并标注）

① 国土交通省（住居・地価統計）、総務省統計局（地域统计）、各都道府県/市町村官网 ＞ ② HelloWork 地域检索（岗位密度一手聚合）、JETRO 地域信息 ＞ ③ 賃貸/生活门户（挂牌口径，仅预期指标）＞ ④ 地域媒体

## 三、基线锚定（防止已修正事实回退）

更新时必须**读取 `{{HANDBOOK_PATH}}`（单份知识手册）与受影响章节的当前版本**（含 `reports/archives/` 内历史版），继承其结构与全部已核实结论。本清单随每次修正持续追加：

```
【继承 monitors 求人定位类修正（注册地/勤务地/线路区分）；主题级修正追加于此：
- ❌（首期为空）】
```

## 四、更新协议 + 事件触发器表

刷新窗口与差异对比规则继承通用模板。本主题**必查重大事件触发器**（命中任一项即触发对应文档重点更新；无触发则降级为核验/收敛型轻运行，**不得为制造变化而虚构变化**）：

```
- 目标地域岗位密度/条件显著变化（联动 02-career-driver 求人抽样） → 01
- 地域生活支援制度变化（自治体） → 02
- 个人选定目标地域 → 01/02
```

## 五、手册章节更新要点（知识库主题更新类型）

明确要动态获取 / 保持的内容：

```
【导航与使用约定】更新：篇目状态与最近更新日期；保持：篇目结构（手册前部导航区，含更新日志）
【01 地域选择框架】动态获取：目标地域岗位密度（HelloWork 地域件数）、薪资地域差（锚 monitors 岗位 × 地域分层）、生活成本地域差；保持：选择框架与评分维度（推断标注）
【02 地域生活笔记】动态获取：目标地域自治体多语言支援、外国人登记相关制度；更新：个人笔记；保持：笔记结构
```

## 七、执行方式（建议）

1. 启动 2 个并行研究子代理：① 目标地域岗位密度与薪资地域差；② 生活成本与自治体外国人支援。全部限定日/英来源、逐点引用，**每条数据必须附可直接访问的 URL**；门户数据标注为预期指标。
2. 子代理返回后，由主代理读取 `{{HANDBOOK_PATH}}`（单份知识手册）与受影响章节当前版本做差异合并，**继承已修正事实、应用第四、五节更新要点**。
3. 对冲突数据保留双份引用；对无法核实项单列"待复核清单"。
4. 回写完成后运行 `python prompts/tools/md2html.py 13-regional-info/reports` 重新生成 HTML；运行 `python prompts/tools/archive_reports.py` 执行保留策略。

## 八、输出格式要求

- **增量回写** `{{DOC_LIST}}` 中受影响章节；未受影响章节不动；结构性内容（选择框架与评分维度、笔记结构）按第五节"保持"。
- **变更摘要与待复核清单**写入手册内「导航与使用约定」的更新日志区（格式见知识库模板 T3），不单独成文。
- 正文新增数据点一律附 `[Source: 完整URL, 年份]`；表格按通用规范二.2 呈现（主题文字超链接 + hover 来源，不设"来源"列）；推断显式标注。
- 新增知识在现有文档中找不到位置时，在手册内新建 ## NN 章节（编号顺延）；禁止把不相关内容塞进既有章节，禁止新建独立 .md 文件。
- 文件命名与保留策略：`reports/` 顶层保留最新 3 份（`*_baseline` 基线版固定保留，永不进入 archives），其余入 `reports/archives/`，归档上限 7 份。

- [ ] 勤務地、注册地、通勤圈已区分（继承 monitors 求人四元组教训）

- [ ] 追踪表 4 项均已核对并填"是否更新"
- [ ] `{{REGISTRY_PATH}}` 已读已写：追踪表"上次值"列取自登记册，变更摘要与登记册一致；prompt 模板自身无硬编码活值
