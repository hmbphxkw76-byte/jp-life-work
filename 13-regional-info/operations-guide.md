# 日本地域信息监测 · 四类报告启动操作指引（Agent 可执行版）

> **适用范围**：`13-regional-info` 业务线的基线 / 月度 / 季度 / 年度四类报告。
> **使用方式**：本指引可由人类逐步照做，也可整体交给 AI Agent 执行。Agent 执行时须遵守文末「Agent 执行约定」。
> **单一事实源**：业务参数一律以 [prompts/business-config.md](./prompts/business-config.md) 为准，本指引不复制阈值与来源清单，只给路径。

---

## 0. 通用规定（四类报告共用）

### 0.1 目录速查

| 资产 | 路径 |
|---|---|
| 四份周期提示词（启动入口） | `13-regional-info/prompts/prompt-{baseline-setup|monthly-monitor|quarterly-analysis|annual-review}.md` |
| 业务参数（固定变量、触发器、监测项） | `13-regional-info/prompts/business-config.md` |
| 指标登记册与研究边界档案 | `13-regional-info/data/regional_indicator_registry.md` |
| 报告产物 | `13-regional-info/reports/` |
| 报告归档 | `13-regional-info/reports/archives/` |
| 工具链 | `src/prompts-tools/tools/`（退出码：0 过 / 1 错 / 2 警告） |
| 通用层（只读，不改） | `src/report_templates/` |

### 0.2 两种启动方式

- **手动启动（推荐首次使用）**：打开对应周期提示词 → 填写「运行变量」区块 → 将整份提示词提交给 AI 执行。
- **按周期窗口启动**：本业务线为市场指标监测型月 / 季 / 年三周期；统计类来源按官方发布节奏（年度 / 季度）核对，门户类来源按季度窗口采集，个人决策时点（Offer 比较 / 定居后复盘）触发即时核对。

### 0.3 通用前置检查（每次启动前必做）

```powershell
# 在仓库根目录执行
python src/prompts-tools/tools/validate.py          # 结构与命名校验，期望：本主题零 WARN / 零 ERROR
python src/prompts-tools/tools/lint_reports.py      # 报告内容校验，期望：0 错误
```

> **退出码说明**：`validate.py` 0 = 通过；1 = 存在错误项；2 = 仅存在警告项（警告应仅来自其他未迁移主题）。`lint_reports.py` 0 = 通过；1 = 存在错误（免责声明缺失、表格规范等）。

并人工确认三点：

1. 基线报告 `reports/2026-11_baseline_report.md` + 同名 HTML 存在（月 / 季 / 年的对比锚，缺失则先走第 5 节灾难恢复）。
2. 上期同周期报告存在（首期除外），路径记入 `{{PREVIOUS_REPORT_PATH}}`。
3. 对应周期提示词存在，且继承声明指向 [src/report_templates/market-monitoring/](../src/report_templates/market-monitoring/)。

## 1. 基线报告（首期机制建立，一次性）

### 1.1 启动入口与前置条件

- 入口：[prompt-baseline-setup.md](./prompts/prompt-baseline-setup.md)
- **重要**：本业务线基线已产出（`reports/2026-11_baseline_report.md` v1.0 + 登记册）。**正常运行永不重跑基线**。仅以下两种情形允许再次启动：
  - 报告与登记册全部丢失（灾难恢复）；
  - 十节结构经维护规范批准重排（须在 business-config 版本记录留痕）。
- 前置条件：无上期报告依赖；确认来源清单与官方发布节奏；确认 `{{REGISTRY_PATH}}` 不存在或已获准重建。

### 1.2 运行变量（必填）

| 变量 | 填写规则 | 示例 |
|---|---|---|
| `{{CURRENT_DATE}}` | 本次执行日期 | `2026-11-13` |
| `{{BASELINE_DATE}}` | 首期基线日期（重建时改重建日期） | `2026-11-12` |
| `{{OUTPUT_PATH}}` | 固定 `reports/2026-11_baseline_report.md` | 同左 |
| `{{REPORT_VERSION}}` | 首期固定 `v1.0`；重建时递增 | `v1.0` |

### 1.3 执行步骤

1. 填写提示词顶部运行变量。
2. 按[业务配置第三节](./prompts/business-config.md)确认研究边界与结构映射。
3. 按 4 项追踪指标采集官方一手来源；每个数字记录「机构 · 统计周期 · 核验状态」。
4. 撰写报告：首期保留现行结构（不改正文）；重建场景按十节骨架撰写，标题逐字固化。
5. 首建 / 复核研究边界档案（领域边界、统计域分层、主体清单与入选标准、口径清单），回写 `{{REGISTRY_PATH}}`。
6. 回填追踪表 4 项「是否更新」；空清单补记「已修正事实清单」（首期为空）。
7. 落盘 `{{OUTPUT_PATH}}` 与同名 HTML。

### 1.4 结果验证

```powershell
python src/prompts-tools/tools/lint_reports.py
```

人工核对：地域数据注明统计域；登记口径与挂牌口径已区分；免责声明为固定原文；基线导航为简化锚点；结构与声明映射一致。

## 2. 月度报告（轻量核验节拍）

### 2.1 启动入口与前置条件

- 入口：[prompt-monthly-monitor.md](./prompts/prompt-monthly-monitor.md)
- 前置条件：通用前置检查通过；确定本期性质（T+0 / T+1 / 空窗，见 2.4）；检查[业务配置第七节](./prompts/business-config.md)「月度」触发器是否命中（目标地域岗位密度 / 条件显著变化、防灾气象预警体系与配信渠道变化）。**无触发 → 降级为核验 / 收敛型轻运行，不得虚构变化。**

### 2.2 运行变量（必填）

| 变量 | 填写规则 | 示例（2026 年 12 月期） |
|---|---|---|
| `{{CURRENT_DATE}}` | 本次执行日期 | `2026-12-05` |
| `{{PREVIOUS_REPORT_PATH}}` | `reports/` 中最近一期月度报告 | `reports/2026-11_monthly.md` |
| `{{BASELINE_REPORT_PATH}}` | 固定 `reports/2026-11_baseline_report.md` | 同左 |
| `{{OUTPUT_PATH}}` | `reports/{{YYYY-MM}}_monthly.md`，月份＝数据所属月 | `reports/2026-12_monthly.md` |
| `{{REPORT_VERSION}}` | `v` + 执行日期 | `v2026.12.05` |

固定值（不填，读自业务配置第一节）：`{{REGISTRY_PATH}}`、`{{REPO_RAW_URL_BASE}}` 等。

### 2.3 执行步骤

1. 填变量 → 读 `{{PREVIOUS_REPORT_PATH}}` 与基线，提取「已修正事实清单」全部条目（防回退）。
2. 发布日历判定（T+0 / T+1 / 空窗）：核对统计类来源最新一期标题与发布日期。
3. 运行前从登记册读取活值与研究边界档案，填入追踪表。
4. 按三个模块采集：①地域选择框架；②地域间公共服务差异视角；③地域生活笔记（含防灾情报渠道）。
5. 逐模块核验；冲突数据保留双份引用；无法核实项单列「待复核清单」。
6. 数据变更摘要覆盖全部 4 项；回写报告与登记册。
7. 落盘 md + HTML。

### 2.4 时间范围与数据范围规则

- **报告月份 = 数据所属月**（非执行月）。文件名 `2026-12_monthly.md` 覆盖 2026 年 12 月发布窗口内可取得的最新数据。
- T+1 判定：本期与上期发布窗口同日或仅隔 1 日 → 报告明确标注「T+1 刷新」，价值在核验、口径澄清与阈值距离，不制造变化。
- 时效取舍：统计类近 12 个月内优先；门户数据标注采集日期并标为预期指标；同一指标多版本并存以官方最新发布为准。

### 2.5 结果验证

```powershell
python src/prompts-tools/tools/lint_reports.py
python src/prompts-tools/tools/classify_reports.py
```

人工核对：导航锚点全部跳转准确；已修正事实清单无回退；登记口径与挂牌口径并列；免责声明原文未改写；登记册与报告变更摘要一致。

## 3. 季度报告（全景研判节拍）

### 3.1 启动入口与前置条件

- 入口：[prompt-quarterly-analysis.md](./prompts/prompt-quarterly-analysis.md)
- 前置条件：通用前置检查通过；确认季度触发器（地域生活支援制度变化、医师数等医疗·教育资源统计年度发布，见[业务配置第七节](./prompts/business-config.md)「季度」）。**无触发 → 降级为核验 / 收敛型轻运行。**

### 3.2 运行变量（必填）

| 变量 | 填写规则 | 示例 |
|---|---|---|
| `{{CURRENT_DATE}}` | 本次执行日期 | `2027-04-08` |
| `{{QUARTER}}` | 被分析季度，自然季 | `2027-Q1` |
| `{{PREVIOUS_REPORT_PATH}}` | 最近一期季度报告 | `reports/2026-Q4_quarterly.md` |
| `{{BASELINE_REPORT_PATH}}` | 固定 `reports/2026-11_baseline_report.md` | 同左 |
| `{{OUTPUT_PATH}}` | `reports/{{YYYY-Qn}}_quarterly.md`，季度＝被分析季度 | `reports/2027-Q1_quarterly.md` |
| `{{REPORT_VERSION}}` | `v` + 执行日期 | `v2027.04.08` |

### 3.3 执行步骤

1. 填变量 → 读 `{{PREVIOUS_REPORT_PATH}}` 与基线，继承「已修正事实清单」。
2. 全景研判：地域选择 7 维 + 公共服务差异，逐维交叉核验，口径并列（登记口径 ≠ 挂牌口径 ≠ 预期指标）。
3. 逐项更新读数；与首期基线的偏离逐项说明（复核确认 / 修订 / 结构性 / 版本修正 / 无新期）。
4. 数据变更摘要覆盖全部 4 项；回写报告与登记册。
5. 落盘 md + HTML。

### 3.4 时间范围与数据范围规则

- **分析对象 = 自然季度**（Q1=1–3 月，Q2=4–6 月，Q3=7–9 月，Q4=10–12 月）。启动时点通常在季末后 1–2 个月，以统计发布为准。
- 统计滞后于自然季时标「滞后一期」；广域口径与窄域口径不得直接合并；不同统计域（都道府県 / 市町村）不得混算。

### 3.5 结果验证

```powershell

python src/prompts-tools/tools/classify_reports.py
```

人工核对：导航锚点全部跳转准确；与基线偏离逐项说明；口径并列表齐全；免责声明原文未改写。

- 入口：[prompt-annual-review.md](./prompts/prompt-annual-review.md)
- 前置条件：通用前置检查通过；年度触发器确认（国交省地価统计 / 地域统计年度发布、个人选定目标地域，见[业务配置第七节](./prompts/business-config.md)「年度」）；确认上期最新月度 / 季度报告路径。

### 4.2 运行变量（必填）

| 变量 | 填写规则 | 示例（复盘 2026 年） |
|---|---|---|
| `{{CURRENT_DATE}}` | 本次执行日期 | `2027-01-15` |
| `{{YEAR}}` | 被复盘的年份 | `2026` |
| `{{DATA_CUTOFF}}` | 数据截止日；未发布写最近已发布周期 | `2026-12-31` |
| `{{PREVIOUS_REPORT_PATH}}` | 最近一期月度或季度报告 | `reports/2026-12_monthly.md` |
| `{{BASELINE_REPORT_PATH}}` | 固定 `reports/2026-11_baseline_report.md` | 同左 |
| `{{OUTPUT_PATH}}` | `reports/{{YEAR}}_annual.md` | `reports/2026_annual.md` |
| `{{REPORT_VERSION}}` | `v` + 执行日期 | `v2027.01.15` |

### 4.3 执行步骤

1. 填变量 → 读 `{{PREVIOUS_REPORT_PATH}}` 与基线，继承「已修正事实清单」。
2. 全年复盘：地域选择框架 7 维读数年度更新、候选地域速览刷新、公共服务差异年度统计更新、生活笔记年度汇总。
3. 判断 vs 实际偏离检验：偏离度 =（实际 ÷ 对照）− 1，绝对值 >30% 必须重设假设并列出重设的三项假设，不做事后拟合。
4. 重置长期基线（地域统计类锚取最近已发布年度值）；上年判断逐条复判，原文保留。
5. 数据变更摘要覆盖全部 4 项；登记册按「增量留痕」回写，不覆盖历史值。
6. 落盘 md + HTML。

### 4.4 时间范围与数据范围规则

- **复盘对象 = `{{YEAR}}` 全年**；数据截止 `{{DATA_CUTOFF}}`，未发布的年度值写最近已发布周期并标注。
- 年度数据存在时滞，不得用于月度择时；「实时值」与「年度基准」口径不得混用。

## 5. 全类型通用收尾（每次报告落盘后必做）

### 5.1 校验

```powershell
python src/prompts-tools/tools/lint_reports.py
python src/prompts-tools/tools/classify_reports.py
```

- [ ] 免责声明固定原文存在（含「免责声明」节 + 「不构成投资建议」表述）——**现有报告为遗留项，新产出报告必须满足**
- [ ] 表格 `<thead>` / `<tbody>` 成对，多列表声明百分比列宽，无竖排塌缩
- [ ] 来源链接可点击，`[Source: 完整URL, 年份]` 完整
- [ ] 图注含单位、来源、统计周期与口径警示
- [ ] 锚点跳转准确（月 / 季 / 年报告：`href="#sN"` 与 `<h2 id="sN">` 逐字对应）
- [ ] 浏览器打开无控制台 error

### 5.2 归档

- 基线报告常驻 `reports/` 顶层，不归档。
- 月度报告保留最新 12 期、季度保留 8 期、年度保留 5 期，超出移入 `reports/archives/`。
- 登记册修改采用增量方式：保留历史值，不覆盖。

### 5.3 提交

git 提交报告 + 登记册（建议提交信息：`report: {YYYY-MM} 地域信息月度监测` 等格式）。

### 5.4 浏览器抽查

打开 HTML，确认导航锚点、表格排版、来源链接与正文数值一致。

## 6. 常见异常排查

| 现象 | 原因 | 处置 |
|---|---|---|
| `validate.py` 退出码 1 | 通用层缺文件 / 业务目录结构缺项 / 报告命名不合规 | 按 error 行补齐文件或改命名；不得为过检删除通用层内容 |
| `lint_reports.py` 退出码 1 | 缺免责声明（须同时含「免责声明」节 + 「不构成投资建议」）、表格规范错误 | 按行修复 HTML；免责声明用固定原文 |
| `validate.py` 退出码 2 | 存在警告项 | 确认警告仅来自其他未迁移主题；本主题应零 WARN |
| 基线报告缺失 | 误删或未恢复 | **停止周期报告**，先按 prompt-baseline-setup.md 灾难恢复 |
| 上年判断被改写 | 差异合并时覆盖原文 | 恢复原文，复判结论另起段落并列呈现 |
| 官方页面无新数据 | 发布窗口未开（T+1 / 空窗） | 正常情形：按核验型轻运行处理，禁止虚构变化 |
| 口径冲突无法裁决 | 多源口径不同 | 并列呈现并标注来源与年份，不取均值 |
| 内联 JS 报错 | 图表语法错误 | `node --check` 定位；修复后重新落盘 |
| 链接指向旧文件名 | 报告改名后未同步 | 全库 grep 旧报告名 / 旧登记册名并改为新名 |

## 7. Agent 执行约定

1. **顺序不可跳**：前置检查 → 填变量 → 日历判定 → 读上期 / 基线 → 采集 → 写报告 → 回写登记册 → 校验 → 收尾。任何前置步骤失败即停，不得带病运行。
2. **单一事实源**：边界、来源、口径、触发器从 business-config.md 与登记册读取，不得凭记忆填写；提示词内严禁预填活值。
3. **防回退**：每次运行必须完整继承「已修正事实清单」；与清单冲突的旧结论不得复活。
4. **不虚构**：无触发器命中时降级为核验型轻运行；「没有数据」写成可核验陈述。
5. **留痕**：所有修正逐条补记清单；登记册更新按「实质修订 / 新增口径记录 / 复核确认 / 未取得维持上期值 / 结论不变」分组。
6. **边界**：只输出「条件 → 判断 → 框架性含义 → 风险提示」，不给落户价位、不给单一「最优地域」结论；薪资地域差转 07、求职渠道地域策略转 02、保险与就医流程转 12、就学手续与学制转 10、灾害时外国人支援政策环境转 09。
