11 文化与生活 · 动态更新提示词

用途：周期性刷新「文化与生活」知识库，动态获取劳动文化制度、生活手续、自治体支援的最新官方口径，保持个人生活适应记录同步。可直接整体复制，替换顶部变量后提交给 AI 执行。

继承声明（三层体系）：本文件 = 通用基座 × 知识库主题更新类型模板 × 本主题专属配置。冲突时本文件优先。

运行变量（每次运行前填写）

{{TOPIC_DIR}}            = monitors-culture-life（固定）
{{HANDBOOK_PATH}}        = monitors-culture-life/reports/日本文化与生活知识手册.md
{{DOC_LIST}}             = 手册内对应章节（由主题提示词第五节声明）
{{CURRENT_DATE}}         = 本次运行日期 YYYY-MM-DD
{{FRESHNESS_PRIORITY}}   = 数据时效优先级窗口（默认：制度类近 12 个月内优先；经验类标注记录日期）
{{SOURCE_LANGUAGE_RULE}} = 制度类须日文官方原文；经验类不限（标注为个案）
{{REGISTRY_PATH}}        = ../data/culture-life-indicator-registry.md —— 3 项指标活值登记册，每次运行先读后写
{{REVIEWS_DIR}}          = ../reviews/ —— 每期运行复盘存放处（可选）

一、主题专属硬性约束

通用约束（逐点引用、事实与推断分离、口径标注等）自动继承通用规范第一至四节。本主题额外强制：

  1. 受众定位：职场文化适应与生活指南：职场人际、现场文化、生活适应。经验类内容须与制度类内容分离存放与标注。
  2. 术语口径区分（正文中不得混用）：
  3. 法规义务 ≠ 职场惯例（习惯性做法不得表述为法定要求）；
  4. 「先輩後輩」等文化描述标注为一般化观察，不作统计事实。

二、来源优先级（通用框架的本主题实例化，冲突时报双份并标注）

① 厚生労働省（労働に関する制度）、総務省/自治体（生活制度、ゴミ分別等）＞ ② JILPT/公共機関的职场调查 ＞ ③ 地域自治体多语言生活指南 ＞ ④ 在日生活门户与社区（经验类，标注个案）

三、基线锚定（防止已修正事实回退）

更新时必须读取 {{HANDBOOK_PATH}}（单份知识手册）与受影响章节的当前版本（含 reports/archives/ 内历史版），继承其结构与全部已核实结论。本清单随每次修正持续追加：

- ❌（首期为空）——产生修正后逐条补记。

四、更新协议 + 事件触发器表

刷新窗口与差异对比规则继承通用模板。本主题必查重大事件触发器（命中任一项即触发对应文档重点更新；无触发则降级为核验/收敛型轻运行，不得为制造变化而虚构变化）：

- 劳动文化相关制度变化（联动 monitors-politics-law） → 01
- 生活制度变化（在留卡手续、年金手续等，联动 monitors-visa-immigration） → 02
- 个人新生活经验沉淀 → 02

五、手册章节更新要点（知识库主题更新类型）

明确要动态获取 / 保持的内容：

【导航与使用约定】更新：篇目状态与最近更新日期；保持：篇目结构（手册前部导航区，含更新日志）
【01 职场文化与人际】更新：现场观察沉淀（个案标注）；动态获取：相关调查/官方指引；保持：主题框架
【02 生活指南与适应】动态获取：在留手续、生活制度官方现行流程；更新：个人适应记录；保持：清单结构

六、关键信息追踪表 — 每次运行逐项核对

prompt 模板内严禁填写活值；运行前从 {{REGISTRY_PATH}} 读取、运行后回写。登记册格式见通用基座五-A。

# 信息项 优先数据源 上次值（运行前从 {{REGISTRY_PATH}} 读取填入） 本次是否更新
1 在留相关生活手续流程变化 自治体/入管庁 ☐
2 职场文化相关官方调查 JILPT/厚労省 ☐
3 个人生活适应记录 自记录 ☐

每次运行须逐项填写"是否更新"，未变动项保留登记册值并注明"截至 {{CURRENT_DATE}} 无更新"。指标活值统一维护于 {{REGISTRY_PATH}}（登记册格式见通用基座五-A）：运行前读登记册 → 核验 → 运行后回写登记册 → 回写手册内更新日志区与相关章节；prompt 模板内不重复维护数值。

七、执行方式（建议）

  1. 启动 1–2 个并行研究子代理：① 劳动制度与职场调查；② 生活手续与自治体支援。全部限定日/英来源、逐点引用，每条数据必须附可直接访问的 URL。经验类内容作为个案沉淀单独标注。
  2. 子代理返回后，由主代理读取 {{HANDBOOK_PATH}}（单份知识手册）与受影响章节当前版本做差异合并，继承已修正事实、应用第四、五节更新要点。
  3. 对冲突数据保留双份引用；对无法核实项单列"待复核清单"。
  4. 回写完成后运行 python prompts/tools/md2html.py monitors-culture-life/reports 重新生成 HTML；运行 python prompts/tools/archive_reports.py 执行保留策略。

八、输出格式要求

  • 增量回写 {{DOC_LIST}} 中受影响章节；未受影响章节不动；结构性内容（主题框架、清单结构）按第五节"保持"。
  • 变更摘要与待复核清单写入手册内「导航与使用约定」的更新日志区（格式见知识库模板 T3），不单独成文。
  • 正文新增数据点一律附 [Source: 完整URL, 年份]；表格按通用规范二.2 呈现（主题文字超链接 + hover 来源，不设"来源"列）；推断显式标注。
  • 新增知识在现有文档中找不到位置时，在手册内新建 ## NN 章节（编号顺延）；禁止把不相关内容塞进既有章节，禁止新建独立 .md 文件。
  • 文件命名与保留策略：reports/ 顶层保留最新 3 份（*_baseline 基线版固定保留，永不进入 archives），其余入 reports/archives/，归档上限 7 份。

九、质量自检（通用清单之外的本主题专属项）

通用自检清单见通用规范第八节。本主题额外确认：

  • [ ] 法规义务与职场惯例已区分，习惯性做法未表述为法定要求
  • [ ] 经验类内容全部标注为个案，未与制度类事实混存
  • [ ] 与 monitors-politics-law、monitors-visa-immigration 的联动触发器正确
  • [ ] 追踪表 3 项均已核对并填"是否更新"
  • [ ] {{REGISTRY_PATH}} 已读已写：追踪表"上次值"列取自登记册，变更摘要与登记册一致；prompt 模板自身无硬编码活值

结束提示词。
