08 政治与法规 · 动态更新提示词

用途：周期性刷新「政治与法规」知识库，动态获取入管法改正、劳动维权渠道、移民政策动向的最新官方口径。可直接整体复制，替换顶部变量后提交给 AI 执行。

继承声明（三层体系）：本文件 = 通用基座 × 知识库主题更新类型模板 × 本主题专属配置。维权渠道以 monitors-ssw-driver-logistics 修正清单（ITJ/GFP 结论）为锚，本主题不得另立分叉；冲突时以本文件为准。

运行变量（每次运行前填写）

{{TOPIC_DIR}}            = monitors-politics-law（固定）
{{HANDBOOK_PATH}}        = monitors-politics-law/reports/日本政治与法规知识手册.md
{{DOC_LIST}}             = 手册内对应章节（由主题提示词第五节声明）
{{CURRENT_DATE}}         = 本次运行日期 YYYY-MM-DD
{{FRESHNESS_PRIORITY}}   = 数据时效优先级窗口（默认：法规类近 12 个月内优先；政治动向标注事件日期）
{{SOURCE_LANGUAGE_RULE}} = 法规类须日文官方原文；政治动向类日英媒体可引但须回溯
{{REGISTRY_PATH}}        = ../data/politics-law-indicator-registry.md —— 3 项指标活值登记册，每次运行先读后写
{{REVIEWS_DIR}}          = ../reviews/ —— 每期运行复盘存放处（可选）

一、主题专属硬性约束

通用约束（逐点引用、事实与推断分离、口径标注等）自动继承通用规范第一至四节。本主题额外强制：

  1. 受众定位：在留法规、移民政策环境、个人维权工具箱。政治动向影响判断属推断，须标注；法规条文引用须给 e-Gov 或官方原文链接。
  2. 术语口径区分（正文中不得混用）：
  3. 法令条文（e-Gov 原文）≠ 政府解说页 ≠ 媒体转述，三层须分别标注；
  4. 在留资格种类引用须注明制度（同 monitors-visa-immigration 口径）。
  5. 交叉验证锚：维权渠道以 monitors-ssw-driver-logistics 修正清单（ITJ/GFP 结论）为锚；本主题文档与监测报告冲突时，回写监测报告并同步本主题。

二、来源优先级（通用框架的本主题实例化，冲突时报双份并标注）

① e-Gov 法令检索、出入国在留管理庁、厚生労働省（check-roudou.mhlw.go.jp）、各都道府県労働局 ＞ ② JILPT 研究报告 ＞ ③ 弁護士会/行政书士会公开指引 ＞ ④ NHK、日本経済新聞、Nikkei Asia（政治动向，须回溯）

三、基线锚定（防止已修正事实回退）

更新时必须读取 {{HANDBOOK_PATH}}（单份知识手册）与受影响章节的当前版本（含 reports/archives/ 内历史版），继承其结构与全部已核实结论。本清单随每次修正持续追加：

【继承 monitors 最新版报告文首清单（含"不得再提 ITJ 窗口/GFP 官方支持机构"条目）；主题级修正追加于此：
- ❌（首期为空）】

制度类修正统一记入 monitors-ssw-driver-logistics 报告文首清单为单一事实源；本主题只追加主题级修正（文档结构、路径、口径类）。

四、更新协议 + 事件触发器表

刷新窗口与差异对比规则继承通用模板。本主题必查重大事件触发器（命中任一项即触发对应文档重点更新；无触发则降级为核验/收敛型轻运行，不得为制造变化而虚构变化）：

- 入管法/相关法令改正（e-Gov 公布） → 01
- 移民政策重大动向（受入方针、政党政策变化） → 02
- 劳动维权渠道/热线变化 → 03
- monitors 修正清单涉及维权条目（ITJ/GFP 类） → 03

五、手册章节更新要点（知识库主题更新类型）

明确要动态获取 / 保持的内容：

【导航与使用约定】更新：篇目状态与最近更新日期；保持：篇目结构（手册前部导航区，含更新日志）
【01 在留法规框架】动态获取：入管法及关系法令改正（锚 monitors-visa-immigration 制度触发器）；保持：法规框架图
【02 政治动向与移民政策环境】动态获取：政策报道、阁议决定；保持：动向时间线（推断标注）
【03 维权与合规工具箱】动态获取：厚労省外国人相談窗口、劳动基准监督署联系方式现行口径；保持：维权路径清单

七、执行方式（建议）

  1. 启动 2–3 个并行研究子代理：① 入管法及关系法令改正；② 劳动维权渠道与咨询窗口；③ 移民政策动向。全部限定日/英官方来源、逐点引用，每条数据必须附可直接访问的 URL；媒体报道须回溯原文。
  2. 子代理返回后，由主代理读取 {{HANDBOOK_PATH}}（单份知识手册）与受影响章节当前版本做差异合并，继承已修正事实、应用第四、五节更新要点。
  3. 对冲突数据保留双份引用；对无法核实项单列"待复核清单"。
  4. 回写完成后运行 python prompts/tools/md2html.py monitors-politics-law/reports 重新生成 HTML；运行 python prompts/tools/archive_reports.py 执行保留策略。

八、输出格式要求

  • 增量回写 {{DOC_LIST}} 中受影响章节；未受影响章节不动；结构性内容（法规框架图、动向时间线、维权路径清单）按第五节"保持"。
  • 变更摘要与待复核清单写入手册内「导航与使用约定」的更新日志区（格式见知识库模板 T3），不单独成文。
  • 正文新增数据点一律附 [Source: 完整URL, 年份]；表格按通用规范二.2 呈现（主题文字超链接 + hover 来源，不设"来源"列）；推断显式标注。
  • 新增知识在现有文档中找不到位置时，在手册内新建 ## NN 章节（编号顺延）；禁止把不相关内容塞进既有章节，禁止新建独立 .md 文件。
  • 文件命名与保留策略：reports/ 顶层保留最新 3 份（*_baseline 基线版固定保留，永不进入 archives），其余入 reports/archives/，归档上限 7 份。

通用自检清单见通用规范第八节。本主题额外确认：

  • [ ] 法令条文（e-Gov 原文）、政府解说页、媒体转述三层已分别标注
  • [ ] 在留资格种类引用与 monitors-visa-immigration 口径一致
  • [ ] 政治动向影响判断均标注为推断
  • [ ] 未出现已修正的 ITJ 窗口 / GFP 官方支持机构引用
  • [ ] 追踪表 3 项均已核对并填"是否更新"
  • [ ] {{REGISTRY_PATH}} 已读已写：追踪表"上次值"列取自登记册，变更摘要与登记册一致；prompt 模板自身无硬编码活值
