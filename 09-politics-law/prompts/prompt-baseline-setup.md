## 一、项目专属硬性约束

1. **官方原文铁律**：法规类须 e-Gov / 官方原文；媒体转述仅作线索。法令条文 / 政府解说页 / 媒体转述三层须分别标注。
2. **只盯官方文本**：不采集舆论反应（边界归舆情监测型）；原文有歧义处并列多解，不静默择一。
3. **结论边界**：不构成法律意见；合规应对建议标「建议」；重大合规决策提示咨询执业法律专业人士。政治动向影响判断一律标「推断」。
4. **术语口径**：入管法 ≠ 関係法令；在留资格种类引用须注明制度（与 08 口径一致）。
5. **边界纪律**：签证实务归 08、劳动合规细节归 02、自动驾驶法规归 05、永住年收财务归 07、地域信息归 13；官方统计活值只读引用 01 登记册。

## 二、来源优先级

见[业务配置第五节](./business-config.md)：① e-Gov / ISA / 厚労省 / 総務省 / 各都道府県労働局 ＞ ② 主要政党官网 / JILPT ＞ ③ 弁護士会 / 行政书士会 ＞ ④ 媒体（须回溯）。每条数据附官方原文 URL 与版本日期。

## 三、基线锚定与重启条件

- 基线报告一经产出即为对比锚：监管框架地图、解读规则与已核实结论由后续事件触发解读完整继承。
- **正常运行不重跑**。重启仅限两种情形：①灾难恢复（报告与登记册全部丢失）；②九节结构经维护规范批准重排。重排须在[业务配置](./business-config.md)第十二节版本记录留痕，并同步评估解读提示词。
- 现状：首期基线保留现行三章结构（业务固化锚），结构映射见[业务配置第 3.2 节](./business-config.md)。

## 五、追踪表与边界档案

按[业务配置第八节](./business-config.md)的 5 项追踪指标逐项核对并填写「是否更新」；运行后回写 `{{REGISTRY_PATH}}` 的核心指标与[研究边界档案](./business-config.md)（领域边界、法规分层、主体清单与入选标准、口径清单）。未核实项注明「待核实」，不补值、不外推；prompt 模板内不填活值。

## 六、执行方式（建议）

1. 原文回溯先行：逐渠道核对官方原文，完成台账登记后才进入解读环节。
2. 并行启动 2–3 个研究子代理：① 入管法及关系法令改正；② 劳动维权渠道与咨询窗口；③ 移民政策动向。全部限定日 / 英官方来源、逐点引用，每条数据附可直接访问的 URL；媒体报道须回溯原文。
3. 主代理合并差异，冲突口径保留双份引用，无法核实项单列「待复核清单」。
4. 维权渠道结论（ITJ / GFP 类）与 01-ssw-driver 最新报告文首「已修正事实清单」交叉验证一致（只读锚，不回写）。

## 七、渲染与交付

- 交付格式：md + 同目录自包含 HTML（`python src/prompts-tools/tools/md2html.py`）；HTML 须通过 `python src/prompts-tools/tools/lint_reports.py`。
- 基线导航采用简化锚点目录，不强制 `.report-nav`。
- 落盘后将[业务配置第一节](./business-config.md)的 `{{BASELINE_REPORT_PATH}}` 指向本报告（重建场景）。
