# 端到端流水线编排系统 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在「研究正文人 / Agent 产出」边界内，把触发检测 → 计划 → 撰写 → 生成校验 → 审计提交 → 监控串成有状态、可续跑、可观测的端到端流水线。

**Architecture:** 纯本地 CLI 编排（`pipeline_runner.py` 六阶段状态机）+ 触发检测（`trigger_watch.py`，派生自 business-config §7 与登记册）+ 统一监控（`pipeline_status.py`）；CI 只承担定时检测与门禁，不跑撰写。复用既有 27 个工具，不修改其规则。

**Tech Stack:** Python 3.12 标准库（不新增依赖）、GitHub Actions、Markdown/JSON。

**Spec:** `docs/端到端流水线编排系统设计-2026-11-17.md`

**Global Constraints:**
- 不新增第三方依赖；仅用标准库 + 仓库既有 `_common`。
- 新工具遵循退出码约定：0 通过 / 1 错误 / 2 仅警告。
- 状态文件只存路径、状态、时间戳、摘要；不存正文、不存凭据。
- 唯一人工环节 = S2 研究正文撰写；编排器不得自动产出正文。
- 所有写盘走 `_common.atomic_write`。
- 提交 / 合并只走 `python engine/scripts/workflow_guard.py`；不直接 push `main`。
- 命名：工具 `pipeline_*.py` / `trigger_watch.py`；状态 `state-<period>.json`；快照 `trigger-watch.json`。
- 既有工具只调用、不修改其校验规则。

## 阶段总览（任务节点 / 责任人 / 时间节点 / 验收标准）

> 时间节点为**建议值**（自 2026-11-17 起），可在审定时调整；责任人为「Agent」= 本会话执行，「用户」= 审定 / 验收。

| 阶段 | 任务节点 | 责任人 | 时间节点 | 验收标准 |
|---|---|---|---|---|
| P0 审定 | 设计文档 + 本计划审定 | 用户（审定）/ Agent（修订） | 2026-11-17 | 设计文档八项 checklist 全通过；计划确认 |
| P1 基础设施 | T1 状态层 | Agent | 2026-11-18 | 单测通过；schema 校验用例 ≥ 3 |
| P2 触发检测 | T2 `trigger_watch.py` | Agent | 2026-11-19 | 幂等零差异；默认只读；单测 ≥ 6 |
| P3 编排器 | T3 `pipeline_runner.py` | Agent | 2026-11-20 | 断点续跑 ≥ 4 用例；失败可恢复；S2 闸门生效 |
| P4 监控与 CI | T4 `pipeline_status.py` + T5 工作流 | Agent | 2026-11-21 | CI 全绿；监控字段齐全；既有测试无回归 |
| P5 治理与验收 | T6 治理标准 + T7 一致性报告 | Agent + 用户（验收） | 2026-11-22 | 一致性报告通过；交付物 D1–D10 齐 |

**Review Focus:**
1. 空状态 / 首次运行：无状态文件时编排器须能冷启动，不得崩溃。
2. 损坏状态文件：`schema_version` 缺失或不符须报错并可重建，不得静默续跑。
3. 幂等：同一阶段重复执行须产出一致，状态文件无额外漂移。
4. 无触发 / 无待办：触发检测须返回空清单而非虚构候选。
5. S2 闸门：编排器在 S2 必须暂停，不得跳过或自动生成正文。

Run: `python -m pytest engine/tests/test_pipeline_orchestrator.py -v`
Expected: FAIL

- [ ] **Step 3: 实现 `pipeline_runner.py`**

- 每阶段一个函数，签名 `(period, project, dry_run) -> (ok: bool, summary: dict)`。
- `S0_detect` 调 `trigger_watch.scan`；`S1_plan` 调 `update_planner`；`S2_author` **只置 `pending` 并产出待撰写清单，不产出正文**；`S3_build` 调 `md2html` + `auto_verify`；`S4_audit` 调 `audit_pipeline --submit`；`S5_monitor` 调 `pipeline_status.collect`。
- `run`：从 `from_stage`（缺省 `S0_detect`）起顺序执行；遇 `S2_author` 且未显式 `from_stage` 跳过时停在 `pending` 并返回 0。
- 每阶段结束写 `save_state`；失败写 `FAILED` 并返回 1。
