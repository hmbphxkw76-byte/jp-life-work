## 一、审计范围与方法

1. **规范基线法**：以根部规范 + `compliance-rules.json` + `_common.py` 登记为基准，逐文件核对。
2. **逐份通读 + 程序化交叉校验**：相对链接可解析性 333 条、变量使用汇总、节数与 `compliance-rules` 对照、审计工具引用覆盖。
3. **结构程序化核对**：脚本提取每份模板「声明节数 / 结构表行数 / 自检清单节数」，与 `compliance-rules.json` 的 `sections` 交叉比对。
4. **链接可解析性核对**：按「存储位置 / 复制后位置」双语义核对继承声明、类型模板引用、工具路径是否真实可达。
5. **命名一致性核对**：提取全部 `{{OUTPUT_PATH}}` / 文件名示例，与 `monitoring-common-spec.md` §1 及命名正则比对，并与业务线实际产物（22 份）对照。
6. **三处同步核对**：类型模板 ↔ `prompts/` 泛用版 ↔ `business-prompt-scaffold.md` 的内容与必备章节一致性。
7. **行业最佳实践对照**：按 `report-classification.md` 六族十三类的「核心产出 / 数据来源特征 / 边界」，逐类评估章节覆盖度与模块完整性。
