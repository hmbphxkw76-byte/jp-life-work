## 一、方案背景

### 1.1 仓库定位

jp-life-work 是「**文档即内容 + 工具链即引擎 + 静态 HTML 即交付物**」的离线知识库：21 个主题、27 个工具脚本（+ `_common` 内核）、7 条 GitHub Actions 工作流、259 项契约测试。无长驻服务、无网络服务端、无数据库、无前端工程。

### 1.2 实测基线（2026-11-16）

| 项 | 实测值 |
|---|---|
| 工具脚本 | 28 个 `.py`（27 工具 + `_common`） |
| 工作流 | 7 条 |
| 主题 / 报告 | 21 主题；md 22、html 22 |
| 词库主题 | 20 |
| 契约测试 | 259 项 OK（2 skipped） |
| `validate.py` | 退出码 0 |
| 唯一外部依赖 | `markdown==3.11.3` |
| CI | ubuntu-latest / Python 3.12 |

### 1.3 评估结论

架构整体健康：五层职责清晰、依赖单向、幂等与回滚设计突出、文档与测试文化强。但存在以下需优化的问题（详见评估）：

| 编号 | 级别 | 问题 |
|---|---|---|
| I-1 | P1 | 规范文档易变数字漂移（记 255，实测 259） |
| I-2 | P1 | 新类型注册点 4 处分散 |
| I-3 | P1 | 写回/生成缺统一原子写 |
| I-4 | P1 | `workflow_guard --verify-cmd` 使用 `shell=True` |
| I-5 | P2 | 全量扫描、无基准、测试耗时 58s |
| I-6 | P2 | 私有函数跨模块依赖 |
| I-7 | P2 | 无 mypy/ruff 配置 |
| I-8 | P2 | 无 E2E 流水线测试 |
| I-9 | P2 | 无工具/类型单一注册表 |
| I-10 | P2 | 安全属性无专用回归测试 |
| 安全类 | P1/P2 | 命令注入面（=I-4）、路径越界防护、安全属性回归 |

## 二、核心目标

| 方向 | 优化目标 | 关联问题 |
|---|---|---|
| A 单一事实源强化 | 消除文档↔代码口径漂移与注册点分散，清单/文档由注册表派生 | I-1、I-2、I-9 |
| B 事务性写 | 写回/生成操作原子性，中断不产生脏文件 | I-3 |
| C 入口安全硬化 | 消除命令注入面与路径越界 | I-4、安全类 |
| D 性能与规模 | 控制规模增长下的构建耗时，建立可观测基线 | I-5 |
| E 工程硬化 | 引入静态检查与端到端覆盖 | I-7、I-8 |
| F 私有接口治理 | 跨模块复用只依赖公开接口 | I-6 |
| G 安全回归 | 关键安全属性具备专用断言 | I-10、安全类 |

## 三、架构设计

### 3.1 分层架构（保持不变，仅强化约束）

| 层 | 职责 | 载体 |
|---|---|---|
| ① 研究生产层 | 提示词四层继承 + 登记册 + 词库 | `NN-topic/prompts`、`data/*_indicator_registry.md`、`src/vocabulary` |
| ② 生成同步层 | md→HTML→索引→归档 | `md2html` / `report_diff` / `build_hub` / `build_index` / `archive_reports` |
| ③ 质量门禁层 | 规范类硬门禁 | `validate.yml` + `stage_gate_check` / `lint_reports` / `compliance_check` / `info_quality_check` |
| ④ 审计闭环层 | L1–L5 + 状态机 + 哈希链台账 | `audit_pipeline` / `audit_check` / `audit_preflight` / `audit_badge` / `audit_sampling` / `audit_registry` |
| ⑤ 决策消费层 | 只读收敛 + 缺失暴露 | `00-decision-hub` + 决策支持工具 |

### 3.2 模块边界与依赖约束

- `_common.py` 为**唯一下游**；禁止反向依赖与工具间循环依赖。
- 判定内核单一事实源：新增校验须复用 `compliance_check` / `info_quality_check` / `audit_registry`。
- 工具目录扁平 + `sys.path` 注入机制**保持不变**；跨模块依赖只允许公开接口（方向 F）。

### 3.3 数据流（保持不变）

`reports/*.md → md2html(+report_diff) → html → build_hub → index.html/search-index.json → INDEX.md → archive`；审计链：指纹 → `audit-ledger.jsonl` → `audit-status.json` → 徽章。

## 四、实现逻辑（A–G）

### A 单一事实源强化

1. 引入机器可读注册表（类型 / 工具 / 主题），作为唯一事实源；
2. 文档（`tools/README.md` 清单等）与 CI 步骤由生成器派生；
3. 易变数字（工具数/测试数/类型数/工作流数）改为工具输出或加守卫测试；
4. 新增注册一致性守卫：`template-registry.md ↔ _common.TEMPLATE_TYPE_DIRS ↔ compliance-rules.json`。

**约束**：生成器幂等、输出确定性；不得破坏现有 `validate.py` 与 CI 门禁。
**落点**：Phase 1（守卫）、Phase 3（注册表与生成）。

### B 事务性写

1. 统一 `atomic_write(path, text)`：临时文件 + `os.replace`；
2. 建立「备份 → 写 → 校验 → 回滚」模板；
3. 改造 3 个写回点：`auto_verify`、`build_hub`、`audit_badge`。

**约束**：保留换行风格；失败回滚；保持幂等。
**落点**：Phase 1。

### C 入口安全硬化

1. `workflow_guard --verify-cmd` 改参数数组或命令白名单，移除 `shell=True`；
2. 统一路径 `resolve()` + 仓库根前缀校验。

**约束**：不降低易用性；兼容 Windows/POSIX；不引入网络出口。
**落点**：Phase 1。

### D 性能与规模

1. 变更感知增量生成（按 `git diff` 选择受影响报告）；
2. 构建耗时基准入 CI；
3. 测试分片并行。

**约束**：增量结果与全量等价；基准可复现；并行无共享状态冲突。
**落点**：Phase 0（基线）、Phase 2（POC/对比/分片）、Phase 3（落地）。

### E 工程硬化

1. 引入 `ruff` 并接入 CI（warning 起步）；
2. 引入 `mypy` 并接入 CI（渐进式）；
3. 搭建 E2E 流水线测试骨架（生成→门禁→审计→合并）。

**约束**：渐进式，存量先告警后收紧；E2E 不依赖外网。
**落点**：Phase 2。

### F 私有接口治理

1. 跨模块复用的私有函数改为公开函数；
2. 或显式 `@internal` 标注并集中管理；
3. 梳理私有依赖清单并逐项改造。

**约束**：不改变外部行为与判定结果；公开化同步文档注释。
**落点**：Phase 2。

### G 安全回归

为三类属性补专用断言：① HTML 转义 / `</script>` 逃逸防护（`build_hub`）；② 已审计标识剥离后的内容指纹（`audit_registry`）；③ 路径越界防护（方向 C 落点）。

**约束**：正反例断言；不得弱化现有指纹/转义逻辑。
**落点**：Phase 3。

## 五、边界定义

### 5.1 范围内

- A–G 七个方向对应的基础设施与守卫建设；
- 23 项原子任务（见实施清单）；
- 文档与 CI 的同步更新。

### 5.2 范围外（不做）

- 不新增 A–G 之外的优化内容；
- 不改变五层架构与主数据流；
- 不引入服务端、数据库、前端工程、网络出口；
- 不改写报告研究内容（工具链不产出研究正文）。

### 5.3 遗留观察项

**I-11｜平台差异（CI bash / 本地 PowerShell）** 在原始方案中未映射到任何方向 A–G，不纳入本次实施；登记为遗留观察项，待确认后再立项。

## 六、风险预案

| 风险 | 触发条件 | 预案 |
|---|---|---|
| 原子写改造破坏现有写回语义 | 改造后报告内容/徽章变化 | 保留旧路径回滚开关；单测覆盖写回前后内容比对 |
| 增量生成与全量不等价 | POC 对比发现差异 | 以全量结果为基准；差异未清零不进入 Phase 3 落地 |
| ruff/mypy 存量告警过多 | CI 告警淹没 | warning 起步，不阻断；分批收紧 |
| 守卫测试过严导致误报 | 文档正常变更触发失败 | 守卫只校验易变数字与注册一致性；失败即修文档 |
| 私有接口改造引入循环依赖 | import 图成环 | 改造前绘制依赖清单；`TestProcessReuse` 回归 |
| 安全改造影响本地工作流 | `shell=True` 移除后命令失败 | 保留参数数组默认值；提供白名单入口 |

## 七、验收标准（统一）

每个阶段、每个任务均须满足：

1. 单元测试全量通过（`python -m unittest discover -s src/tests`，退出码 0）；
2. `validate.py` 执行退出码为 **0**；
3. 本阶段新增守卫测试全部通过；
4. 相关文档同步更新（含版本记录）；
5. 合并流程通过 `audit-gate --gate` 校验。
