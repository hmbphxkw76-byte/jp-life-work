# 输入门禁可移植性方案（跨 IDE / 跨模型 / 跨机器）

> 版本：v1.0（2026-11-18）
> 定位：把「输入润色与确认门禁」做成可移植的仓库级规范。
> 单一事实源：`AGENTS.md`「输入润色与确认门禁」节。

## 一、目标

确保门禁在三种场景下都完整生效：

- **跨 IDE**：妙手 / Claude Code / Cursor 等。
- **跨模型**：任意 LLM 一致执行。
- **跨机器**：新电脑 `git clone` + 一条命令即可就绪。

## 二、设计原则

1. **单一事实源（SSOT）**：口径只写在 `AGENTS.md`；其它载体一律指针 / 导入。
2. **配置即代码**：所有 artifact 入 git，随仓库迁移。
3. **机械可判定**：触发规则可机检，不依赖语义推理。
4. **声明式 + 可验证**：bootstrap 声明式部署，check 可验证。
5. **最小惊讶**：默认只读校验；写操作需 `--install` 显式触发。

## 三、载体层（跨 IDE）

| 载体 | 作用 | 读取方 |
|---|---|---|
| `AGENTS.md` | 唯一事实源（门禁完整口径） | 妙手、Claude Code、Cursor（新版）等 |
| `CLAUDE.md` | `@AGENTS.md` 导入 | Claude Code |
| `.cursorrules` | 指针 | Cursor |

原则：**指针不复制**，避免口径漂移。

## 四、判定层（跨模型）

- 短祈使句 + 明确清单，置于 `AGENTS.md` 前部。
- 触发 = 「要求执行动作」；不触发 = 穷举五项（纯提问 / 确认 / 补充 / 闲聊 / 句末问号）。
- 两项均可机检，任意模型一致执行。

## 五、迁移层（跨机器）

新机器步骤：

1. `git clone <repo>`
2. `python engine/scripts/bootstrap_gate.py --install`
3. 脚本补齐 / 校验载体 → 运行 `check_gate` 自检 → 输出就绪报告。

可选：`--personal` 把工作区 skill 部署到 `~/.meituan-catpaw/<uid>/skills/`（跨项目可用）。

## 六、验证层

`python engine/scripts/check_gate.py`：

- 校验 `AGENTS.md` 含门禁节与机械判定口径；
- 校验 `CLAUDE.md` 导入、`.cursorrules` 指针、工作区 skill、设计文档；
- 退出码 0 / 1，可接 CI。
