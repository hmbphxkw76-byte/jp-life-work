# 引擎层迁移方案（SRC→ENGINE）

> **版本**：v1.0（2026-11-17）
> **定位**：jp-life-work 仓库「`src/` → `engine/` 完整迁移 + 根 `tools/` 职责归位」的**统一落地方案**与执行依据。
> **基线**：`origin/main` = `6680434`（含分支命名合并 `2a633d2`）；跟踪文件中 **250 个**含 `src/` 引用；8 条工作流、34 个工具、13 类型、21 主题。
> **性质**：**纯目录 / 路径 / 命名迁移，零行为变更**（本仓库无长驻服务，无停机窗口）。
> **上位依据**：[AGENTS.md](../../AGENTS.md)、[CI 与自动化体系](CI.md)、[工具链开发规约](toolchain/TOOLCHAIN-DEV-SPEC.md)、[架构优化技术方案-2026-11-16](架构优化技术方案-2026-11-16.md)。
> **执行提示词**：见附录 A（交付执行 Agent 使用）。

## 0. 决策点

| 项 | 建议 | 备选 |

## 2. `tools/` 职责重叠梳理与归位

### 2.1 现状（两个 tools）

| 维度 | 根 `tools/` | `src/prompts-tools/tools/` |
|---|---|---|
| 文件 | workflow_guard / git_push / cleanup_workspace / run_tests_parallel / branch_naming / git-hooks / README | 34 工具 + `_common.py` + registry.json + coverage-config.json + README |
| 职责 | git 协作 / 合并 / 推送 failover / 工作区清理 / 测试分片 / 分支命名 | 报告生产 / 校验 / 审计 / 编排 / 决策支持 |
| 是否产出内容 | 否 | 是（HTML / 索引 / 审计产物） |
| 是否做 git 可变操作 | 是（受三层隔离约束） | 否 |

**重叠 / 交叉点**：

- 命名重叠：两目录同名 `tools`，文档、配置、命令频繁混用；
- 覆盖重叠：`.coveragerc` source 同时含两者；`TOOLCHAIN-DEV-SPEC` 适用范围同时含两者；
- 引用交叉：`tools/README.md` → `src/tests/...`；工具链 README 的合并前检查单 → `tools/cleanup_workspace.py`；`workflow_guard` → `src/prompts-tools/tools/validate.py`；CI action → `tools/cleanup_workspace.py`；
- 功能相邻：`run_tests_parallel`（根）与 CI unittest 步骤；`cleanup_workspace`（根）与 `validate.yml` 的 workspace-hygiene job。

### 2.2 归位方案

| 目录 | 职责 | 禁止 |
|---|---|---|
| `engine/tools/` | 报告生产 / 校验 / 审计 / 编排（产出内容） | 不做 git 可变操作 |
| `engine/scripts/` | git 协作 / 合并 / 推送 failover / 工作区清理 / 测试分片 / 分支命名 | 不产出内容、不校验报告 |

结果：全仓**只有一处 `tools/`**（`engine/tools`），协作脚本统一 `scripts/`，消除「两个 tools」。

### 3.2 字符串替换顺序（长 → 短，防误替）

1. `src/prompts-tools/tools/` → `engine/tools/`
2. `src/report_templates/` → `engine/report_templates/`
3. `src/report-audits/` → `engine/report-audits/`

8. 代码常量 `ROOT / "src"` → `ROOT / "engine"`；`SKIP_TOP` 成员 `"src"` → `"engine"`

### 3.3 深度推导修正（最易漏、最危险）

目录层数变化会让 `Path(__file__).parents[N]` 静默跑偏：

| 文件 | 现状 | 迁移后 |
|---|---|---|
| `engine/tools/_common.py` | `parents[3]` | **`parents[2]`** |
| `engine/tools/coverage_gate.py` / `generate_registry.py` / `review_gate.py` | `parents[3]` | **`parents[2]`** |
| `engine/tools/migrate_monthly_reports.py` | `parents[2]/"report-audits"` | **`parents[1]/"report-audits"`** |
| `engine/tests/*.py`（全部） | `parents[2]` | `parents[2]`（层数不变） |
| `engine/tests/test_tools.py:24` | `parents[1]/"prompts-tools"/"tools"` | **`parents[1]/"tools"`** |
| `engine/tests/test_cov_audit.py:117`、`test_tools.py:1019/1153/2217` | `parents[3]` | **`parents[2]`** |
| `engine/scripts/cleanup_workspace.py` | `parent.parent` | **`parents[2]`** |
| `engine/scripts/run_tests_parallel.py` | `parents[1]` | **`parents[2]`** |
| `engine/scripts/workflow_guard.py` | git rev-parse（稳健） | 不变；但 `_find_push_script` 的 `cwd/"tools"/"git_push.py"` → `cwd/"engine"/"scripts"/"git_push.py"`；`_run_verify` 默认路径 → `wt/"engine"/"tools"/"validate.py"` |
| `engine/vocabulary/script/*.py` | `parent.parent`（=vocabulary/） | 不变 |

### 3.4 关键常量 / 正则 / 配置

- `_common.SRC` → `ENGINE`（`ROOT/"engine"`）；`TEMPLATE_ROOT`、`PIPELINE_DIR` 同步。
- `_common.SKIP_TOP`：删 `"src"`、加 `"engine"`——**漏了会把 `engine/vocabulary`（含 `data/`）误判成业务线**。
- `_common.TYPE_RE`：`src/report_templates/` → `engine/report_templates/`（business-config 类型识别）。
- 各工具 `AUDIT_DIR` / `IQ_CACHE` / `RULES_DIR` / `SEARCH_DIR` / `VOCAB_DATA` / `OUT_PATH` / `SNAPSHOT` / `TOPIC_REGISTRY` 等 `ROOT/"src"/...` 常量。
- `coverage-config.json`（`test_discovery`、`baseline`）、`.coveragerc`（source / omit）、`ruff.toml`（`"src/tests/*"`）、`.gitignore`（4 条）、`validate.yml`（ruff `check src tools`、mypy 路径）。

### 3.5 不改动项（历史留痕，避免过度替换）

- 审计台账 `audit-ledger.jsonl` 等历史文本中的旧路径：保留。
- 报告正文 / HTML 内已写死的「验证日志：`src/report-audits/...`」：按「零行为变更」**不追改**（如确需修改须单独确认）。
- git 历史：`git mv` 保留，不重写。

## 8. 灰度切换 / 双路径兼容 / 回滚

### 8.1 灰度切换
三阶段放行：① 引擎内部迁移（不影响内容层）→ ② CI / 配置切换（门禁把关）→ ③ 文档 / 提示词切换。每阶段以「全量测试 + `validate.py`」为出口；合并后以 CI 三作业 + 下一维护周期为观察期。

### 8.2 双路径兼容（限时过渡）
- `engine/tools/_common.py` 增加布局探测：`engine/tools` 与旧 `src/prompts-tools/tools` 两种布局都能解析出 `ROOT` 与引擎目录（`ROOT/"engine" if exists else ROOT/"src"`，回退时打印 DEPRECATED 警告）。
- `engine/scripts/workflow_guard.py` 的 `_find_push_script` / `_run_verify` 同步双路径。
- 目的：合并落地前后仍在旧布局上的任务分支 / 克隆可继续运行，避免「一刀切」导致他会话中断。
- **退出条件**：所有任务分支已合并或 rebase + 活引用清零 + CI 连续一个维护周期全绿 → 移除回退分支与对应守卫。

### 8.3 回滚预案
迁移为纯路径替换，合并提交是单一可 revert 单元：异常时 `git revert <merge-sha>`（经 `lock run`）整体回退，无数据丢失。合并冲突时 `merge` 保留 `.worktrees/_merge`，人工处理后重试，远端零污染。

---

## 9. 异常回滚触发条件

1. 全量 unittest 失败或测试数异常减少（非预期）；
2. `validate.py` 退出码 1，或 audit-gate / html-sync / info-quality 任一阻断；
3. `iter_business_dirs()` 主题数 ≠ 21，或 `engine/vocabulary` 被误判为业务线；
4. `ROOT` 解析异常（深度推导漏改）；
5. 生成物与迁移前不一致（非路径文本 / 时间戳差异）；
6. CI 连续 2 次失败或覆盖率跌破阈值；
7. 合并后 24h 内出现 `src/` 活引用回潮（他会话误改）。
