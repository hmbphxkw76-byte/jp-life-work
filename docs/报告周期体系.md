# 报告周期体系（REPORT-CYCLE-SPEC）

> **版本**：v1.2（2026-11-24）
> **定位**：jp-life-work 报告周期的**单一事实源**。定义月 / 季 / 年三档的保留与展示窗口、周期归属识别、环比更新高亮与基准迁移规则。
> **落地**：`engine/tools/report_cycles.py`（纯函数）+ `engine/vocabulary/config/report-cycles.json`（可扩展配置）；消费方 `build_hub.py` / `build_index.py` / `archive_reports.py` / `md2html.py`。
> **上位依据**：`AGENTS.md`（会话硬性规约）、[信息生产全链路执行规范](信息生产全链路执行规范.md)、[审计报告标准化管理体系](审计报告标准化管理体系.md)。

---

## 一、周期定义与窗口

| 周期 | 保留（keep） | 默认展示（default） | 交互 |
|---|---|---|---|
| 月度 | 近 **18** 个自然月 | 近 **6** 个自然月 | 超 6 个月折叠进「更多」，点击完整展开至 18；超 18 个月移入 `reports/archives/` |
| 季度 | 近 **24** 个自然月 | 近 **24** 个自然月（8 期） | 完整展示，按季度末月归档（如 2026-Q4 → 2026-12） |
| 年度 | 近 **60** 个自然月 | 近 **60** 个自然月（5 份） | 完整展示，按自然年归档（12 月） |

- 窗口按**当前日期滚动计算**（近 N 个自然月），与展示、归档同源。
- `default == keep` 时完整展示，不折叠。
- 报告统一命名 `YYYY-MM-<主题slug>`；季度 / 年度报告按末月归档，与月度报告同一套命名 / 对比 / 展示逻辑。

## 二、周期归属（自动识别，可扩展）

周期归属**不改 business-config 结构**，由 `report_cycles.detect_cycle_in()` 读取既有内容自动判定，优先级从高到低：

| 优先级 | 判定依据 | 主周期 |
|---|---|---|
| 1 | `prompts/prompt-annual-refresh.md` | annual |
| 2 | `prompts/prompt-quarterly-analysis.md` | quarterly |
| 3 | `prompts/prompt-annual-review.md` | annual |
| 4 | `prompts/prompt-policy-review.md`（事件触发 + 年度台账） | annual |
| 5 | `prompts/prompt-monthly-monitor.md` / `prompt-update.md` | monthly |
| 6 | business-config 文本含「季度」/「年度」 | quarterly / annual |
| 7 | 兜底 | monthly |

**当前 21 主题映射**（2026-11-18 实测）：

| 主题 | 主周期 | 保留 | 默认展示 | 依据 |
|---|---|---|---|---|
| 00-decision-hub | 季度 | 24 | 24 | business-config `{{CADENCE}}` = 季 |
| 01 / 02 / 03 / 07 / 10 / 11 / 12 / 14 / 15 | 月度 | 18 | 6 | `prompt-update.md` |
| 04 / 05 / 06 | 年度 | 60 | 60 | `prompt-annual-refresh.md` |

**扩展**：在 `engine/vocabulary/config/report-cycles.json` 的 `overrides` 按主题目录名覆盖（如 `"13-regional-info": {"primary": "monthly"}`）；新增周期只需在 `policy` 追加一项，无需改代码。

## 三、环比更新与高亮

- 每期报告在**上一期（同主题、最近一个更早自然月）**基础上比对（`report_diff.py` block 级 diff）。
- 报告页（`md2html.py`）写入机器可读 meta：
  - `<meta name="report-period" content="YYYY-MM">`
  - `<meta name="report-cycle" content="月度 | 季度 | 年度">`
  - `<meta name="report-diff" content="prev=…;new=…;mod=…;del=…">`
- 汇总页（`build_hub.py`）据此高亮：
  - 有更新：绿色「已更新」+ `较上期 YYYY-MM：新增 X / 修改 Y / 删除 Z`；
  - 无更新：灰色「无更新」，内容保持不变；
  - 最新一期：绿色「新」标识。
- **无更新不虚构变化**：内容与上期一致时保持原样，不重写。

## 四、基准与迁移

| 项 | 口径 |
|---|---|
| 当前基准月 | **2026-11**（所有月报以此为基础做环比） |
| 下一期基准 | **2027-01** 起以 **2026-12** 为环比基准 |
| 切换方式 | 由 `report-cycles.json` 的 `baseline_period` / `next_baseline_period` 声明；报告页与汇总页按实际报告期自动取上一期 |

## 五、展示与归档落地

| 环节 | 工具 | 行为 |
|---|---|---|
| 汇总页 | `build_hub.py` | 详情页按 `data-cycle` / `data-default-months` / `data-keep-months` 动态过滤；月报默认 6、「更多」展开 18；季报 24；年报 60 |
| 全局索引 | `build_index.py` | `INDEX.md` 增列「周期」，按周期标注 |

| 报告页 | `md2html.py` | 预渲染跨期 diff 高亮 + meta |

## 七、第二期触发机制（N17，2026-11-19）

「第二期」指同一主题在**首个报告期之后**产出的下一期报告（如 2026-11 → 2026-12）。当前全库仅有 2026-11 一期数据，故**第二期触发次数 = 0**。

### 7.1 触发条件（机制已就绪）

| 触发面 | 条件 | 机制 / 工具 |
|---|---|---|
| 时间触发 | 进入新的自然月（月度主题）/ 季度末月（季度）/ 年度末（年度） | `report_cycles.py` 窗口滚动；`.github/workflows/scheduled-report-tasks.yml` |
| 数据触发 | 官方统计 / 制度有新发布或口径变化 | 各主题 `prompts/prompt-update.md` / `prompt-policy-review.md` |
| 事件触发 | 政策 / 考试 / 签证 / 汇率等事件命中 | `engine/tools/trigger_watch.py`；主题 `prompt-policy-review.md` |
| 人工触发 | 月度维护窗口手动「本月报告全量更新」 | `docs/月度批量更新唤醒词.md` |

### 7.2 当前 0 触发原因（不虚构）

- 全库报告基线为 **2026-11**（见 §四），**尚无 2026-12 及以后报告**，因此「第二期」在时间上尚未到达。
- `decision_metrics` 五问判定率 0% / 缺失 16 条的根因同样是**只有一期数据**，无法做跨期收敛（2026-11-19 实测：收敛率 21% / 五问判定率 0% / 缺失 16）。
- 机制侧已就绪：`report_cycles.py` 窗口 / 归档 / diff 高亮、`scheduled-report-tasks.yml` 调度、`trigger_watch.py` 事件监测均可在第二期到达时自动或半自动触发；**无需新增代码即可触发**。

### 7.3 验证口径

- 第二期报告产出后，`report_diff.py` 应能取到「上一期」并生成 diff；`build_hub.py` 应显示「较上期 YYYY-MM：新增 X / 修改 Y / 删除 Z」。
- 若第二期无实质更新，按 §三「无更新不虚构变化」保持原样并标「无更新」。

### 7.4 2026-12 期触发时点与就绪度（2026-11-24）

| 项 | 状态 |
|---|---|
| 时间窗口 | 进入 **2026-12** 自然月即满足「时间触发」；月度主题按当前日期滚动窗口（保留 18 月 / 默认展示 6 月） |
| 机制 | **已就绪**：`report_cycles.py` 窗口与归档、`scheduled-report-tasks.yml` 调度、`trigger_watch.py` 事件监测、`report_diff.py` 环比 diff |
| 数据前置 | 需 2026-12 官方统计 / 制度更新到位（厚労省毎月勤労統計、ISA 認定送出機関名单、日銀 SPPI 等各有发布节奏）；**未发布的指标沿用上一版并显式标注时点**，不虚构新值 |
| 决策前置 | 五问判定仍待个人参数（PF-01 / 02 / 11 / 13 / 16）；未输入前 `decision_metrics` 的跨期收敛无法计算（保持 0% 并说明原因，不虚报） |
| 触发入口 | ① 自动：`scheduled-report-tasks.yml` + `trigger_watch.py`；② 人工：「本月报告全量更新」（见 [月度批量更新唤醒词](月度批量更新唤醒词.md)） |
| 产出后校验 | `md2html` → `lint_reports` → `auto_verify` → `audit_preflight` → `audit_check` → `audit_pipeline --submit` |

> 结论：**机制无需新增代码即可触发**；当前未触发的原因是时间未到 + 部分数据/决策前置未齐，属预期。
