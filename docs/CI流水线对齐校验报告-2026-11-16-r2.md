**隐性执行分支 / 边缘触发**（逐条核对，无遗漏）：

1. `audit-gate.yml` 的 `--gate` 参数三分支：PR → `git diff origin/<base_ref>...HEAD`；push 且 `before` 非空 → `git diff <before> <sha>`；push 且 `before` 为空（新分支 / 首推）→ `--strict` 全库。
2. `audit_pipeline._changed_report_paths` 仅保留 `*/reports/*.md`：HTML-only / 非报告变更不触发审计门禁（与审计标准十「受检报告」口径一致）。
3. `validate.yml` 的退出码判定逐项显式化：`validate` / `classify` / `ensure` / `stage_gate` / `info_quality` / `fact_card` / `pending_verification` 允许 `{0,2}`；`lint` / `compliance` 允许 `{0,2}`；`finance` 仅允许 `0`；词库 `topic-check` / `verify` 允许 `{0,2}`、`sync check` 仅允许 `0`；其余非零（含 127 命令异常）一律阻断。
4. `info-quality.yml` 的 `--apply` 步骤**不**因退出码 1 直接失败，而是捕获后继续跑 md2html / unittest，再由后续「P0/P1 告警」步骤统一失败——保证失败路径仍产出三清单。
5. `audit-sampling.yml` 命中门槛未达标时 `exit 1`，后续 `audit_badge --sync` / `record` / 提交均 `if: always()`，保证不合格处置（置 `stale` + 撤销标识）落盘。
6. 提交 / 推送类步骤一律排在收尾清理（`if: always()`）之前；7 条工作流均接入「阶段前置（checkout + setup-python 后）+ 阶段收尾」清理。`workspace-hygiene` 自检 job 为唯一例外（其自身即清理链路验证）。
7. cron 均为 UTC：`00:15` / `00:20` / `00:25` / 周一 `02:20`，与规范五「周期 / 触发」列一致。
