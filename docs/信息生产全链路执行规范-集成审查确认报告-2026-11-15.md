## 四、核心执行逻辑符合性

### 4.1 状态机分支与跳转（规范 2.4 / 四 / 七）

实现：`audit_pipeline.py::TRANSITIONS`（L62–75）。设计状态机逐条一致：

| 当前状态 | 事件 | 目标状态 | 一致性 |
|---|---|---|---|
| （无） | register | registered | ✅ |
| registered / rejected / stale | submit | pending_initial | ✅ |
| pending_initial | stage_pass / stage_fail | pending_re_review / rejected | ✅ |
| pending_re_review | stage_pass / stage_fail | pending_final / rejected | ✅ |
| pending_final | stage_pass / stage_fail | audited / rejected | ✅ |
| audited | revoke | stale | ✅ |
| stale | rebind | audited | ✅ |

- 环节与角色绑定：`initial→reviewer_l1`、`re_review→reviewer_l2`、`final→audit_chair`（L57–59），与《审计报告标准化管理体系》一致。
- 审计编号：`AUD-YYYYMM-NNN` 自动生成、唯一性校验（L264–270、L430）。

### 4.2 门禁分支判断与拦截条件

- `cmd_gate`（L639–693）拦截条件与设计一致：① 台账哈希链断裂/篡改；② 登记册与实际文件不一致；③ 「已审计」标识与状态不一致；④ 受检报告未 `audited` / 指纹失配 / 缺有效 L5 证据。任一即退出码 1。
- 增量/严格双模式：`--strict` 全库、`--changed` 变更清单、缺省 `origin/main...HEAD`（L584–611），与 `audit-gate.yml` 的 PR/push 分支逻辑一致。
- 阶段闸拦截：存在 P0/P1 → 退出码 1；仅 P2 → 2（`stage_gate_check.py` L221–223）。

### 4.3 异常处理

| 异常场景 | 处理实现 | 位置 |
|---|---|---|

| 无变更的周期工作流 | `git diff --cached --quiet` → 跳过提交 | html-sync L59–66；maintenance L97–101 |
| 终审缺 HTML 交付物 | 拒绝终审通过 | `cmd_review` L366–368 |
| L5 证据无效 | 拒绝 re_review 通过并列出问题 | `validate_l5_evidence` L96–137 |
| 工具读取损坏 JSON | 捕获 `JSONDecodeError` 回退/返回空 | `audit_badge._load_status` L43–55 等 |
