# 全链路信息处理体系梳理（InfoPipeline）

> **版本**：v1.0（2026-11-15）
> **适用范围**：jp-life-work 全部主题（`00`–`20`，其中 `00` 为跨主题决策层）
> **上位依据**：[信息质量评估提示词体系](信息质量评估提示词体系.md)、[审计报告标准化管理体系](审计报告标准化管理体系.md)、[CI 与自动化体系](CI.md)
> **程序化实现**：`src/prompts-tools/tools/`（26 个工具脚本，含 `_common` 公共模块）、`.github/workflows/`（7 条工作流）、`src/tests/`（契约测试）
> **定位**：把「信息采集 → 信息筛选 → 信息分类 → 内容生成 → 报告输出」的全链路节点，与每个节点对应的质量保障流水线，收敛为一份可核对、可复用的总览文档。

---

## 一、体系总览

整个体系由**五层**构成，统一语言为退出码 `0 = 通过 / 1 = 错误（阻断）/ 2 = 警告（放行）`：

| 层 | 载体 | 职责 |
|---|---|---|
| ① 研究生产层 | 提示词四层继承（通用基座 × 通用规范 × 类型模板 × 业务配置）+ 指标登记册 + 词库 | 把原始信息加工为有来源、有口径、有结论的研究正文 |
| ② 生成同步层 | `md2html.py` / `report_diff.py` / `build_hub.py` / `build_index.py` / `archive_reports.py` | 把 md 源稿转为自包含 HTML、索引与检索层，滚动归档 |
| ③ 质量门禁层 | `validate.yml` + `audit-gate.yml`（阻断式）+ 本地工具链 | 规范类、审计类双门禁，P0/P1 一律阻断 |
| ④ 审计闭环层 | AuditGuard L1–L5 + 状态机 + 哈希链台账 + 已审计标识 | 全量纳入、多级校验、全程留痕、内容防篡改、定期抽检 |
| ⑤ 决策消费层 | `00-decision-hub` 决策支持件套 + 五问视图 + 缺失清单 | 只读消费各主题结论，收敛为决策答案并暴露缺失 |

```mermaid
flowchart LR
    A["阶段1 信息采集<br/>提示词 · 登记册 · 触发器"] --> B["阶段2 信息筛选<br/>来源分级 · 时效 · 冲突并列"]
    B --> C["阶段3 信息分类<br/>六族十三类 · 命名归位"]
    C --> D["阶段4 内容生成<br/>四层继承 · 登记册回写"]
    D --> E["阶段5 报告输出<br/>md→HTML→索引→归档"]
    E --> F["质量门禁<br/>validate.yml + audit-gate.yml"]
    F -->|P0/P1 阻断退回| D
    F -->|通过| G["周期保障<br/>html-sync · maintenance · info-quality · sampling"]
    G --> H["决策消费<br/>00 五问收敛 + 缺失暴露"]
    H -->|触发补缺| A
```

## 二、全流程节点拆解（五阶段）

### 2.1 阶段一 · 信息采集

| 项 | 内容 |
|---|---|
| **输入** | 业务配置 `prompts/business-config.md`（来源优先级、语言规则、追踪表、触发器清单）；指标登记册 `data/*_indicator_registry.md`；上期报告与基线报告；周期提示词 |
| **核心步骤** | ① 前置检查（`validate.py` / `lint_reports.py`，并人工确认基线存在、上期路径、提示词继承声明）；② 完整继承上期「已修正事实清单」防回退；③ 从登记册读取活值；④ 按追踪表逐项采集，每个数字记录「**机构 · 统计周期 · 发布日期 · 核验状态**」四元组；⑤ 触发器判定——无触发且窗口未到则不启动，不得虚构变化 |
| **输出标准** | 带四元组的原始事实集 + 待复核清单；T+1 刷新须显式标注「核验、口径澄清与阈值距离」 |
| **依赖工具** | `update_planner.py`（月度任务清单）、`scheduled-report-tasks.yml`（月度 Issue 提醒）、`operations-guide.md`（人工/Agent 执行手册）、外部检索 |
| **采集纪律** | 来源分级 ① 官方一手 > ② 国际权威 / 行业机构 > ③ 门户抽样 > ④ 媒体转述（仅线索，标「需核实原文」）；`{{SOURCE_LANGUAGE_RULE}}` 强制（日文官方一手 + 英文权威优先，中文来源仅作线索）；时效近 12 个月优先、超 24 个月须标注年份并谨慎使用 |

### 2.2 阶段二 · 信息筛选

| 项 | 内容 |
|---|---|
| **输入** | 阶段一的原始事实集 |
| **核心步骤** | ① 按业务配置来源优先级采信，冲突时并列双份并标注来源与年份，**不合并、不取均值**；② 时效过滤（`{{FRESHNESS_PRIORITY}}`：最新官方页 > 上期值 > 预测值）；③ 核验状态分级标注（已核验 / 部分核验 / 待核实 / 需核实原文）；④ 口径冲突进入「口径冲突并列清单」；⑤ 无法核实项单列「待复核清单」，缺失事实标「⚠ 缺失」，不补值、不外推 |
| **输出标准** | 可采信事实集（每条附来源 + 核验状态）+ 待复核清单 + 口径冲突清单 |
| **依赖工具 / 规则** | 通用基座 §3 / §4、business-config §4 / §5 / §10、`confidence-grade-standard.md`（来源 × 时效 × 核验三维分级）、`pending_verification.py`（首轮核验截止 2026-12-31） |
| **阈值** | 事实单元来源标注覆盖率程序化门槛 **≥ 20%**（低于为 C-07 P2 提示，语义目标 100%）；④ / ⑤ 级来源缺核验标注 = C-14（P1） |

### 2.3 阶段三 · 信息分类

| 项 | 内容 |
|---|---|
| **输入** | 筛选后事实集 + 主题定位 |
| **核心步骤** | ① 报告类型选型（[report-classification](../src/report_templates/report-classification.md) 六族十三类，一票判别表 + 判别五问）；② 类型模板继承（[template-registry](../src/report_templates/template-registry.md) 13 个已注册类型，各含基线 + 周期模板）；③ 结构骨架匹配（[compliance-rules.json](../src/report_templates/compliance-rules.json)，12 类 × 周期的 h2 节数 / 节名 / 导航要求）；④ 命名与归位——统一 `YYYY-MM-<slug>.md` + `.html`（slug = 主题目录名去 `NN-` 前缀），季度按季度末月归档（`2026-Q4` → `2026-12`） |
| **输出标准** | 归档位置正确、结构骨架合规、命名可被标准正则识别、md / html 成对 |
| **依赖工具** | `classify_reports.py`（错位报告自动归位）、`ensure_region_topics.py`（结构补全，幂等）、`validate.py`（命名 / slug 归属 / 配对校验） |

### 2.4 阶段四 · 内容生成

| 项 | 内容 |
|---|---|
| **输入** | 类型骨架 + 可采信事实集 + 登记册活值 |
| **核心步骤** | ① **四层提示词继承**：业务提示词 = [通用基座](../src/report_templates/prompt-generic-base.md) × [通用规范](../src/report_templates/monitoring-common-spec.md) × 类型模板 × 业务配置（冲突优先级：业务提示词 > 业务配置 > 类型模板 > 通用基座 > 通用规范）；② 读登记册活值（prompt 内严禁硬编码活值）；③ 写正文——事实 / 推断分离，自算值标「自算」、预测值标「预测值（F）」，关键结论具备「事实 → 推理 → 结论」链并附来源；④ **回写登记册**（增量留痕，不覆盖历史值）+ 生成「数据变更摘要」「已修正事实清单」；⑤ 落盘前执行**三步自检**：`audit_preflight.py --report` → `audit_check.py --report` → `audit_pipeline.py --submit` |
| **输出标准** | 报告 md 源稿 + 登记册回写 + 变更摘要；P0 / P1 = 0 |
| **依赖工具** | `skeleton_builder.py`（骨架 / 空模块合并 / 边界声明集中）、`sync_vocab.py`（词库 → business-config 标记区间自动同步）、`audit_preflight.py` / `audit_check.py` / `audit_pipeline.py` |

### 2.5 阶段五 · 报告输出

| 项 | 内容 |
|---|---|
| **输入** | 报告 md 源稿 |
| **核心步骤** | ① `md2html.py` 生成自包含 HTML（navy 设计令牌、skip-link、report-nav、页脚），构建期预渲染**跨月对比高亮**（`report_diff.py`，新增绿 / 修改黄 / 删除折叠，修改相似度阈值 0.35）；② `build_hub.py` 重建 `index.html`（主题卡片 + 详情页，默认最近 12 个自然月窗口、倒序）与 `search-index.json`（问题 → 报告、关键词、五问视图）；③ `build_index.py` 生成 `INDEX.md`；④ `archive_reports.py` 滚动归档（每主题保留最新 **12** 期，超出移入 `reports/archives/`）；⑤ 提交推送 |
| **输出标准** | md / HTML 双格式成对；索引与汇总页为最新（`build_hub.py --check` 逐字节比对）；无旧命名残留 |
| **依赖工具 / 流水线** | `md2html.py`、`report_diff.py`、`build_hub.py`、`build_index.py`、`archive_reports.py`、`html-sync.yml`、`scheduled-maintenance.yml` |

## 三、流水线保障机制

### 3.1 `validate.yml` — 规范门禁（阻断式，push main / PR）

| 步骤 | 规则与阈值 | 拦截逻辑 |
|---|---|---|
| 契约测试 | `python -m unittest discover -s src/tests` | 退出码 1 阻断；`fetch-depth: 0` 保证迁移内容复核可取旧文件 |
| `validate.py` | 通用层共享文件齐全；类型模板必备文件齐全；通用层无业务关键词；业务目录结构；命名 `YYYY-MM-<slug>` + slug 归属 + md / html 配对 | 1 阻断，2 放行 |
| `classify_reports.py --check --unknown-warn` | 错位报告必须可自动归位 | 1 阻断；2（归属不明）放行 |
| `ensure_region_topics.py --check` | 结构补全 | 1 阻断 |
| `build_hub.py --check` | 汇总页过期退出码 1 | 1 阻断；缺失 WARN 放行 |
| `lint_reports.py --new-only` | thead / tbody / table 配对、无畸形 `<th scope="col"ead>`（**错误**）；列宽 / `class="fixed"` / img alt（警告） | 新报告（≥ 2026-11）1 阻断；历史报告跳过，遗留入 `lint-whitelist.json` 豁免（逾期恢复阻断） |
| `compliance_check.py --new-only` | h2 节数少于骨架 = 错误、编号 `id="sN"` 不连续 = 错误、缺 `<title>` / 导航 / 断头锚点 = 错误；超节数 = 警告 | 新报告 1 阻断 |
| `info_quality_check.py --check` | 四维度程序化门槛（见 3.5） | 1 阻断（P0 / P1 遗留） |
| `fact_card_check.py` | 事实卡片五字段 + `[@FC-NNN]` 指针 + 跨报告事实重复率 | 1 阻断 |
| `pending_verification.py --check` | 未登记或已逾期首轮核验项 | 1 阻断；临近截止（2）放行 |
| `personal_finance_model.py --check` | 读 01 / 07 / 14 / 10 / 17 登记册活值，算净储蓄率 / 回本周期 | 非 0 阻断（须重跑并提交） |

### 3.2 `html-sync.yml` — 生成物同步（push 触发）

`md2html.py`（含跨月对比）→ `build_hub.py`（索引 + 检索层）→ 提交推送（无变更跳过）。触发条件覆盖报告 md、`build_hub.py`、`md2html.py`、`report_diff.py`、`topics.json`、`template-registry.md`、词库 `terms.md`、`src/search/**` 变更。

### 3.3 `scheduled-maintenance.yml` — 每月定时维护（每月 1 日 00:15 UTC = 09:15 JST）

归位（`classify --apply`）→ 补全（`ensure_region_topics`）→ 归档（保留 12 期）→ 索引（`build_index`）→ HTML 同步 → 汇总页 → **回归 unittest** → 提交。全部幂等。

### 3.4 `scheduled-report-tasks.yml` — 月度产出提醒（每月 1 日 00:20 UTC）

`update_planner.py --period` 生成清单 → `gh issue create`（先按标题查重，命中则 `edit`）。**只提醒、不写内容**。

### 3.5 `info-quality.yml` — 信息质量周期评估（每周一 02:20 UTC = 11:20 JST）

`info_quality_check.py --apply`：全量评估 → 混乱识别分类 → 自动修复 → 复评验证；随后 `md2html.py` + 契约测试 + 提交三清单（评估台账 / 修复台账 / 验证报告，落 `src/report-audits/info-quality/`）。退出码 1 时 `::error::` 告警需人工介入。

**四维度与量化门槛**（程序化常量已与源码核对）：

| 维度 | 程序化门槛 | 语义类目标（人工 / LLM） |
|---|---|---|
| 完整性 | 必需要素覆盖率 ≥ **95%**（`THRESH_REQUIRED_COVERAGE`）；报告必备结构（结论摘要 / 来源章节 / 免责声明）齐全；空模块占比 ≤ 20%（`THRESH_EMPTY_MODULE`） | 结构完整率 = 100% |
| 准确性 | 事实单元来源标注覆盖率 ≥ **20%**（`THRESH_SOURCE_COVERAGE`，低于为 C-07 P2）；④ / ⑤ 级来源强制核验标注（C-14）；时效读登记册字段化日期，超 **12 个月** → C-08 P2 | 关键信息溯源 100%、时效合格 ≥ 90%、表述一致 ≥ 95%、可验证 ≥ 85% |
| 关联性 | 重复冗余率 ≤ **10%**（`THRESH_DUP_RATIO`）；跨文档重复按归一化相似度 ≥ **80%**（实质段落 ≥ 40 字）；交叉引用有效率 = **100%**（`THRESH_CITE_VALID`）；报告 slug 归属 = 100%；跨报告事实重复率 ≤ 10%（`THRESH_FACT_DUP`） | 术语一致 ≥ 98% |
| 一致性 | 同文档重复标题（C-02）、h2 中文序号跳号（C-04 ≤ 1 处 / 文档）、登记册同名指标口径冲突（C-10）、报告 ↔ 登记册数值一致性（C-13，首期覆盖 `01-ssw-driver`） | 逻辑矛盾 = 0、口径冲突 = 0 |

**自动修复范围**：S-02 同文档去重、S-05 免责声明插入 / 占位骨架、S-08 失效相对引用重指；S-01 / S-03 / S-04 / S-06 / S-07 / S-09 / S-10 / S-11 需人工 / 语义复核。修复最大返工 **2 轮**，仍不达标列入人工裁决清单。

### 3.6 `audit-gate.yml` — 审计门禁（阻断式，push main / PR）

**统一入口 `audit_pipeline.py --gate`**（PR 用 `--changed`、push 用 diff，无 before 时 `--strict` 全库），一次覆盖四类检查：

1. **台账哈希链**：`audit-ledger.jsonl` append-only 事件流，`hash = sha256(prev_hash + 规范化事件体)`，重算全链，篡改即断裂；
2. **登记册双向一致**：`audit_registry.py --check`（自动发现，无遗漏 / 无多余 / 指纹匹配）；
3. **已审计标识一致**：`audited ⟺ 标识存在` 且内容指纹（md SHA-256）匹配，失效必撤销；
4. **受检报告审计状态**：须 `audited` + md / HTML 指纹匹配 + **有效 L5 证据**（缺失即 `L5-EVIDENCE` P1 阻断）。

随后 `audit_check.py --all` 执行 **L1–L5**：

| 层 | 内容 | 判定来源 |
|---|---|---|
| L1 结构 | 命名 / 配对 / HTML 骨架 / lint | `validate` + `compliance_check` + `lint_reports` |
| L2 要素 | E1–E8 必需要素（标题、版本 + 基准日、免责声明、摘要、正文骨架、来源章节、来源标注、后续动作） | `info_quality_check` C-05 / C-06 |
| L3 溯源 | 来源章节、来源覆盖率、失效引用、URL 形态 | C-07 / C-09 / C-14 |
| L4 一致性 | 跨文档重复、口径冲突、数值继承、绝对化表述 | C-02 / C-03 / C-10 / C-13 |
| L5 语义 | 结论-依据匹配、表述一致、时效、以偏概全、口径并列、跨主题引用（六项固定码 `结 / 表 / 关 / 是 / 口 / 跨`） | 人工 / LLM，输出 JSON 证据写入台账 |

**流程状态机**：`registered → pending_initial →（初审）→ pending_re_review →（复核 + L5 证据）→ pending_final →（终审）→ audited`；任一环节 fail → `rejected`；内容变更指纹失配 → `stale` 并自动撤销标识。初审与复核须独立主体，终审由 `audit_chair` 签批。

### 3.7 `audit-sampling.yml` — 月度分层抽检（每月 1 日 00:25 UTC = 09:25 JST）

分层抽样（每主题 ≥ 1 份、总数 ≥ **20%**，不足 5 份全检、逐期轮换，12 个月内每主题至少中签 1 次）。门槛：结构合规率 = 100%、要素完整率 ≥ 95%、状态一致率 = 100%、抽检合格率 ≥ 95%、**P0 / P1 = 0**；命中 P0 / P1 即告警并触发重新审计。

### 3.8 本地协作层 `workflow_guard.py`（CI 之外的质量保障）

三层隔离：任务分支 + 独立 worktree（`task start`）、串行合并锁 + 隔离合并 + `--force-with-lease`（`merge`）、共享检出锁（`lock run / acquire / release`）。保证多会话并行不互相覆盖，从协作侧保障产出一致性。

### 3.9 测试与复用一致性

- `src/tests/test_tools.py` 契约测试：命名合规、历史迁移内容零丢失（git 历史逐份复核）、跨月 diff 准确性、lint / 合规 / `build_hub` 归一化、归档策略等；
- `TestProcessReuse`：逐项断言各阶段均引用对应工具 / 产物，**漏接即失败**，防止流程漂移；
- `src/tests/test_workflow_guard.py`：分支 / 锁 / 合并 / sync。

### 3.10 词库流水线（`src/vocabulary/`）

## 四、节点 × 流水线联动矩阵

| 流程节点 | 主要保障流水线 | 联动方式 |
|---|---|---|
| 1 信息采集 | `scheduled-report-tasks.yml`、`update_planner.py`、operations-guide | 触发器命中才启动；无触发降级核验，不虚构 |
| 2 信息筛选 | 通用基座 §3 / §4、business-config、`pending_verification`、`confidence-grade-standard` | 来源分级与时效规则直接决定哪些事实能进入正文 |
| 3 信息分类 | `report-classification.md`、`template-registry.md`、`compliance-rules.json`、`classify_reports.py`、`validate.yml` | 类型决定骨架与合规校验口径；归位错误在门禁被拦截 |
| 4 内容生成 | 四层提示词继承、登记册 Schema、`audit_preflight → audit_check → audit_pipeline --submit` 三步自检、`sync_vocab` | 生成即自检；P0 / P1 未清零不得提交 |
| 5 报告输出 | `html-sync.yml`、`scheduled-maintenance.yml`、`build_hub --check`、`archive_reports` | 生成物与源稿强一致；归档窗口与展示窗口对齐（12 期） |
| 提交 / 合并 | `validate.yml` + `audit-gate.yml` 双门禁 | 规范类与审计类并行阻断，任一退出码 1 即不可合并 |
| 周期回归 | `info-quality.yml`（周）、`audit-sampling.yml`（月）、`scheduled-maintenance.yml`（月） | 存量报告持续复评；P0 / P1 触发重新审计 / 人工介入 |
| 决策消费 | 00 件套 + 五问视图 + 缺失清单 | 消费层暴露缺失 → 触发补缺（14–20 主题即由此产生）→ 回流阶段 1 |

**闭环关键设计**：

- **单一事实源**：business-config / 登记册 / compliance-rules / topics.json 各管一类参数，标准只定义一次；
- **复用一致性**：`TestProcessReuse` 保证各环节引用同一套工具，防止流程漂移；
- **防篡改**：内容指纹 SHA-256 + 哈希链台账 + 已审计标识，任何内容变更使审计失效并强制重走流程；
- **防回退**：「已修正事实清单」跨期继承，已核实结论不得复活旧表述。

## 五、质量闭环与可靠性机制

1. **标准统一**：通用层不含业务关键词，业务参数只在 business-config 维护一份；登记册 Schema（v1 / v2）统一口径字段，C-08 / C-10 / C-13 直接消费。
2. **门禁前移**：生成三步自检 → PR 双门禁 → 合并后同步，三层拦截点覆盖「落盘前 / 合并前 / 合并后」。
3. **全量而非抽样**：信息质量与审计校验全量执行，仅月度分层抽检用于复核；历史问题用 `--new-only` + 白名单过渡，逾期恢复阻断。
4. **防篡改可追溯**：指纹绑定 + append-only 哈希链 + 标识自动撤销，任何内容变更都使审计失效并强制重走流程。
5. **决策支撑**：00 层只读消费 01–20 结论，五问「是 / 否 / 待定 + 依据 + 置信度」直接服务**信息最优决策**；标准化呈现（canonical 结构 + 跨月对比高亮 + 索引 / 检索层）服务**标准化呈现**。

## 七、质量门禁覆盖核对（准确性 / 完整性 / 可控性）

逐阶段核对每个节点是否同时具备**准确性**、**完整性**、**可控性**三类门禁：

| 阶段 | 准确性门禁 | 完整性门禁 | 可控性门禁 | 结论 |
|---|---|---|---|---|
| 1 信息采集 | 来源分级 ①–⑤ + 四元组标注 + 语言规则（通用基座 §4、business-config §5） | 追踪表逐项核对 + 前置检查基线 / 上期存在（operations-guide 0.3） | 触发器命中才启动；无触发降级核验、不虚构；任务清单提醒 | **齐备** |
| 2 信息筛选 | 时效 12 / 24 月规则；核验状态分级；C-14 分级来源强制标注 | 事实单元来源覆盖率 ≥ 20%；待复核清单 + 口径冲突清单承载未决项 | C-01 / C-02 冲突门禁；冲突并列不合并、不取均值 | **齐备** |
| 3 信息分类 | 六族十三类选型 + 一票判别；骨架节名参考 | h2 节数 / 编号连续 / 锚点 / md-html 配对校验 | `classify_reports` 自动归位；`validate` 命名 + slug 归属阻断 | **齐备** |
| 4 内容生成 | 结论-依据链；事实 / 推断分离；C-13 报告 ↔ 登记册数值一致 | 四层提示词继承；登记册读 + 回写；E1–E8 必需要素 | 三步自检（preflight → audit_check → submit）；P0 / P1 未清零不得提交 | **齐备** |
| 5 报告输出 | md / HTML 指纹一致；`build_hub --check` 逐字节比对 | md / html 成对；索引 + 检索层同步；归档 12 期 | `html-sync.yml` 自动同步；已审计标识 + `stale` 撤销 | **齐备** |
| 提交 / 合并 | `audit-gate --gate`（指纹 + L5 证据） | `validate.yml` 全项规范校验 | 双门禁并行阻断；退出码 1 不可合并 | **齐备** |
| 周期回归 | `audit_check --all` L1–L5；`audit_sampling` 抽检 | `info_quality_check --apply` 全量评估 + 自动修复 + 复评 | 周 / 月节拍；P0 / P1 告警并触发重新审计 | **齐备** |

**核对结论**：五个阶段与合并、周期回归均配置了三类门禁，信息流动的准确性、完整性、可控性在每一个节点都有对应的校验规则与拦截逻辑，无缺口；体系设计目标（信息最优决策 + 标准化呈现）由决策消费层与生成同步层承接。
