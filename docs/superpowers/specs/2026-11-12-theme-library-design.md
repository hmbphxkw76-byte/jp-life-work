# 主题集中展示与汇总阅读页面设计

## 1. 目标与范围

在仓库根目录新增两个静态页面：

- `index.html`：集中展示全部主题，按现有编号段分类，提供主题详情、章节直达、分类筛选和主题搜索。
- `library.html`：聚合全部当前主文档，保留原始标题层级与内容格式，提供连续阅读、全文检索、主题与章节导航。

两个页面均由脚本生成。各主题现有 Markdown 仍是唯一内容源，不创建汇总 Markdown，不修改主题正文，不纳入 `reports/archives/` 历史版本。当前范围为 13 个主题：01 最新一期监测报告及 02–13 知识手册；监测基线仅在没有版本报告时兜底。

## 2. 信息架构与页面行为

### 2.1 分类规则

沿用 README 已确定的编号段，不新增主题分组目录：

| 分类 | 主题编号 |
|---|---|
| 监测动态 | 01 |
| 职业就业 | 02–03 |
| 行业技术 | 04–06 |
| 经济环境 | 07 |
| 制度政策 | 08–09 |
| 学习成长 | 10–11 |
| 生活地域 | 12–13 |

### 2.2 集中展示页 `index.html`

- 顶部提供“主题总览”“汇总阅读”“周期更新看板”入口及全局搜索框。
- 分类导航支持锚点跳转和分类筛选；卡片按主题编号升序排列。
- 每张卡片展示编号、主题名、分类、摘要、版本、类型和主要章节数量。
- “主题详情与章节直达”使用原生 `<details>` 展开，列出主要二级章节。元导航章节“导航与使用约定”和“NN-* 索引”不计入主要章节，但汇总页仍完整保留。
- 卡片提供“在汇总页阅读”和“查看独立原文”两个入口。
- 搜索匹配主题名、分类、摘要及章节标题；结果显示匹配主题和章节，点击章节直达汇总页对应位置。
- 从汇总页返回时，URL 定位到原主题卡片，并通过 `:target` 样式标识当前卡片。

### 2.3 汇总阅读页 `library.html`

- 顶部提供“返回主题总览”“周期更新看板”和全文搜索框。
- 桌面端使用左侧主题导航与右侧连续正文；每个主题含独立目录、版本、返回总览和独立原文入口。
- 13 个主题正文按编号连续呈现，完整保留源文档的标题级别、表格、代码块、引用、列表、链接及表格来源 hover 行为。
- 主题内搜索结果和目录链接定位到具体章节；目标章节使用 `:target` 高亮。
- 每个主题的“返回主题总览”返回到对应卡片，而非只返回页面顶部。
- 无 JavaScript 时，全部正文、目录和双向锚点链接仍可使用，仅搜索功能不可用并显示提示。

## 3. 数据与生成架构

新增 `prompts/tools/build_library.py`，执行 `python prompts/tools/build_library.py` 后生成上述两个 HTML 文件。

数据流：

1. 从 `prompts/schedule.json` 读取主题 id、名称、类型和目标路径，并读取新增的 `category`、`description` 展示元数据。更新调度器忽略新增字段，现有配置校验继续适用。
2. 知识主题直接读取 `target` 指向的 Markdown；监测主题复用 `update_scheduler.latest_report()` 选择最新版本，复用 `topic_version()` 获取版本。
3. 复用 `md2html.py` 的 Markdown 扩展、配置和 `slugify`，从 Markdown 渲染各主题正文。将现有基础 CSS 提取为可复用常量，保持输出风格一致。
4. 为标题和链接添加主题命名空间，生成主题目录、章节元数据和搜索所需结构。
5. 所有主题校验成功后一次性写入 `index.html` 与 `library.html`。输出不包含当前时间等非确定性内容，重复构建结果一致。

展示元数据以 `schedule.json` 为主题登记入口；缺少分类、摘要、目标文件或正文时构建失败，不静默省略主题。

## 4. 锚点与链接规则

- 主题容器 id：`topic-{主题id}`，例如 `topic-02-career-driver`。
- 汇总页标题 id：`topic-{主题id}--{原标题id}`，确保跨主题唯一，同时保留原 slug 的可读性。
- 总览卡片到主题：`library.html#topic-02-career-driver`。
- 总览章节到汇总章节：`library.html#topic-02-career-driver--02-薪资结构与工时合规`。
- 汇总主题返回卡片：`index.html#topic-02-career-driver`。
- 源文档内部 `#锚点` 在汇总页中改写为同主题命名空间锚点。
- 指向其他已登记主题 HTML 的链接，在汇总页中优先改写为目标主题的汇总锚点；无锚点时落到目标主题起点。
- 其他相对链接依据原报告所在目录重写为仓库根目录可解析的相对 URL，避免正文搬入根目录后失效；http、https、mailto 等外部链接保持不变。
- “独立原文”始终链接到原主题 `reports/*.html`，不经过汇总页。

## 5. 搜索、快速定位与响应式

- 两页搜索均使用原生 JavaScript，无外部服务或前端依赖。
- 输入按空白拆词并执行不区分大小写的包含匹配，中文直接按子串匹配；输入事件做 150ms 防抖，最多展示 30 条结果，并提供无结果状态。
- 总览页搜索主题元数据与章节标题；汇总页搜索标题、段落、列表项和表格行，结果展示主题、最近标题和短摘要。
- `/` 聚焦当前页搜索框，`Esc` 清空搜索；不改变浏览器默认 `Ctrl+F` 行为。
- 搜索结果链接使用真实锚点，点击后关闭结果面板并定位、高亮目标。
- 桌面端内容区最大宽度约 1200px；正文保持舒适行宽。窄屏下侧边导航折叠为原生目录控件，卡片改为单列。
- 表格放入横向滚动容器，代码块保留横向滚动，页面本身不产生横向溢出。
- 样式沿用现有 `Microsoft YaHei` / `PingFang SC` 字体、`#222` 正文、`#1a5f5a` 强调色和既有表格来源链接规则；补充焦点态、卡片和导航样式。

## 6. CI、校验与文档接入

- `html-sync.yml` 在主题 Markdown、`schedule.json`、`md2html.py` 或 `build_library.py` 变化时运行；在 `md2html.py` 后执行 `build_library.py`，再运行规范校验。
- 现有“清理非 reports HTML”步骤增加保留根目录 `index.html`、`library.html`，避免误删新页面。
- `validate.py` 新增第 11 项“聚合页面同步校验”：检查两个页面存在、13 个主题入口齐全、双向链接与主题锚点存在，并通过构建器的检查模式比较生成结果，发现陈旧输出时给出错误。
- README 增加两个页面入口、生成命令及目录说明；规范校验数量由 10 项更新为 11 项。
- `.gitignore` 忽略 `.superpowers/`，防止设计草图和预览状态进入版本库。

## 7. 异常处理

- 主题配置缺字段、目标不存在、Markdown 为空、标题或主题锚点冲突：构建失败并输出具体主题和原因。
- 某一主题失败时不写入半更新的两个页面。
- 搜索无结果：两页均显示明确提示；总览页显示无匹配主题，汇总页保留原正文，不清空或隐藏阅读内容。
- 独立原文缺失：构建失败，而不是生成死链。
- JavaScript 不可用：搜索区域显示降级说明，阅读和导航保持可用。

## 8. 验证与验收

新增标准库 `unittest` 测试，覆盖：最新监测版本选择复用、标题命名空间、内部锚点改写、跨主题链接改写、普通相对链接解析、重复构建确定性和缺失主题失败。

本地验证：

1. 运行单元测试。
2. 连续运行两次页面构建，第二次无文件差异。
3. 运行 `python prompts/tools/validate.py`，达到 0 错误；不因本功能引入警告。
4. 浏览器验证 13 个主题卡片、分类筛选、主题搜索、全文搜索、章节直达、返回原卡片和独立原文链接。
5. 在桌面与约 390px 移动宽度验证导航折叠、表格滚动、正文无横向溢出及控制台无错误。

验收完成标准：所有当前主题都能从总览页直达汇总页的对应主题；主要章节和搜索结果可精确定位；汇总页完整呈现原内容且能返回原主题卡片；后续更新主题 Markdown 后，CI 可自动同步两个页面。

## 9. 非目标

- 不聚合历史归档，不重写或校订主题事实内容。
- 不引入前端框架、构建平台、外部搜索服务或新的运行时依赖。
- 不替换现有独立报告页和周期更新看板。
- 不为所有历史报告增加返回链接，不调整现有主题内容边界。
