> **版本**：v1.0（2026-11-18）

## 一、目标操作化（先定义可度量，再谈优化）

三大目标是方向，必须转成可度量、可门禁的指标，否则「优化」无法验收。

| 目标 | 操作化定义 | 核心指标 | 采集方式 |
|---|---|---|---|
| **G1 消除信息差** | 该知道的信息能被找到、被理解、被及时更新：覆盖完整、检索可达、术语对齐、缺口可见、来源可追溯 | ① 主题/报告/手册/词条覆盖率；② 搜索索引覆盖率（报告 / 手册 / 词条）；③ 失效链接数；④ 术语对齐率（同义/别名归一）；⑤ 信息差清单机器可读率 | `validate.py`、`build_hub.py`、`vocab_tool.py`、`search-index.json` 校验 |
| **G2 信息质量可靠** | 来源分级、事实/预测区分、冲突并列、置信度可判、核验闭环、时效管理、变更留痕 | ① 必需要素覆盖率；② 来源标注覆盖率；③ 置信度标注覆盖率；④ 待核实项消减率；⑤ 冲突并列合规率；⑥ L5 证据完备率；⑦ 自动验证日志覆盖率；⑧ 审计覆盖率 | `info_quality_check.py`、`audit_check.py`、`auto_verify.py`、`audit_pipeline.py` |
| **G3 基于信息的决策** | 决策所需信息聚合到 00、置信度支撑结论、缺口显式暴露不阻断、决策日志闭环、可回溯 | ① 五问收敛率；② 缺失清单消减率；③ 决策建议章节覆盖率；④ 决策日志条目/决策比；⑤ 跨月对比覆盖率 | `00-decision-hub` 五问视图、`decision_log.py`、`report_diff.py` |

> **门禁口径**：退出码 `0=通过 / 1=阻断（P0/P1）/ 2=放行（P2）`，与既有规范一致。

## 四、优化解决方案

> 原则：**单一事实源、程序化优先、门禁分级、可回滚**。每个缺口给出方案与判定标准；落地项见 §5。

### G1 消除信息差

**S1（对应 G1-1）索引失效治理**
- 方案：`build_hub.py` 构建期增加「引用存在性校验」——对 `engine/search/*.json`、`search-index.json`、`index.html` 中出现的报告路径逐一比对实际文件；失效即报错并列出。同时清理现有 5+ 处 `2026-12` 失效引用（含 `audit-status.json` 的 stale 记录按流程归档）。
- 判定标准：CI `build_hub.py --check` 通过；全仓无指向不存在报告的链接；`audit-status.json` 无 stale 未处理项。

**S2（对应 G1-2）搜索覆盖面扩展**
- 方案：扩展 `search-index.json` schema，新增 `handbook` 与 `vocabulary` 两类条目（标题、路径、主题、关键词、摘要）；`build_hub.py` 生成，`index.html` 搜索层支持类型筛选。
- 判定标准：21 份报告 + 13 份 handbook + 20 词库全部可检索；索引条目数与实际文件数一致（机器校验）。

**S3（对应 G1-3）新主题成熟度提升流水线**
- 方案：定义主题成熟度分级（词条数 / handbook 节数 / 报告期数 / 待核实消减），设阈值（词条 ≥ 70、handbook ≥ 4 节、报告 ≥ 2 期）；用 `update_planner.py` 生成补全工单，`audit_sampling.py` 月度跟踪。
- 判定标准：14–20 达到阈值；`pending-verification` 47 项按期限（2026-12-31）消减至 0 或显式延期审批。

**S4（对应 G1-4）词条字段扩展与核验状态机**
- 方案：`export.schema.json` 与 `terms.md` 增加 `confidence`（S/A/B/C）、`verification`（已核验/部分核验/待核实）、`source_url`（可空）四字段；`vocab_tool.py` 增加字段校验与导入支持；既有词条默认 `verification=待核实`，增量补核。
- 判定标准：schema 校验通过；导出 JSON 含新字段；词条核验状态可聚合出「待核实占比」指标。

**S5（对应 G1-5）信息差清单机器化**
- 方案：统一 P5 输出为结构化 JSON（缺口项、所属主题、影响、补缺责任、期限），落 `data/gap_register.json`；`audit_check` 增加「信息差清单存在且字段完整」校验。
- 判定标准：21 主题均有机器可读缺口清单；CI 可校验字段完整性。

**S6（对应 G1-6）层 1 实例化流水线**
- 方案：以 01 灰度为模板，批量生成 20 主题的层 1 提示词实例；生成后用 P5 反例复扫 + `prompt-polish`/一致性校验；槽位与 `business-config.md` 自动对齐。
- 判定标准：21 主题层 1 实例齐全；一致性校验 0 违规。

### G2 信息质量可靠

**S7（对应 G2-1/2/3）置信度与报告结构通用化**
- 方案：
  1. 将 `00-decision-hub/prompts/confidence-grade-standard.md` 提升为 `engine/report_templates/confidence-grade-standard.md`（通用层），00 引用之；
  2. `compliance-rules.json` 的 `common` 增加必填章节骨架（数据可靠性与局限 / 置信度标注 / 口径冲突并列 / 信息差清单 / 决策建议），各类型模板对齐；
  3. 报告来源统一为可机读格式（`[标题](URL) — 机构, 年份` + 分级码），`audit_check` 校验关键结论/数字带置信度码。
- 判定标准：新报告 100% 含必填章节；关键结论置信度标注覆盖率 ≥ 95%；结构校验 0 阻断。

**S8（对应 G2-4/5/6）自动验证与自检入 CI**
- 方案：`html-sync.yml` 在 md2html 后对新增/变更报告跑 `auto_verify.py`；`validate.yml` 增加 `audit_preflight` 步骤；`audit/verify/` 日志全量补齐至 21/21。
- 判定标准：`audit/verify/` 覆盖 21/21；CI 日志可见 auto_verify 结果；P0/P1 失败即阻断。

**S9（对应 G2-7）语义质量程序化子集进硬门禁**
- 方案：把可机器判定的语义维度（来源语言/URL 可访问性、口径冲突关键词、以偏概全绝对化词、信息差清单存在性）纳入 `audit_check.py`；真正语义类（结论忠实性）保留 L5 + 抽检。
- 判定标准：新增子集在 CI 可复现；误报率 < 5%（用存量报告回归标定）。

**S10（对应 G2-8/9）配置化与登记闭环**
- 方案：决策工具常量外置到 `engine/vocabulary/config/` 或 `engine/tools/registry.json`；`audit_registry --check`、`generate_registry --check` 接入 `validate.yml`；`registry.json` 过期自动报错。
- 判定标准：CI 校验 registry 一致性；无硬编码漂移。

**S11（对应 G2-10）L5 元评估**
- 方案：对 L5 证据加质量门槛（basis 字数/抽查数/结论一致性），`audit_pipeline.validate_l5_evidence()` 增加元校验；低质量证据判无效并要求重核。
- 判定标准：L5 证据合格率可统计；不合格证据被拒。

### G3 基于信息的决策

**S12（对应 G3-1/3/4）决策收敛度量与建议章统一**
- 方案：00 五问视图输出结构化状态（是/否/待定 + 置信度 + 缺口数）；`build_hub.py`/新工具生成决策收敛趋势（跨月）；所有报告统一「决策建议」章并与置信度/缺口绑定；`report_diff.py` 覆盖新主题（满 2 期后自动）。
- 判定标准：五问收敛率、缺失消减率可跨月计算并可视化；21 报告建议章覆盖率 100%。

**S13（对应 G3-2）决策日志入 CI**
- 方案：`decision_log.py` 接入 `scheduled-maintenance.yml`，校验日志与报告变更同步。
- 判定标准：CI 可检测日志缺失。

### 工程与治理

**S14（对应 E-1～E-8）工程硬化**
- 方案：一次性工具纳入 CI 冒烟；ruff/mypy 分阶段收紧（先清 135 项存量）；补 I-11 平台差异守卫测试；决策增量构建切换；建立性能趋势；清理 `reader.html` 文档漂移；统一提示词命名与模板优先级。
- 判定标准：见 §5 各项验收。

### 6.1 目标 → 指标 → 验证命令对齐矩阵

| 目标 | 指标 | 目标门槛 | 验证命令 |

| 工程 | 测试 / 覆盖率 | unittest 全绿；覆盖率 ≥ 80% | `python -m unittest discover -s engine/tests`；`coverage_gate.py` |

### 6.2 分层验证策略

1. **单元/集成**：`engine/tests/`（868 项）+ 新增项的 TDD 测试；`coverage_gate` ≥ 80% 阻断。
2. **门禁**：`validate.py`（结构/命名/模板/污染）、`lint_reports.py --new-only`、`compliance_check.py --all`、`audit_check.py --all`、`audit_pipeline.py --gate`。
3. **生成物一致性**：`build_hub.py --check`、`build_index.py --check`、`md2html.py` + `report_diff.py`。
4. **抽检**：`audit_sampling.py` 月度分层抽检 + `audit_badge` 标识同步。
5. **人工闸门**：L5 语义复核（`--review`）、S2 人工闸门（`pipeline_runner`）、报告落盘前 P0/P1 自检。

### 6.4 验收标准

- **P0 全部完成**，P0/P1 阻断项 = 0；
- §6.1 矩阵所有指标达门槛；
- §6.3 回归命令全部退出码 0（或 2 放行且留有说明）；
- 新增/变更报告通过 `auto_verify.py` 并写回「## 自动验证结果」；
- 落地后产出「实施结果验证报告」，逐项对照本清单打勾并附证据。

## 八、风险与回滚

| 风险 | 影响 | 缓解 / 回滚 |
|---|---|---|
| 词条字段扩展破坏既有导入/导出 | 词库工具链中断 | 字段可选、默认值兼容；先跑 `vocab_tool.py verify` 再切换；必要时回滚 schema 版本 |
| 报告结构统一引发 21 报告大改 | 交付物波动 | 增量改造 + `md2html` 重生成 + `report_diff` 核对；逐主题提交 |
| 置信度历史转换工作量大 | 进度 | 仅对新报告与关键结论强制；历史报告增量转换（confidence-grade-standard 使用规则第 4 条） |
| 语义门禁误报 | CI 噪音 | 先灰度为告警，标定误报 < 5% 后再转阻断 |
| 新主题内容补全量大 | 人力 | 分级阈值 + 工单化 + 期限管理；允许显式延期审批 |
| 与并行会话冲突 | 合并错误 | 严格三层隔离；只提交本任务文件 |
