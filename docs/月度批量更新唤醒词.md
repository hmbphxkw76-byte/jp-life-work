# 月度报告批量更新 · 唤醒词与执行手册（MONTHLY-BATCH-UPDATE）

> **版本**：v1.0（2026-11-16）
> **定位**：跨主题、平台无关的「本月报告全量更新」唯一入口。**唤醒词负责触发，本手册负责执行。**
> **上位依据**：`AGENTS.md`（会话硬性规约）、[信息生产全链路执行规范](信息生产全链路执行规范.md)（PIPELINE-FLOW-SPEC）、[审计报告标准化管理体系](审计报告标准化管理体系.md)（AuditGuard）、[src/prompts-tools/tools/README](../../src/prompts-tools/tools/README.md)
> **单一事实源**：本文件是唤醒词与批量编排的唯一定义处；各主题业务参数（变量 / 来源 / 口径 / 触发器）仍以其 `prompts/business-config.md` 为准。
> **与编排器的关系**：自动「触发检测 → 计划 → 人工闸门」见 [端到端流水线编排系统设计-2026-11-17](端到端流水线编排系统设计-2026-11-17.md) 与 [端到端流水线治理标准](端到端流水线治理标准.md)；**编排器为唯一自动入口，本手册降级为人工应急预案**（指针互指）。

## 一、唤醒词

| 主唤醒词 | 同义别名（任选其一） |
|---|---|
| **本月报告全量更新** | 月度报告批量更新 · 一键更新本月报告 · 执行本月报告更新 · 本月报告更新 · 月度更新 · 月更 · 全更 |

**用法**：把唤醒词发给任意 Agent，并附一句「按仓库内 `docs/月度批量更新唤醒词.md` 执行」。Agent 读手册后按第二节执行。

**可选参数**（追在唤醒词后，由 Agent 解释执行）：

| 参数 | 作用 | 缺省 |
|---|---|---|
| `--period YYYY-MM` | 指定目标月（映射 `update_planner.py --period`） | 当前自然月 |
| `--project <主题目录>` | 只处理指定主题（映射 `update_planner.py --project`） | 全部主题 |
| `--dry-run` | 只生成清单与骨架，不落盘 | 否 |
| `--force` | 忽略「已产出」，强制重跑（覆盖已审计内容，须显式确认） | 否 |

## 二、执行流程（七步，顺序不可跳）

### 第 0 步 · 隔离（并行会话保护，AGENTS.md 硬性规约）

```bash
python tools/workflow_guard.py task start monthly-update-<YYYY-MM>
cd .worktrees/monthly-update-<YYYY-MM>   # 分支名自动带会话 sid：task/monthly-update-<YYYY-MM>-<sid>
pip install -r requirements.txt
```

### 第 1 步 · 前置检查

```bash
python src/prompts-tools/tools/validate.py
python src/prompts-tools/tools/lint_reports.py
```

退出码 1 → 停止修复；2（仅警告）→ 记录后继续。

### 第 2 步 · 生成月清单

```bash
python src/prompts-tools/tools/update_planner.py --pending-only --period <YYYY-MM>
# 机器读：--porcelain --pending-only --period <YYYY-MM>
```

清单逐条给出：主题目录、提示词路径、输出路径、状态、审计状态。
**清单为空**（本月已产出）→ 转「复核模式」：对已有报告做核验、不重写；或指定 `--period` 指向目标月。

### 第 3 步 · 逐主题执行（研究内容由 Agent 按提示词撰写）

对清单中每个 pending 主题：

1. 读 `<主题>/prompts/business-config.md` 与清单指出的 `prompt-*.md`。
2. 填运行变量：`{{CURRENT_DATE}}`、`{{CADENCE}}`、`{{PREVIOUS_REPORT_PATH}}`、`{{OUTPUT_PATH}}=reports/<YYYY-MM>-<slug>.md`、`{{REPORT_VERSION}}=vYYYY.MM.DD`。
3. 读登记册活值 → 采集（日 / 英来源，逐点引用）→ 写报告 md → 回写登记册。
4. **节拍纪律**（以各主题 business-config 与提示词为准，批量流程不得覆盖）：

   | 节拍类型 | 主题 | 本月动作 |
   |---|---|---|
   | 月度核验型 | 01 / 02 / 03 / 07 / 10 / 11 / 12 / 14 / 15 | 只更新登记册与触发器状态，不重写报告 |
   | 月度监测型 | 13 | 产出当月监测报告 |
   | 事件触发型 | 08 / 09 / 16 / 17 / 18 / 19 / 20 | 无触发不启动；命中触发器才产出解读件 |
   | 年度刷新型 | 04 / 05 / 06 | 窗口未到不启动 |
   | 决策层 | 00 | 季度末月做五问复核；其余月份只读消费 |

5. 继承「已修正事实清单」；**无触发不虚构变化**。

> 若确需「每主题强制产出本月报告」，属节拍变更，须先改各主题 `business-config.md` 并走维护规范，不要用批量唤醒词绕过。

### 第 4 步 · 生成与校验（任务工作树内）

```bash
python src/prompts-tools/tools/md2html.py
python src/prompts-tools/tools/lint_reports.py --new-only
# 对每份新报告：
python src/prompts-tools/tools/auto_verify.py --report <报告相对路径>
```

- `auto_verify` 通过 → 自动写回「## 自动验证结果」、重生成 HTML、自动 `audit_pipeline --submit`。
- 失败 → 按 V1–V5 逐条修正，再走交付四步协议：

  ```bash
  python src/prompts-tools/tools/audit_preflight.py --report <路径>
  python src/prompts-tools/tools/audit_check.py --report <路径>
  python src/prompts-tools/tools/audit_pipeline.py --submit --report <路径>
  ```

### 第 5 步 · 收尾

```bash
python src/prompts-tools/tools/build_index.py
python src/prompts-tools/tools/archive_reports.py
python tools/cleanup_workspace.py
```

`build_hub.py` 由主会话在共享检出目录统一执行（AGENTS.md 规定）。

### 第 6 步 · 提交与合并

```bash
python tools/workflow_guard.py merge monthly-update-<YYYY-MM>
```

合并门禁 `audit_pipeline --gate` 拦截未审计的变更报告。

### 第 7 步 · 决策层（00-decision-hub）

- 季度末月：按 `00-decision-hub/prompts/business-config.md` 第三节做五问季度复核，更新 `reports/<YYYY-MM>-decision-hub.md`。
- 非季度末月：只读消费，不产出。

## 三、平台挂载（迁移任何平台都可用）

唤醒词与手册分离；手册只依赖「读文件 + 跑 shell」，不依赖任何平台专有能力。

| 平台 | 挂载点 | 用户说什么 |
|---|---|---|
| 妙手（CatPaw） | `AGENTS.md` 自动加载 | 「本月报告全量更新」 |
| Claude Code | `CLAUDE.md` 加指针 | 同上 |
| Cursor | `.cursorrules` / 自定义指令加指针 | 同上 |
| 任意 Agent | 首条消息贴唤醒词 + 手册路径 | 同上 |

**指针写法**（加到平台常驻指令文件，一行即可）：

```
收到「本月报告全量更新」时，读取并严格执行 docs/月度批量更新唤醒词.md。
```

---

## 四、迁移性设计原则（为什么换平台仍可用）

1. **唤醒词与手册分离**：短句触发，细节在手册；换平台只改挂载点。
2. **手册路径固定**：`docs/月度批量更新唤醒词.md` 是唯一定义处。
3. **只依赖仓库内相对路径 + `python`**：无绝对路径、无平台专有语法。
4. **不依赖平台能力**：不需要 skill / MCP / hook，能读文件、能跑 shell 即可。
5. **业务参数不下沉**：阈值 / 来源 / 触发器仍读各主题 business-config，手册只给编排。
