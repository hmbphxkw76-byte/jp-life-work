## 一、适用范围与边界

### 1.1 范围内

1. 触发检测：watchlist 结构化、freshness 检查、候选命中清单。
2. 编排：六阶段状态机、状态持久化、断点续跑、幂等。
3. 监控：跨环节统一视图 + 心跳留痕。
4. CI：定时检测、计划生成、门禁与生成物同步。
5. 治理：阶段定义、命名、异常处理、漂移检测的规范固化。

### 1.2 范围外（硬性）

| 项 | 说明 |
|---|---|
| 自动撰写研究正文 | 违反来源分级 / 不虚构纪律；永远人工 / Agent |
| 来源站点自动抓取与内容比对 | 本体系只做「候选提示」，不核实 |
| 服务端 / 数据库 / 外部 API / 消息队列 | 非目标；纯本地 CLI + GitHub Actions |
| 修改既有工具的校验规则 | 只调用；如确需修改走治理流程（第七节） |
| 取代七步手册 | 手册降级为人工应急预案，指针互指 |

### 1.3 人机边界（唯一人工环节）

```
S0 检测   ┐
S1 计划   │ 机器
──────────┼────────────────────────────
S2 撰写   ← 唯一人工环节（人 / Agent 按 prompts 产出正文）
──────────┼────────────────────────────
S3 生成校验 ┐
S4 审计提交 │ 机器（自动续跑）
S5 监控   ┘
```

## 二、阶段定义（S0–S5）

| 阶段 | 输入 | 输出 | 退出条件 | 责任人 |
|---|---|---|---|---|
| `S0_detect` | `business-config §7`、登记册核验日期 | `trigger-watch.json` 快照 + `window_due` / `stale` / `candidates` | 扫描完成（含空清单） | Agent |
| `S1_plan` | 周期 + 业务线清单 | 待撰写清单（`update_planner` pending 判定） | 清单产出 | Agent |
| `S2_author` | 待撰写清单 | 研究正文（`reports/YYYY-MM-<slug>.md`） | **人工完成**后 `resume --from-stage S3_build` | **人 / Agent** |
| `S3_build` | 报告 md 源稿 | 同名 `.html` + V1–V5 验证结论 | `md2html` + `auto_verify` 退出码 0 | Agent |
| `S4_audit` | 报告 md / html | 审计提交（`audit_pipeline --submit`） | 提交成功（含 SKIP 幂等） | Agent |
| `S5_monitor` | 状态文件 + 台账 + 心跳 | `status.md` / `status.json` | 监控视图产出 | Agent |

**S2 硬闸门**：编排器在 `S2_author` 只置 `pending` 并产出待撰写清单，**不得跳过、不得自动生成正文**；守卫测试 `test_workflow_has_no_authoring_step` 与 `test_run_pauses_at_author_gate` 断言该边界。

## 四、状态机

### 4.1 合法转换

```
[*] → S0_detect（冷启动 / 续跑起点）
S0_detect → S1_plan → S2_author(pending) → [人工] → S3_build → S4_audit → S5_monitor → [*]
任一台阶 → FAILED（阶段函数返回 ok=False）
FAILED → S0_detect（修复后从失败阶段续跑）
```

### 4.2 非法转换（守卫）

- 跳过 `S2_author` 直接产出正文 —— **禁止**（无自动路径）。
- `S2_author` 未人工完成即推进 `S3_build` —— 仅允许通过显式 `resume --from-stage S3_build`（视为人工已完成 S2）。
- 状态文件 `schema_version` 缺失或不符时续跑 —— **禁止**，直接退出码 1。
- 从 `S0` 之外的阶段「静默补齐」前置阶段状态 —— 仅 `resume` 显式指定 `from_stage` 时允许，且须留痕。

### 4.3 状态字段

```json
{
  "schema_version": "1.0",
  "period": "2026-11",
  "stages": {
    "S0_detect": {"status": "completed", "summary": {}, "started": "...", "completed": "..."}
  },
  "updated": "..."
}
```

`status ∈ {pending, running, completed, failed}`。

## 五、异常处理

| 场景 | 处置 | 退出码 |
|---|---|---|
| 状态文件缺失 | 冷启动（`new_state`），不报错 | 0 |
| 状态文件损坏 / schema 不符 | 立即终止，打印定位（可重建），不静默续跑 | 1 |
| 阶段函数失败 | 写 `FAILED` + summary，终止；修复后从失败阶段续跑 | 1 |
| 参数错误（非法周期 / 非法阶段） | 打印可选值，终止 | 2 |
| 无触发 / 无待办 | 返回空清单，**不虚构候选** | 0 |

**人工介入条件**：`S2_author` 待撰写；状态文件损坏；阶段连续失败。

## 六、漂移检测（守卫测试）

`engine/tests/test_pipeline_orchestrator.py` 固化以下不变量：

1. **阶段顺序不变**：`STAGES[:3] == ("S0_detect", "S1_plan", "S2_author")`。
2. **S2 闸门生效**：`run` 停在 `S2_author(pending)`，`S1_plan` 已 completed。
3. **续跑可达**：`resume --from-stage S3_build` 后 `S5_monitor` completed。
4. **损坏终止**：损坏状态文件 → 退出码 1。
5. **幂等**：同一阶段重复执行状态一致；`trigger_watch.scan` 重复执行零差异。
6. **只读默认**：`trigger_watch` 默认不写快照，`--apply` 才写。
7. **CI 无撰写**：工作流不含 `md2html.py` / `auto_verify.py` / `audit_pipeline.py`。
8. **单一事实源**：`STAGES` 由 `pipeline_status` 定义，`pipeline_runner` 复用。

> 新增守卫须同步 `docs/CI.md` 测试数（`test_arch_guard::test_test_count_matches_ci_doc` 强制）。

## 七、变更流程

1. **阶段定义 / 阈值 / 人机边界变更**：须修订本文件与设计文档，并经用户审定。
2. **新增阶段**：须同步 `STAGES`、状态机图、守卫测试、CI 工作流（如涉及）。
3. **阈值变更**（如 `STALE_DAYS`）：沿用 `info_quality_check` 单一事实源，不另立口径。
4. **工具登记**：新增工具后运行 `generate_registry.py --write`，同步 `engine/scripts/README.md` 工具一览与 `registry.json`。
5. **留痕**：每次变更追加本文件「版本记录」，并在提交信息中说明。

## 八、版本迭代

- `schema_version` 当前 `"1.0"`，仅含 `schema_version` / `period` / `stages` / `updated`。
- **向后兼容**：版本不符视为损坏，拒绝静默续跑（可重建）；升级时旧状态文件可人工重跑 `run` 重建。
- 状态文件为派生 / 可重建产物，入库仅作审计留痕。
