| 周期保障 G | html-sync / maintenance / info-quality / sampling / report-tasks | 生成物、三清单、抽检报告、提醒 Issue | 见规范第五节 |
| 决策消费 H | 00 五问收敛（只读）、缺失暴露 | 五问判定、缺失清单 | 季度复核 / 事件触发 |
| 补缺准入 I | 先登记后触发、四要素齐备、闭环回写、按节奏 | 登记册状态回写 | P1 季度 / P2 月度 / P3 年度 |
| 反馈链路 | D→A 登记册回写；G→A 修复/基线回写；G→F 抽检重审；内容变更→失效 | C-13 / 三清单 / stale·rejected / 标识撤销 | 见规范第七节 |

### 7.2 禁区（不得偏离）

1. 不得「带病前进」——未过闸不得进入下一环节；修复后必须**重过原闸**（出口=复评口）。
2. 不得跳过 / 重排**交付四步协议**（`md2html+lint` → `audit_preflight` → `audit_check` → `--submit`）。
3. 不得新写判定规则——阶段闸必须复用 `info_quality_check` / `compliance_check` / `audit_registry` 内核。
4. 不得未登记即启动补缺；补缺四要素（分级/责任/验收/**期限**）不齐不得触发。
5. 不得直接 `push main`；不得在共享检出目录运行 `build_hub.py` / `md2html.py`。
6. 不得例外执行——任何偏离必须写入 `lint-whitelist.json` / `pending-p2.json` 并注明原因与复核日期。

### 8.2 持续校验机制

1. **守卫测试**：`TestPipelineFlowSpec`（规范 ↔ 仓库）、`TestProcessReuse`（流程复用）、`TestThreeSystemAlignment`（提示词/AGENTS/CI 三体系）任一失败即视为流程漂移，阻断合并。
2. **CI 两道门禁**：`validate.yml`（结构层 14 步）+ `audit-gate.yml`（审计层 2 步），退出码 1 阻断、2 放行。
3. **周期工作流**：html-sync（push）/ maintenance（每月 1 日 00:15）/ info-quality（每周一 02:20）/ sampling（每月 1 日 00:25）/ report-tasks（每月 1 日 00:20）。
4. **P2 台账**：`pending-p2.json` 30 天复核（当前 `review_by=2026-12-15`），超期告警；豁免清单 `lint-whitelist.json` 复核日过期即恢复阻断。
5. **生成物确定性**：每次重生成后 `git status` 须仅含约定心跳 / 日志类漂移，且须还原；`build_hub --check` / `build_index --check` 恒过。
6. **季度角色复核**：R2/R5 承载语义类边界（来源语言规则、冲突裁决、六族选型正确性）。

### 8.3 无例外执行保障

- 每个节点**先校验、后流转**；校验载体与判定内核单一事实源，禁止并行新写判定。
- 任何「例外」必须落清单（含原因 + 复核日期），复核日过期自动恢复阻断；**不存在无记录的例外执行场景**。
- 新发现偏差按本报告第五节路由：规范要素类（O1/O2/N4）回源对应阶段修正；文档类（N1–N3/N5/N6）在最近维护窗口修正并留痕。
