## 一、审计方法

1. **规范基线法**：以根部 4 份规范 + `compliance-rules.json` + `_common.py` 登记为基准，逐文件核对。
2. **结构程序化核对**：脚本提取每份模板「声明节数（N 节固定顺序）/ 结构表行数 / 自检清单节数」，与 `compliance-rules.json` 的 `sections` 交叉比对。
3. **链接可解析性核对**：核对全部相对链接（继承声明、类型模板引用、工具路径）在当前仓库布局下是否真实可达。
4. **命名一致性核对**：提取全部 `{{OUTPUT_PATH}}` / 文件名示例，与 `monitoring-common-spec.md` §1 及 `_common.py` 命名正则比对，并与业务线实际产物（`*/reports/*.md`，22 份）对照。
5. **三处同步核对**：类型模板 ↔ `prompts/` 泛用版 ↔ `business-prompt-scaffold.md` 的内容与必备章节一致性。
6. **行业最佳实践对照**：按 `report-classification.md` 六族十三类的「核心产出 / 数据来源特征 / 边界」，逐类评估章节覆盖度与模块完整性。

## 三、系统性问题（跨类型，按优先级）

### S1【P0】market-monitoring 三份周期模板节数口径漂移，与 compliance 规则冲突

| 文件 | 声明 | 结构表行数 | 自检清单 | `compliance-rules.json` | 判定 |
|---|---|---|---|---|---|
| `prompt-monthly-monitor-template.md` | 「9 节固定顺序」(L18) | 8 | 「9 节齐全」(L56) | monthly = **8** | ❌ 多报 1 节 |
| `prompt-quarterly-analysis-template.md` | 「12 节固定顺序」(L81) | 11（编号 1–10、12，**跳 11**） | 「12 节齐全」(L121) | quarterly = **10** | ❌ 多报 2 节 + 编号断号 |
| `prompt-annual-review-template.md` | 「11 节固定顺序」(L69) | 10 | 「11 节齐全」(L127) | annual = **10** | ❌ 多报 1 节 |

- **影响**：业务提示词若按模板自检「N 节齐全」执行，会与 CI `compliance_check.py` 的 h2 节数校验（`sections`）冲突，导致合规校验误报或漏报；季度模板「节 12 页脚」缺第 11 节编号，结构表自身不连续。
- **建议**：把三份模板的声明/自检改为与规则一致（8 / 10 / 10）；季度模板将「页脚」改为第 11 节（h2）或明确标注为 `footer` 元素（与规则注释「第 11 节页脚为 footer 元素」对齐），并补齐编号连续性。

### S2【P0】market-monitoring 4 份模板继承声明相对链接错误

- 4 份文件 L5 均写 `[通用基座](./prompt-generic-base.md)` / `[监测报告通用规范](./monitoring-common-spec.md)`。
- 文件位于 `src/report_templates/market-monitoring/`，`./` 指向同目录，**目标文件不存在**；正确应为 `../`。
- 其余 11 类模板均用 `../`，唯 market-monitoring 例外（历史遗留）。
- **建议**：4 份文件 L5 的 `./` 改为 `../`；并在守卫测试中增加「模板内相对链接可解析性」用例（当前 `test_template_tool_paths_valid` 只校验工具路径）。

### S3【P0】11 份脚手架 + 24 份泛用版 prompts 的继承链接全部陈旧（布局漂移）

- 脚手架/泛用版统一使用 `../../../report_templates/...`（脚手架）或 `../../../prompt-generic-base.md` + `../../monitoring-common-spec.md` + `../<模板>.md`（泛用版）。
- 该写法假设「业务提示词位于 3 层深的 `{REGION}/{PROPERTY}/prompts/`，且 `report_templates/` 在仓库根」——这是 **macropulse-reports 时代的两层布局**。
- 本仓库现实：业务线为**单层** `NN-slug/prompts/`（2 层），模板在 `src/report_templates/`。经核，实际业务提示词（42 份，覆盖全部 21 条业务线）统一使用 `../../src/report_templates/...`。
- **后果**：按脚手架/泛用版复制到新业务线后，三条继承链接**全部不可解析**（`../../monitoring-common-spec.md` 与 `../<模板>.md` 在复制后也错位）。
- **建议**：统一改为 `../../src/report_templates/...` 口径（与实际业务提示词一致），或在业务配置中引入 `{{TEMPLATE_ROOT}}` 变量消解布局耦合；同步修订 `prompt-generic-base.md` §1.1/§1.2 与 `template-registry.md` §3.2 的目录约定。

### S4【P0】employment-research 周期模板泄漏业务关键词，违反类型中立硬性约束

- `employment-research/prompt-update-template.md` L32：「市场与政策：国家 / 城市 **AI 与网络安全**战略实施进展……」——这是 dubai/cybersecurity 业务线的专属内容，被带入了类型模板。
- `template-registry.md` §3.1 第 2 步明确「模板内**严禁**出现任何业务关键词（地区 / 机构 / 专属指标）」。
- 该类型已接入 9 条业务线（ssw-driver / career-driver / economy-finance / language-japanese 等），「AI 与网络安全」会误导全部业务线。
- **建议**：改为类型中立的「国家 / 城市 **重点产业**战略实施进展」或「（TODO：按业务配置实例化的产业政策）」，并复核同文件 L37「签证门槛」等表述（作为就业落地维度可保留，但建议改为「（TODO：准入与居留路径）」）。
- **配套**：`_common.py` 的 `BUSINESS_KEYWORDS` 仅含 Dubai 词表（L180–191），无法通用拦截；建议扩充为「地区名 / 已知业务线主题词」通用表，并在 `validate.py` 中对类型模板启用。

### S5【P1】旧命名残留：71 处 `_baseline_report` + 2 处 `_annual`

- `monitoring-common-spec.md` v1.1（2026-11-15）已明确「旧 `_baseline_report` / `_monthly` / `_quarterly` / `_annual` 命名不再使用」，统一为 `YYYY-MM-<slug>`。
- 实际产物已全部合规（22/22 份 `*/reports/*.md` 均为 `YYYY-MM-<slug>`，0 份 `_baseline_report`）。
- 但模板/泛用版/脚手架中仍有 **71 处 `_baseline_report`**（37 个文件）与 **2 处 `_annual`**：
  - `market-monitoring/prompt-annual-review-template.md` L11：`reports/{{YEAR}}_annual.html`
  - `policy-analysis/prompt-policy-review-template.md` L14：`{{YYYY}}_annual.md`（与同文件 §四「输出与命名」的 `{{YYYY-MM}}-<slug>.md` **自相矛盾**）
  - `trend-weekly/prompt-baseline-setup-template.md` L11/L36：`reports/{{YYYY-MM}}_baseline_report.html`
  - 以及 11 份脚手架、24 份泛用版 prompts 的 `{{OUTPUT_PATH}}` / `{{BASELINE_REPORT_PATH}}` 示例。
- **影响**：新业务线复制泛用版后，按示例填出的文件名不符合现行规范，`compliance_check.py` 会因「无法识别周期」降级为警告，`validate.py` 命名校验口径分裂。
- **建议**：批量替换为 `reports/{{YYYY-MM}}-<slug>.md`（基线同样按此口径，slug 由业务配置定义）；`trend-weekly` 周报保持 `{{YYYY-MM-DD}}_weekly`（已纳入标准正则），其基线机制文档改用 `{{YYYY-MM}}-<slug>.md`。

### S6【P1】24 份泛用版 prompts 全部缺失「落盘后审计」协议

- 28 份类型模板均含「落盘后审计（提交前必做）」章节（引用 `audit_preflight.py` / `audit_check.py` / `audit_pipeline.py`）。
- **24 份 `prompts/` 泛用版 0 份引用审计三件套**（仅有 `md2html.py` + `lint_reports.py`）。
- `template-registry.md` v1.5 要求「内容与脚手架正文一致，修改周期提示词内容时须同步类型模板、prompts/ 泛用版与脚手架三处」；AGENTS.md 交付协议要求报告落盘后按序执行审计。泛用版是可独立运行的母版，缺失审计协议会导致新业务线漏审。
- **建议**：在 24 份泛用版末尾统一补「落盘后审计（提交前必做）」小节；并把 `test_prompts_reference_audit_tools` 的扫描范围从 `src/report_templates/*/prompt-*.md` 扩展到 `src/report_templates/*/prompts/*.md`。

### S7【P1】`compliance-rules.json` 与 flash-commentary 模板不符

- 规则：`flash-commentary.cycles.monthly = { sections: 8, nav: true, template: prompt-flash-note-template.md }`（L136）。
- 模板：`prompt-flash-note-template.md` 定义的是**四段式**（事件摘要 / 预期对比 / 初步影响判断 / 后续观察点），与 `flash_note` 周期（sections=4）对应。

- **建议**：删除或修正 `flash-commentary.cycles.monthly`（若确无月度节拍），保留 `baseline` + `flash_note`；避免规则文件与模板骨架漂移。

## 四、逐类型审查（13 类）

> 评估维度：章节结构 / 内容模块 / 数据维度 / 呈现逻辑 / 格式规范。✅ = 与行业主流同类型报告最佳实践对齐；🟡 = 基本对齐但有改进空间；❌ = 存在缺陷。

### A1 market-monitoring 市场指标监测型（4 份模板）

- **行业最佳实践**：摘要 → 方法论/数据源 → 指标看板 → 逐项对比 → 信号/阈值 → 基线偏离 → 缺口 → 观察清单；季度含传导链、红线归一化、供给情景；年度含预测回测、来源巡检、台账版本。
- **符合项**：骨架完整且细粒度领先（五态定义、红线归一化公式、T+0/T+1 判定、专题预警六件套、标准列结构表）；双格式交付、导航、来源承载齐全。
- **待调整**：S1 节数漂移（月 9→8、季 12→10、年 11→10）；S2 相对链接；S5 年度命名；季度结构表跳号。
- **结论**：🟡（内容最佳，结构口径需修）

### A2 competitive-intelligence 竞争情报监测型（2 份模板）

- **行业最佳实践**：执行摘要 → 监测机制 → 竞争格局（份额/集中度）→ 竞品档案卡 → 动态矩阵 → 信号规则 → 来源治理 → 风险盲区 → 来源清单。
- **符合项**：九节与行业惯例高度一致；「公开信息边界」「多源交叉（单源待证）」「档案库闭环」专业。
- **待调整**：S3 链接陈旧；L73 版本记录「六族十二类」陈旧（应为十三类）；可补「情报生产周期（规划→采集→分析→分发）」方法论句（非阻断）。
- **结论**：✅

### A3 sentiment-monitoring 舆情传播监测型（2 份）

- **行业最佳实践**：声量趋势 → 情感分布 → 议题/热点榜 → KOL 观点摘编 → 风险预警 → 口径方法声明。
- **符合项**：九节对齐；「言论≠事实」声明、机器人/水军盲区、口径一致性纪律专业。
- **待调整**：S3 链接陈旧；可补「情感判定工具与人工复核比例」的最低要求已具备；无需大改。
- **结论**：✅

### A4 trend-weekly 行业趋势周报型（2 份）

- **行业最佳实践**：本周要点 Top5 → 分板块（固定 3 块）→ 数据看板（上期/本期/变化）→ 风险与不确定性 → 可执行启示 → 来源。
- **符合项**：八节与行业周报惯例一致；数据截止日命名、T+1 标注、空窗降级、反方证据收录齐全。
- **待调整**：S5 基线命名（`_baseline_report.html`）；`prompt-baseline-setup-template.md` L11/L36 改 `{{YYYY-MM}}-<slug>.md`；`prompts/prompt-baseline-setup.md` 用「结果验证」而 `prompt-weekly-monitor.md` 用「渲染与交付」，建议统一；可增「上期观察点跟踪」模块（行业惯例）。
- **结论**：🟡

### B1 employment-research 职业就业调研型（2 份）

- **行业最佳实践**：摘要 → 方法论 → 行业与政策趋势 → 供需与薪酬 → 雇主细分 → 技能要求 → 资质证书 → 落地路径建议 → 数据局限 → 来源。
- **符合项**：九节覆盖完整；「岗位 × 职级」交叉分层表、净薪/总包模型、证书路线图、来源语言规则执行声明专业。
- **待调整**：**S4 业务关键词泄漏**；建议把「调研方法与设计」独立成节或在摘要中显式声明抽样/回溯方法（当前方法融在摘要与可靠性节，行业惯例偏向独立方法论节）；L37「签证门槛」建议泛化。
- **结论**：🟡（内容强，中立性需修）

### B2 consumer-research 消费者·用户调研型（2 份）

- **行业最佳实践**：方法论（抽样/样本量/置信度）→ 细分画像 → 满意度/NPS → 交叉分析 → 结论建议。
- **符合项**：八节对齐；样本质量声明、显著性降级、知情同意与隐私、定性脱敏齐全。
- **待调整**：S3/S5；建议补「问卷/访谈提纲附录」与「样本结构表（配额完成度）」硬性要求（当前为隐含）。
- **结论**：✅

### C1 industry-research 行业深度研究型（2 份）

- **行业最佳实践**：摘要 → 研究范围方法 → 产业链 → 规模与格局 → 竞争格局 → 驱动与风险 → 趋势判断 → 数据治理 → 来源。
- **符合项**：九节与券商/咨询行业研究惯例一致；多口径并列、趋势复判（上年原文保留）、边界档案闭环专业。
- **待调整**：S3/S5；无需大改。
- **结论**：✅

### C2 market-sizing 市场规模测算与预测型（2 份）

- **行业最佳实践**：TAM/SAM/SOM、自上而下/自下而上、假设清单、基准年规模、三情景、敏感性、模型治理。
- **符合项**：九节对齐；「模型即核心交付物」「每个数字可追溯假设」「区间 + 三情景不给神数字」「回测归因」专业。
- **待调整**：S3/S5；建议在 §2 明确「自上而下与自下而上交叉验证」为必做（当前 §4 已含交叉验证，可上提为方法要求）。
- **结论**：✅

- **行业最佳实践**：投资要点（评级/估值区间）→ 标的概况 → 行业输入 → 财务与估值 → 风险清单 → 情景与敏感性 → 合规 → 来源。
