# 输入润色与确认门禁（Prompt Polish & Confirm Gate）

> 版本：v1.0（2026-11-18）
> 定位：会话交互规范。任务型输入先润色、再确认、后执行。
> 硬性规约：`AGENTS.md`「输入润色与确认门禁」节；操作细则：工作区 skill `prompt-polish-confirm`。

## 一、意图

把「输入 → 直接执行」改为「输入 → 润色 → 展示 → 确认 → 严格按最终版执行」，
让歧义与误读在执行前暴露，而不是事后解释。

## 二、目标 / 非目标 / 反目标

- **目标**：任务型输入 100% 先润色确认；确认后执行内容与确认版一致。
- **非目标**：不改写用户原意；不替用户做需求决策；不改变现有 git / 审计流程。
- **反目标**（出现即失败）：跳过确认直接执行；确认后自行加码；把用户的修改版再润色一遍。

## 三、方案选择

| 方案 | 强制力 | 结论 |
|---|---|---|
| `AGENTS.md` 硬规约 + 工作区 skill | 每个会话自动生效 | **采用** |
| 个人 skill（全局） | 需 Agent 主动调用，不自动触发 | 不采用 |
| 纯文档 | 无约束 | 不采用 |

## 四、流程

1. **触发**：任务型输入（要求 Agent 执行动作）。纯提问 / 确认 / 补充 / 闲聊不触发。
2. **润色**：重构为【目标】【背景】【约束】【期望输出】【原意核对】五段；补结构不补需求；歧义列入核对。
3. **展示**：完整展示，请用户「确认执行」或修改；展示后停住，不调用工具、不执行、不预写文件。
4. **执行**：仅按用户最后确认版执行；不扩展、不改写、不增补；分叉停下问。

## 五、边界与例外

- **确认认定**：回复「确认 / 执行 / 同意 / 可以」或修改版，均视为确认；以最后给出的版本为准。
- **无例外**：用户要求「直接做 / 跳过确认」也不跳过，仍需确认一次。
- **强制触发**：不可逆 / 影响共享状态的操作（push、删文件、改 main、发外部消息）即使用户语气随意也触发。
- **修改版**：用户修改后以其版本为准，不再二次润色。
