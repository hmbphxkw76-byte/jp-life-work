# 提示词模板清单

> **用途**：本仓库全部动态更新提示词模板的登记册。新建或修改模板后须同步更新本表，并运行文末校验命令。
> **元数据规范**：每个模板文件首部必须含四项字段——**模板标识 / 适用场景 / 版本 / 更新说明**，缺一视为不合规。
> **版本规则**：`vYYYY.MM.DD[_N]`，同日多次修改逐次递增 `_N`，不得复用。
> **状态定义**：`正常` = 已按规范整理并通过契约测试；`待优化` = 已知存在偏差或待补字段；`已废弃` = 不再使用，仅留档。

## 三、重叠主题的边界约定

| 重叠点 | 归属（单一事实来源） | 另一方的写法 |
|---|---|---|
| 自动驾驶 | 产业面 → 04；技术与制度面 → 05 | 只给结论 + 跨主题链接；01 仅保留指标 #10 |
| 岗位与资格需求 | 岗位实操 → 02；管理岗过渡 → 03；资格/讲习制度 → 10 | 02/03 写岗位与晋升，10 写资格要件与费用 |
| 驾照与免许费用 | 01 登记册 #14 | 02（准入路径）、10（教育投资）只读引用 |
| 考试日程/费用/考位 | 01 登记册 #3 | 08 写制度要件；11 写备考计划，数值只读 |
| 受入上限/在留者数/试验要件 | 01 登记册 #1/#2 | 08、09 只读引用，不独立改值 |
| 住房与生活成本 | 12 写制度与查询入口；租金行情归 13/07 登记册 | 12 只写结构与入口，不复述行情数值 |
| 政策更新日志 | 08 手册 09 章 | 09 只写动向结论并链接，不另设日志章节 |

## 四、维护与校验

1. 新增/修改模板：补齐四项元数据 → 更新本表 → 跑校验（新建主题的完整步骤见第五节）。
2. 契约测试（39 项，覆盖变量一致性、章节真实性、SSOT 只读、版本规则、活值零硬编码、reviews 默认关闭；已接入 CI `validate.yml`）：

```bash
python -m unittest discover -s prompts/tools/tests -p "test_*.py"
```

3. 规范校验（12 项）：

```bash
python prompts/tools/validate.py
```

4. 状态变更：模板被替代时改为 `已废弃` 并在「更新说明」注明替代者；`待优化` 须写明待办事项。

## 五、新建主题流程（2026-11-12 演练通过）

按顺序执行；第 8 步通过前，本清单第二节的状态只能写 `待优化`。

1. **定参数**：编号 `NN`、slug、中文名、章节数与登记册项数 N、更新周期（对应 `schedule.json` 的 `cadence_days`）。
2. **建目录**：`NN-{slug}/data/`、`NN-{slug}/prompts/`、`NN-{slug}/reports/archives/`。
3. **复制脚手架**：知识库主题用 [prompt-脚手架-知识库主题更新.md](脚手架/prompt-脚手架-知识库主题更新.md) → `NN-{slug}/prompts/prompt-{slug}-update.md`；监测项目改用 [prompt-脚手架-职业就业调研.md](脚手架/prompt-脚手架-职业就业调研.md)。
4. **替换占位符**（改完不得残留）：
   - 身份类：`{{主题名}}`、`{{slug}}`、`{{中文名}}`、`{{target}}`，以及正文中的 `NN`
   - 运行变量：`{{DOC_LIST}}` 章节区间、`{{REGISTRY_PATH}}` 的「N 项」
   - `{{REVIEWS_DIR}}` **保持留空**；知识库主题不设复盘目录
   - 第一、二、四、五、六、九节的示例占位符（如 `{{事件 1}}`、`{{章节名}}`）逐条换成真实内容
   - 追踪表与自检里的项数必须等于登记册项数（3 项 → 「追踪表 3 项」）
5. **补四项元数据**：模板标识 `PRM-TOPIC-{NN}`、适用场景、版本 `vYYYY.MM.DD`、更新说明；头部保留「通用基座」「类型模板」字样（`validate.py` 第 10 项只查头部 2000 字符）。
6. **建配套文件**：
   - `data/{slug}-indicator-registry.md`，表头固定为 `| # | 指标 | 优先数据源 | 最新值（来源/年份） | 基准版本 |`，首期填「待基线确立」。
   - `reports/日本{中文名}知识手册.md`，`## NN 章节名` 须与第五节逐节对应，首版含「导航与使用约定」更新日志区。
7. **登记三处**：`prompts/schedule.json` 的 `topics`（id / name / kind / target / category / description / prompt / registry 缺一不可）；README「知识库主题目录说明」表；本清单第二节。
8. **跑校验**：第四节两条命令 + `python prompts/tools/update_scheduler.py status`，确认新主题被排期识别。
9. **验收项**（与演练脚本一致）：身份占位符零残留、四项元数据齐备、三变量齐备、头部继承声明、九节结构、`{{REVIEWS_DIR}}` 留空、追踪表与自检项数对齐、快照顺序段（先读上一版 → 差异比较 → 再回写登记册）、回写范围限定本主题主责、第五至七节无「同上」与「05/06 文档」旧称。

> **演练记录（2026-11-12）**：以 `NN=14`、`slug=dryrun-topic` 实例化知识库脚手架，上述 9 条对应的 11 项结构断言全部通过；产物仅落系统临时目录，未写入仓库。
