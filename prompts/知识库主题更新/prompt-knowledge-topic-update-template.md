# 类型模板 · 知识库主题更新（动态获取）

> **层级定位**：第 2 层类型模板 = [通用基座](../通用基座/prompt-generic-base.md) × 本文件差异配置。适用于本仓库 `docs/` 下**以知识库文档群为单位**的主题（每个 `docs/{NN-topic}/` 即一个"主题项目"）。与监测类的区别：产出不是单份新报告，而是**增量回写既有文档群**；锚定对象是文档群自身的历史版本。
>
> **继承声明**：运行变量、全局约束、基线锚定、更新协议、执行方式、自检骨架均自动继承通用基座与《[监测报告通用规范](../monitoring-common-spec.md)》，本文件只写**类型差异**；与上层冲突时以本文件为准。

---

## 类型差异 T1 · 主题项目结构（docs/ 主题目录约定）

```text
docs/{NN-topic}/
├── 00-index.md                    # 目录导航：篇目清单 + 更新状态 + 最近更新日期（每次更新后维护）
├── {NN}-…md                       # 主题文档（按编号组织，一篇一个子话题）
├── prompts/
│   └── prompt-{slug}-update.md    # 第 3 层主题提示词 = 本模板 × 主题专属配置
└── data/                          # 可选：主题级登记册（指标活值、来源台账）
```

## 类型差异 T2 · 专属运行变量

```
{{TOPIC_DIR}}            = 主题目录路径（如 docs/01-visa-immigration）
{{DOC_LIST}}             = 本次更新涉及的文档清单（由主题提示词声明）
{{INDEX_PATH}}           = 主题导航文件（默认 {TOPIC_DIR}/00-index.md）
```

锚定对象：`{{PREVIOUS_REPORT_PATH}}` 在本类型中语义为 **`{{TOPIC_DIR}}` 内各文档的当前版本**（git 历史为最终回退锚）。

## 类型差异 T3 · 输出形态（覆盖通用基座第七节）

- **增量回写**：直接更新 `{{DOC_LIST}}` 中受影响的文档；未受影响文档不动；结构性内容（路线、框架表）按模块要点"保持"。
- **每次更新必须产出**（写入 `{{INDEX_PATH}}` 的更新日志区，不单独成文）：
  1. **数据变更摘要**：| 文档 | 变更点 | 旧值/旧说法 | 新值（来源/年份）| 性质（新增/修订/无变化）|
  2. **待复核清单**：无法核实的条目 + 推荐复核入口。
- **新增知识**在现有文档中找不到位置时，新建编号文档并同步 `00-index.md`；禁止把不相关内容塞进既有文档。
- 文档内新增数据点一律附 `[Source: 完整URL, 年份]`；推断显式标注。

## 类型差异 T4 · 来源登记

每主题在提示词或 `data/` 中维护**主题来源台账**：机构/域名、类型（官方一手/国际组织/行业机构/门户/媒体）、语言、用途（对应模块）。新增来源须先归类再引用；中文来源按项目语言规则处理。

## 类型差异 T5 · 执行方式建议

1. 触发器前置检查（同通用基座第六节第 1 条）。
2. 并行子代理 2–4 个，按文档群分工；每个子代理限定主题来源台账范围、逐点引用、**每条数据必须附 URL**。
3. 主代理差异合并：读取受影响文档当前版本 → 继承已修正事实 → 按"更新/动态获取/保持"回写 → 更新 `00-index.md`。
4. 回写完成后运行 `python scripts/md2html.py {{TOPIC_DIR}}` 重新生成 HTML（产物在 `output/`，不入库）。

## 类型差异 T6 · 主题专属必填区（第 3 层填写清单）

第 3 层主题提示词 = 本类型模板 × 以下配置：

1. 【主题定位与受众】一句话说明本主题服务哪条人生/职业路线
2. 【来源优先级实例化】五层框架 → 本主题具体域名/机构清单 + 语言规则
3. 【术语口径区分】（如适用）
4. 【事件触发器表】→ 触发文档编号
5. 【文档群更新要点】逐篇：更新 / 动态获取 / 保持
6. 【关键信息追踪表】编号 + 信息项 + 优先数据源（活值存 `data/` 或文档内）
7. 【已修正事实清单】首期为空，随修正追加
