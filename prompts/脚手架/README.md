# 脚手架 · 全新主题 prompt 创建指南

> **用途**：本目录提供两套**可直接复制粘贴**的 prompt 脚手架，用于创建新的 `NN-{slug}` 主题目录。
> **前置**：先阅读 [通用基座](../通用基座/prompt-generic-base.md) 和匹配的类型模板，理解三层继承体系。
> **步骤**：
> 1. 复制对应的脚手架文件到 `NN-{slug}/prompts/prompt-{slug}-update.md`
> 2. 替换所有项目占位符：`{{项目名}}`/`{{主题名}}`、`{{slug}}`、`{{受众描述}}`、来源清单类（`{{列出…}}`）、`{{事件 N}}`、`{{模块名 N}}`/`{{文档名}}`、`{{项目专属自检项 N}}`；可选锚（`{{数字/结论}}`、`{{target}}`、`{{类型类/制度类/数字类}}`）按实际填写，无交叉验证则删除该行
> 3. 首次运行前，按通用基座五-A 格式创建 `NN-{slug}/data/{slug}-indicator-registry.md`
> 4. 运行、获取首版基线、修正登记册，后续迭代;每期结束后在 `NN-{slug}/reviews/` 写复盘（如启用）

## 产出形态选择

| 类型 | 脚手架文件 | 适用场景 | 产出 |
|---|---|---|---|
| **单份报告（职业就业调研类）** | `prompt-脚手架-职业就业调研.md` | 面向拟赴某地就业的读者，以行业调研 + 落地建议为主体 | 单份 Markdown + HTML 报告 |
| **知识手册（知识库主题更新类）** | `prompt-脚手架-知识库主题更新.md` | 按章节组织单份知识手册，增量回写既有手册 | 单份知识手册 md + html（## NN 章节） |

## 变量约定（通用集 + 类型专属）

以下为通用变量集（★ = 所有类型必填；其余按产出类型取用），含义由通用基座统一规定：

```
★ {{REGION}}
★ {{TOPIC}}
★ {{CURRENT_DATE}}
  {{REPORT_VERSION}}
  {{PREVIOUS_REPORT_PATH}}
  {{OUTPUT_PATH}}
★ {{FRESHNESS_PRIORITY}}
★ {{SOURCE_LANGUAGE_RULE}}
★ {{REGISTRY_PATH}}     = NN-{slug}/data/{slug}-indicator-registry.md（prompt 文件内可写 ../data/{slug}-indicator-registry.md，等价）—— N 项指标活值登记册，每次运行先读后写
  {{REVIEWS_DIR}}       = NN-{slug}/reviews/ —— 运行复盘存放处（未启用可省略，启用则每期必写）
```

类型专属变量（由对应类型模板定义，不得与通用变量重名冲突）：

| 产出类型 | 必填专属变量 | 说明 |
|---|---|---|
| 单份报告（职业就业调研） | `{{REPORT_VERSION}}`、`{{PREVIOUS_REPORT_PATH}}`、`{{OUTPUT_PATH}}` | 版本号含 `v` 前缀，文件名不得再重复加 `v` |
| 知识手册（知识库主题更新） | `{{TOPIC_DIR}}`、`{{HANDBOOK_PATH}}`、`{{DOC_LIST}}` | `{{PREVIOUS_REPORT_PATH}}` 语义为知识手册当前版本 |

**反模式禁令**：prompt 模板内严禁硬编码活值（如"上次值：341,158 円"）——活值一律运行前从 `{{REGISTRY_PATH}}` 读取、运行后回写登记册。

## 章节映射（通用基座 ↔ 第 3 层脚手架）

脚手架按第 3 层提示词的可执行顺序展开，与通用基座章节一一对应，迁移时不遗漏：

| 通用基座 | 第 3 层脚手架 | 承载内容 |
|---|---|---|
| 运行变量 | 运行变量 | 通用变量 + 类型/项目专属变量 |
| 一、全局硬性约束 | 一、项目/主题专属硬性约束 + 二、来源优先级 | 基座约束继承；第 3 层只写来源语言、受众、术语口径、来源优先级实例化 |
| 二、基线锚定 | 三、基线锚定 | 已修正事实清单 |
| 三、更新协议 | 四、更新协议 | 事件触发器表 |
| 四、模块更新要点 | 五、模块/手册章节更新要点 | 更新 / 动态获取 / 保持 |
| 五、追踪表 + 五-A 登记册 | 六、追踪表 | 空"上次值"列 + registry 读写说明 |
| 六、执行方式 | 七、执行方式 | 子代理分工 + md2html/归档 |
| 七、输出要求 | 八、输出格式要求 | 结构、命名、变更摘要、复盘 |
| 八、质量自检 | 九、质量自检 | 通用清单 + 专属项 + registry 检查 |

## 与现有 monitors 的交叉验证锚

如果新主题与现有 monitors 有数据交叉（如司机薪资、汇率、试验费用等），在 prompt 继承声明末尾添加：

```
> **交叉验证锚**：{{数字/结论}} 以 NN-{{target}}/data/{{target}}-indicator-registry.md 为单一事实源；冲突时以本文件为准。
```

## 首次运行 checklist

- [ ] 目录结构创建：`NN-{slug}/{data,prompts,reports,reviews}/`
- [ ] `data/{slug}-indicator-registry.md` 按通用基座五-A 格式创建（首期"最新值"列可写"待基线确立"）
- [ ] prompt 文件已替换所有占位符
- [ ] 类型模板匹配（单份报告用职业就业调研模板、知识手册用知识库主题更新模板）
- [ ] 运行变量齐全，`{{REGISTRY_PATH}}` 指向正确位置
- [ ] 事件触发器表至少列 3 项（无触发器则按空窗期轻运行）
