# 监测报告通用规范

> **模板标识**：PRM-SPEC-001
> **适用场景**：全部监测类报告与知识库主题更新的跨类型质量规范（引用、来源优先级、口径、结构、版本、自检）
> **版本**：v2026.11.12
> **更新说明**：2026-11-12 版本号统一为 `vYYYY.MM.DD[_N]` 同日递增制；覆盖规则改为显式允许/禁止清单，明确引用与 SSOT 红线不可被下层覆盖。
>
> **用途**：本项目所有监测类报告（`NN-{主题}/reports/`）与知识库主题更新（`NN-{主题}/reports/`）的通用质量规范，跨报告类型共享。动态更新提示词采用**三层继承**：[通用基座](通用基座/prompt-generic-base.md)（骨架）→ 类型模板（差异）→ 项目/主题提示词（专属配置）。优先级顺序项目/主题专属 > 类型模板 > 通用基座 > 本规范；可覆盖范围仅限输出结构、路径、运行变量与更严格的类型纪律，不可覆盖引用纪律、禁止编造、事实与推断分离、SSOT 主责与已修正事实。任何覆盖须显式声明。

---

## 一、语言与输出

1. 最终报告统一以**中文**撰写；来源 URL、机构名、专有名词保持原文（英文原样），不翻译。
2. 数据来源语言要求由各项目自行声明（如"仅英文来源"），本规范不强制。

## 二、引用规范（逐点可回溯）

1. **行内引用**：正文段落中的每个关键数据点必须附 `[Source: 完整URL, 年份]`。
2. **表格引用（统一呈现）**：表格内不出现 `[Source: …]` 原文，也不单设"来源"列；把该行主题单元格（参数/指标/事项/企业·岗位等）的文字做成超链接：`href` = 首个来源 URL，`title` = 完整来源串（`来源：URL, 年份`），实现 hover 显示来源、点击直达原文。`title` 必须落到真实 URL，不得保留"同上"等占位；无可用 URL 时保留原文，不得丢源。
3. **来源清单**：报告末尾附完整参考来源清单，含 URL + 标题 + 年份。
4. **可回溯性**：读者应能凭引用直接访问原始出处；二手转载须注明"经 XX 转载，原文未取得"。

## 三、来源优先级框架（强制排序）

同一指标存在多个来源时按下列优先级取值；**冲突时并列呈现双份并标注**，不得擅自取舍：

1. **官方一手**：政府/监管机构官网、官方统计与公报
2. **国际权威组织**：国际公认的标准组织、研究机构、行业协会
3. **行业专业机构**：专业咨询/研究机构的公开报告与指数
4. **平台/门户抽样**：招聘平台、数据门户等一手聚合数据
5. **主流媒体**：主流媒体报道（常为二手转述，需尽量回溯原文）

各项目须在提示词中将上述 5 层实例化为具体域名/机构清单。

## 四、事实与推断分离

1. 直接引用的数据标注"来源"；由分析者合理推演的结论必须**显式标注"推断"**，不得伪装成事实。
2. **数据口径标注**：
   - 不同机构统计口径不同（如成交价 vs 挂牌价、登记口径 vs 调研口径），须在表格中以"来源口径"列区分；
   - 口径不同的数据**不可直接比较或加总**；
   - 市场规模类数据须注明统计口径差异（如"终端支出" vs "含服务总收入"）。

## 五、报告结构模板（九段式，可裁剪）

```text
一、核心结论（摘要）        — 结论先行，数字卡/信号灯形式呈现关键判断
二、市场趋势与政策          — 政策框架、规模与增速、需求驱动、区域对比、展望（推断须标注）
三、供需与价格/薪资         — 缺口/供给、分层基准表、区域对比、成本模型
四、生态/企业/主体细分      — 雇主或参与方分类、重点主体核实、近期生态事件
五、技能/产品/技术要求      — 分层要求表、专项技能、工具栈
六、认证/资质/标准          — 资质总览、新兴专项、路线图、本地可得性、监管内嵌要求
七、行动建议（结论章）      — 路径、渠道、实操清单、谈判/决策要点
八、数据可靠性与局限说明    — 核验程度分级、已知口径冲突、未取得项
九、参考来源清单（完整 URL）
```

纯市场监测项目可裁剪为：核心结论 → 指标读数 → 信号与阈值 → 缺口 → 观察清单 → 免责声明。

## 六、版本管理与文件命名

1. 版本号格式 `vYYYY.MM.DD[_N]`（数据基准日）：同日首次运行可省略 `_N`（即 `vYYYY.MM.DD`），同日多次运行须逐次递增 `_N`（`_2`、`_3`…），不得复用同一版本号。
2. 文件命名：`{主题}报告_{版本}.md`（`{版本}` 已含 `v` 前缀，如 `v2026.11.12`、同日第二次为 `v2026.11.12_2`，文件名不得再重复加 `v`）或按周期 `{YYYY-MM}_{周期}.html`（项目内自行声明并保持一致）。
3. 同目录保留历史版本，不覆盖删除；任何情况下不得覆盖既有文件；报告文末标注：`本报告为 {版本} 动态更新版，数据基准 {日期}，来源要求见项目提示词。`

## 七、数据变更摘要与待复核清单（每次更新必产出）

1. **数据变更摘要**（置于报告开头或参考来源前）：

| 指标 | 上一版值（来源/年份） | 本次值（来源/年份） | 变化性质（新增/上调/下调/修正/无变化） |
|---|---|---|---|

2. **待复核清单**：列出本次仍无法从符合优先级要求的来源核实、建议用户自行复核的条目及推荐复核入口。

## 八、质量自检清单（提交前逐项确认）

- [ ] 正文每个关键数据点均有 `[Source: URL, 年份]` 行内引用
- [ ] 表格无 `[Source: …]` 原文与独立"来源"列，行主题已超链接（hover 显示来源、点击直达）
- [ ] 来源优先级合规，冲突数据已并列双报
- [ ] 事实与推断分离，推断处均显式标注
- [ ] 所有表格标注数据口径，口径不同者未直接比较
- [ ] 已继承项目"已修正事实清单"，无事实回退
- [ ] 追踪表指标均已核对并填写"是否更新"，未变动项注明"截至 {日期} 无更新"
- [ ] 已产出"数据变更摘要"与"待复核清单"
- [ ] 文件按版本规范命名，历史版本保留
