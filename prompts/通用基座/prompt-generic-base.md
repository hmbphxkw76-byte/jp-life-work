# 动态更新提示词 · 通用基座

> **模板标识**：PRM-BASE-001
> **适用场景**：本仓库全部周期性更新类提示词的第一层继承基座（监测项目、职业就业调研、市场指标监测、知识库主题更新）
> **版本**：v2026.11.12
> **更新说明**：2026-11-12 统一版本号为 `vYYYY.MM.DD[_N]` 同日递增制；把覆盖规则改为显式允许/禁止清单；区分登记册当前值与报告/手册历史快照；reviews 改为仅显式启用；补充快照比较顺序与历史记录不可追溯改写。
>
> **层级定位**：本仓库动态更新提示词采用**三层继承**体系，本文件为第一层（通用基座），提炼自职业就业调研类与市场指标监测类两类模板的公共骨架。
>
> ```text
> 第 1 层  prompts/通用基座/            ← 本文件：运行变量、锚定、更新协议、追踪表、执行与输出骨架
> 第 2 层  prompts/{类型}/              ← 类型模板：只写该类型差异（输出形态、结构模板、专属纪律）
> 第 3 层  {项目或主题}/prompts/        ← 项目/主题提示词：类型模板 × 专属配置（来源清单、触发器、追踪指标）
> ```
>
> **使用方式**：
> 1. 第 2 层、第 3 层提示词**不复制本文件正文**，在文件头部用一行继承声明引用：`本文件 = 通用基座 × {类型模板} × {专属配置}`；
> 2. 覆盖规则：项目/主题专属 > 类型模板 > 通用基座 > 《监测报告通用规范》只表示文件选择顺序；可覆盖范围仅限输出结构、路径、运行变量与更严格的类型纪律；不可覆盖引用纪律、禁止编造、事实与推断分离、SSOT 主责与已修正事实。任何覆盖须在文件头部显式声明"本节覆盖上层第 X 节"；
> 3. 质量规则（中文输出、逐点引用、来源优先级框架、口径标注、事实与推断分离）统一遵循《[监测报告通用规范](../monitoring-common-spec.md)》，全链路自动继承，任何层不得弱化。

## 运行变量（通用变量集）

```
{{REGION}}               = 监测/调研地区
{{TOPIC}}                = 监测/调研主题
{{CURRENT_DATE}}         = 本次运行日期，格式 YYYY-MM-DD
{{REPORT_VERSION}}       = 本次版本号，格式 vYYYY.MM.DD[_N]：同日首次运行可省略 _N（即 vYYYY.MM.DD），同日多次运行须逐次递增 _N（_2、_3…），不得复用同一版本号；任何情况下不得覆盖既有文件
{{PREVIOUS_REPORT_PATH}} = 上一版产出路径（首期为空 → 直接产出基线，作为后续锚定）
{{OUTPUT_PATH}}          = 本次输出路径（按类型模板/项目声明）
{{SOURCE_LANGUAGE_RULE}} = 来源语言规则（如"仅英文" / "日文+英文" / "不限，引用须回溯原文"）
{{FRESHNESS_PRIORITY}}   = 数据时效优先级窗口（默认：近 12 个月内优先；超过 24 个月须标注年份并谨慎使用）
{{REGISTRY_PATH}}        = 指标活值登记册路径（**强制变量，不得省略**）；规范写法 `NN-{slug}/data/{slug}-indicator-registry.md`（仓库根相对），prompt 文件内可写作 `../data/{slug}-indicator-registry.md`（等价）；登记册为活值唯一存放处，prompt 模板内禁止持有具体数值
{{REVIEWS_DIR}}          = 运行复盘存放目录（仅项目显式启用时设置，路径 `NN-{slug}/reviews/`；当前知识库主题默认省略，未设置时不创建该目录）
```

类型模板/项目可追加专属变量（如知识库类型的 `{{TOPIC_DIR}}`、`{{INDEX_PATH}}`、`{{DOC_LIST}}`；职业就业调研类型的 `{{REPORT_VERSION}}` 已在通用集），但不得重定义上述通用变量含义。

> **反模式禁令**：prompt 模板的追踪表、更新变量区块中**严禁写入具体活值**（如"上月读数：341,158 円"）——活值一律运行前从 `{{REGISTRY_PATH}}` 读取、运行后回写登记册。prompt 模板自身只留编号、指标名、数据源与空 checkbox。

## 一、全局硬性约束（违反即视为失败）

1. **继承《监测报告通用规范》第一至四节**：中文输出、行内引用 `[Source: 完整URL, 年份]`、来源优先级五层框架（冲突时并列双报）、事实与推断分离、口径标注。
2. **禁止编造数据**：无法核验的标"未核验／需核实原文"，不得作为事实引用；区分实际值、预测值（后缀 F）、计划值。
3. **周期未发布时**使用最近已发布周期并明确写出数据截止时间；多来源冲突并列呈现，不得静默择一。
4. 项目专属约束（来源语言、受众、禁用来源、术语口径）写入第 3 层提示词的【项目专属约束区】。

## 二、基线锚定（防止已修正事实回退）

1. 更新前**必须读取 `{{PREVIOUS_REPORT_PATH}}`**（首期除外），继承其结构与全部已核实结论。
2. 维护**已修正事实清单**：每条以 ❌ 开头，写明"错误说法 + 正确结论 + [Source]"，随每次修正持续追加；此前已被推翻的说法严禁重新引入。
3. 清单存放位置由第 3 层声明（随报告文首或独立登记册），全链路唯一，不得分叉。
4. **跨主题冲突**：本主题与外部主责主题（含 01 监测）结论冲突时，先回官方一手来源复核，再由该事实的 SSOT 主责方更新；消费方只读同步并保留修正清单，不得反向覆盖主责方。

## 三、更新协议

1. **刷新窗口**：以 `{{FRESHNESS_PRIORITY}}` 为准；同一指标多版本并列呈现并标注年份。
2. **事件触发器**（命中任一项即触发对应模块重点更新；无触发则降级为核验/收敛型轻运行，**不得为制造变化而虚构变化**）：

```
【事件触发器表 — 第 3 层按项目填写】
- {事件} → 触发模块 {X、Y}
```

3. **差异对比**：先读取指定上一版快照做差异比较，再回写登记册；未变动项注明"截至 {{CURRENT_DATE}} 无更新"。
4. **待复核清单**：无法从符合优先级要求的来源核实项单列，附推荐复核入口。
5. **更新标记（已更新 标注）**：本轮发生变更的章节/内容块，在源文档 markdown 中**单独一行**写入
   `<!-- updated: YYYY-MM-DD [| 本次更新摘要] -->`（紧邻章节标题 = 章节级；位于段落/表格/列表/引用/代码块之前 = 块级）。
   构建 `index.html` / `library.html` 时自动转为「已更新」徽标与高亮；未标记内容保持原样。
   标记表示**最近一次更新**：只维护本轮变更处的标记，未再变动的旧标记应移除，避免高亮累积。
   语法与独立成行要求由 `prompts/tools/validate.py` 第 12 项校验。

## 四、模块更新要点（格式约定）

按产出结构逐模块声明三类动作，第 3 层逐项填写：

```
【模块 N · 名称】
- 更新：…（定期变化的框架性内容）
- 动态获取：…（本轮必查的指标/资料及其优先数据源）
- 保持：…（结构性内容，不轻易变动）
```

## 五、关键指标追踪表（格式约定）

每次运行逐项核对，未变动项保留基线值并注明"截至 {{CURRENT_DATE}} 无更新"。**prompt 模板内严禁填写活值**（见反模式禁令），模板只保留编号、指标名、数据源与空 checkbox；"上次值"列留空，运行时按本文件《快照比较顺序》填入。

```
| # | 监测指标/信息项 | 优先数据源 | 上次值（运行前从 {{PREVIOUS_REPORT_PATH}} 读取填入） | 本次是否更新 |
|---|---|---|---|---|
| 1 |  |  | （留空） | ☐ |
```

## 五-A、指标活值登记册（registry）格式规范

登记册存放于 `{{REGISTRY_PATH}}`，是全项目**活值唯一存放处**，任何 prompt / 报告文档不得另立活值分叉。仅登记本主题/项目主责指标；外部主责项只读引用，不写入本登记册。格式：

```markdown
# {项目} · 指标登记册（活值）

> **用途**：N 项关键监测指标的**活值存放处**（提示词只保留指标定义与数据源，避免提示词被每次运行改写）。每次运行更新本登记册 → 回写报告"数据变更摘要"。
> **格式**：每项含 `最新值（来源/年份）` 与 `基准版本`。首值取自首期基线报告"数据变更摘要"。
> **锚定**：已修正事实清单以最新版报告文首为单一事实源，本登记册不重复维护。

## 观察项与触发器状态（每次运行更新）

| 状态项 | 内容 | 更新于 |
|---|---|---|
| 唯一观察项 |  |  |
| 首要触发器 |  |  |

登记册每次运行**必读必写**（仅限本主题主责项）；外部 SSOT 项只读引用、不参与回写。

**当前值与历史快照的区分**：登记册只保存截至本次核验的当前活值，并逐项标注来源日期与基准版本；上一版报告、手册更新日志中的数值属历史快照，二者须以来源日期与基准版本区分，不得混用。本次输出须成为带数据基准日的新快照；旧报告与手册更新日志属历史记录，不得追溯改写。

**快照比较顺序**：先读取 `{{PREVIOUS_REPORT_PATH}}` 指定上一版快照（不以登记册当前值代替），据此做差异比较，再更新 `{{REGISTRY_PATH}}`；顺序不可颠倒。

## 六、执行方式（建议）

1. **触发器前置**：先检查事件触发器表，未命中且无未决观察项时，仅做轻量核验，不启动全量刷新。
2. 启动 2–6 个并行研究子代理（按产出规模：单份报告类 4–6、知识手册类 2–4），按模块/章节分工；**每条数据（含佐证级）必须附可直接访问的 URL**，无 URL 不采纳。
3. 子代理返回后，由主代理读取 `{{PREVIOUS_REPORT_PATH}}` 做差异合并：继承已修正事实、应用更新协议与模块要点。
4. 冲突数据保留双份引用；无法核实项单列"待复核清单"。

## 七、输出要求

1. 报告结构遵循第 2 层类型模板声明；引用、口径、版本命名遵循通用规范第五、六节。
2. 每次更新必须产出：**数据变更摘要 + 待复核清单**（通用规范第七节）。
3. 文件命名 `{主题}报告_{{REPORT_VERSION}}.md`（`{{REPORT_VERSION}}` 已含 `v` 前缀，文件名中**不得再重复加 `v`**；或类型模板声明的周期命名），同目录保留历史版本，不覆盖删除；文末标注版本与数据基准日。
4. 首期命名为 `…_baseline.md`（或 `YYYY-MM_baseline` 周期格式）；基线版始终留在 `reports/` 顶层，不进入 `archives/`。
5. **运行复盘**：仅当项目已显式设置 `{{REVIEWS_DIR}}` 时，写入复盘（运行概况、逐项处理矩阵、修正与教训、下期建议）；未设置或留空时**不得创建**该目录，直接省略复盘输出。登记册"观察项与触发器状态"表照常同步。

## 八、质量自检（通用清单）

- [ ] 正文每个关键数据点均有 `[Source: URL, 年份]` 行内引用；表格按通用规范二.2 以主题超链接呈现来源
- [ ] 来源优先级合规，冲突数据已并列双报；事实与推断分离
- [ ] 已继承"已修正事实清单"，无事实回退
- [ ] **`{{REGISTRY_PATH}}` 已读已写**（仅本主题主责项）：报告变更摘要与登记册一致
- [ ] 追踪表逐项核对并填写"是否更新"；已产出变更摘要与待复核清单
- [ ] 触发器已检查；空窗期未虚构变化
- [ ] 文件按版本规范命名（`{{REPORT_VERSION}}` 不重复加 `v`），历史版本保留；文末附完整参考来源清单
- [ ] 运行复盘仅在 `{{REVIEWS_DIR}}` 已设置时写出；未设置或留空时不得创建目录
- [ ] **prompt 模板自身无硬编码活值**（追踪表"上次值"列为空或运行时动态填入，而非模板内预写）
