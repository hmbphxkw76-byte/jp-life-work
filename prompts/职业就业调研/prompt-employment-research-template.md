# 类型模板 · 职业就业调研（动态更新）

> **层级定位**：第 2 层类型模板 = [通用基座](../通用基座/prompt-generic-base.md) × 本文件差异配置。适用于「面向拟赴某地就业的读者、以行业调研 + 落地建议为主体」的项目（如 01-monitor-ssw-driver）。指标台账型市场监测项目请用《[月度监测类型模板](../市场指标监测/prompt-monthly-monitor-template.md)》。
>
> **继承声明**：运行变量、全局硬性约束、基线锚定、更新协议、模块要点格式、追踪表格式、执行方式、输出与自检骨架均自动继承通用基座与《[监测报告通用规范](../monitoring-common-spec.md)》，本文件只写**类型差异**；与上层冲突时以本文件为准。

## 类型差异 T1 · 输出形态与结构

- 产出：**中文行业调研报告**（Markdown + 自包含 HTML 双格式），版本命名 `{主题}报告_{{REPORT_VERSION}}.md`（`{{REPORT_VERSION}}` 已含 `v` 前缀，文件名不得再重复加 `v`）。
- 结构采用通用规范第五节**九段式**（可裁剪），本类型默认模块划分：

```text
一、核心结论（摘要）
二、{制度/政策框架模块}      — 签证/准入制度、政策动向
三、{供需与薪资模块}         — 缺口、薪资基准（岗位 × 地域分层）、成本模型（推断须标注）
四、{行业态势模块}           — 行业事件、重点主体、雇佣动向
五、{技术/展望模块}          — 技术趋势对岗位的影响（全部标注"推断"）
六、就业落地建议（结论章）    — 路径、渠道、清单、风险与维权
七、数据可靠性与局限说明
八、参考来源清单（完整 URL）
```

- 受众定位（第 3 层实例化）：面向"拟赴 {{REGION}} 从事 {{TOPIC}} 工作"的读者，兼具行业监测与求职落地顾问视角。

## 类型差异 T2 · 术语口径纪律

制度/岗位/资质类术语在正文中不得混用（第 3 层列出本项目的术语口径区分清单，如签证制度之间、岗位类别之间的区分），引用数据须注明所属制度。

## 类型差异 T3 · 执行分工建议

并行子代理按模块分工建议 4–6 个：① 制度/准入路径；② 供需 + 薪资交叉验证；③ 行业态势 + 企业动态；④ 技术/展望；⑤ 落地手续 + 风险与维权。全部限定 `{{SOURCE_LANGUAGE_RULE}}`、逐点引用。

## 类型差异 T4 · 项目专属必填区（第 3 层填写清单）

第 3 层项目提示词 = 本类型模板 × 以下配置：

1. 【项目专属约束区】来源语言规则、受众、禁用来源类型
2. 【来源优先级实例化】通用规范五层框架 → 具体域名/机构清单
3. 【术语口径区分清单】
4. 【事件触发器表】→ 触发模块编号
5. 【各模块更新要点】按 T1 模块划分填写"更新/动态获取/保持"
6. 【关键监测指标追踪表】编号 + 指标 + 优先数据源（**prompt 内严禁填活值**；活值存 `{{REGISTRY_PATH}}`，格式见通用基座五-A）
7. 【已修正事实清单】首期为空，随修正追加
8. 【指标登记册】运行前读、运行后写 `{{REGISTRY_PATH}}`；首期运行须同时创建登记册并填入基线值
