# 主题知识手册拆分标准化提示词模板（handbook-split-standard）

> **定位**：跨主题共享的**内容结构化拆分操作规范 + 可直接复用提示词模板**。沉淀自 12-culture-life 拆分实践（2026-11-14，提交 4d3e200），供其余全部待处理主题（以各主题 `reports/` 基线报告是否含合并附录手册为准；`00-decision-hub` 为跨主题决策层、无手册正文，不适用）统一执行依据。
>
> **目标**：将「分析报告 + 知识手册合并单文件」的密集式信息罗列，转化为「时序报告（reports/）+ 细分主题手册（handbook/）」的层次化结构，全程**内容信息零改动**。
>
> **继承**：本文件为根部共享规范，与 [monitoring-common-spec.md](./monitoring-common-spec.md)（渲染/交付最低标准）、[prompt-generic-base.md](./prompt-generic-base.md)（质量规则）配合使用；报告正文骨架与监测机制以各业务 `business-config.md` 为单一事实源。

---

## 一、核心设计原则（不可协商）

1. **双产物分离**：`reports/` = 时序监测产物（基线固定、按节拍追加），`handbook/` = 长效知识参考（按维度独立维护）。二者性质不同，永不合并回单文件。
2. **编号即接口**：handbook 维度编号（01–05 或该主题实际维度数）必须与报告**登记册指标 # 与触发器 →01–05 映射一一对应**——不重排、不改号、不插入新编号。这是拆分方案的首要约束。
3. **内容层零改动**：事实、来源 URL、核验标注（`[Source: URL, 年份]`、`title="来源：URL, 年份"`）、推断标记、待复核表述、HTML 注释（`<!-- updated: … -->`）一律原样搬运。
4. **导航层可改但须披露**：文件一览表路径、front 说明、更新日志新增条目、待复核清单归属标注、文件末尾导航脚注、章节标题层级提升（原合并版 H3/H4 → 独立文件 H1/H2）——全部属于导航层调整，须在更新日志与实施报告中逐项披露。
5. **先方案后执行**：拆分分两阶段——先输出完整拆分方案（目录结构 + 归属映射 + 边界裁定 + 效果预期）供确认，确认后才执行文件操作。

## 二、阶段一：拆分方案（只读展示，不执行）

### 2.1 目标目录结构模板

```
{{TOPIC_DIR}}/
├── operations-guide.md                    # 不动
├── prompts/                               # 不动
├── data/{{TOPIC_SLUG}}_indicator_registry.md   # 不动（活值唯一权威源）
├── reports/                               # 时序报告区
│   ├── {{YYYY-MM}}-{{TOPIC_SLUG}}.md      # 正文骨架不动，附录 → 链接指针
│   ├── {{YYYY-MM}}-{{TOPIC_SLUG}}.html    # 管线重建，降级为报告专用
│   └── archives/
│       └── {{YYYY-MM}}-{{TOPIC_SLUG}}-merged-v{N}.md   # 原合并版全文快照
└── handbook/                              # ★ 新增
    ├── 00-navigation.md                   # 导航与使用约定（索引/关联目录/使用约定/更新日志/待复核清单含归属标注）
    ├── 01-{{DIM_SLUG_1}}.md               # 维度一（编号 = 登记册/触发器映射）
    ├── 02-{{DIM_SLUG_2}}.md               # 维度二 …
    └── 0N-{{DIM_SLUG_N}}.md               # 维度 N
```

- 文件命名：小写 kebab-case 英文 + 中文 H1 标题；单文件目标 **≤90 行**。
- **子节升级预案**：某子节体量 >80 行且具独立复核节奏（如防灾之于生活指南）时，默认保留在原维度文件内以维持触发器编号定位；增长超阈值后升级为 `{编号}a-{{SLUG}}.md`（`02a` 不占用 `06` 位号，避免与未来新维度冲突）。

### 2.2 归属映射表（必产出）

| 目标文件 | 承载的原内容 | 约量 |
|---|---|---|
| handbook/00-navigation.md | 手册头部说明、主题索引、文件一览表、关联目录、使用约定、更新日志、待复核清单 | ~N 行 |
| handbook/01-….md | 手册 01 章全部 | ~N 行 |
| … | …（每小节唯一去向，逐行列尽） | ~N 行 |
| reports/{报告} | 正文整体保留；附录替换为指针 | ~N 行 |

- **遗漏检查**：原手册每一小节在上表中均有唯一去向；报告部分整体保留不拆。
- 拆分前统计基线：原文件总行数、附录部分 URL 计数（后续守恒验证的基准）。

### 2.3 边界裁定表（必产出）

对「同一话题出现在两个章节」的每一处重叠，按下表规则裁定权威归属：

| 重叠类型 | 裁定规则 |
|---|---|
| 制度 / 资源 / 流程类 | 归对应制度章（如心理健康资源 → 医疗章）；生活章仅保留概述级一句 + 链接 |
| 生活经验 / 场景类 | 归生活指南章；制度章只留制度侧 |
| 章内冗余（如防灾袋在第 3 节与第 6 节） | 权威小节为准；重复句保留原文不删，执行时补一条指向权威小节的内链 |
| 跨主题边界（维权→09、税费→07、在留→08、现场安全→02-career、地域→13 等） | 原有跨主题链接与边界引注**原样保留**，不在本主题展开 |

### 2.4 效果预期（必产出）

拆分前后对比：单文件最大行数、文件数、检索直达性、报告基线稳定性、季节性复核定位；并声明编号体系兼容性。

## 五、链接与锚点规范

1. **Markdown 锚点 slug**（GitHub 风格）：保留 CJK/字母数字/连字符，剔除标点（、。（）·／：等），空格转连字符，整体小写。例：`### 03 维权与合规工具箱` → `#03-维权与合规工具箱`；`## 六、防灾与应急` → `#六防灾与应急`。
2. **HTML 锚点双通道**：`md2html.py` 已实现——h2 重编号 `id="sN"`（导航）+ 每个标题内注入 `<a id="{{github-slug}}" aria-hidden="true"></a>`（跨主题中文锚点）。跨主题 `.html#中文锚点` 链接因此可直接书写，无需改用 sN。
3. **引用侧一致性**：写跨主题锚点链接时，slug 必须与目标 md 标题按第 1 条规则核对（历史上出现过标点转连字符的笔误，如 `#02-增长赛道-ec-冷链-3pl` 应为 `#02-增长赛道ec冷链3pl`）。
4. **全部链接目标必须在仓库内可达**：相对链接逐条解析验证；外部 URL 保持完整（`[Source: 完整URL, 年份]` 行内引用不删除）。

## 八、HTML 预览/实施报告页风格统一标准（会话产物，不入库但风格统一）

### 8.1 设计系统（CSS 变量，禁止散落硬编码色值）

```css
:root {
  --bg: #f7f6f2;      /* 页面底 */
  --bg2: #ffffff;     /* 卡片面 */
  --ink: #26251f;     /* 正文 */
  --muted: #6f6c62;   /* 次级文字 */
  --rule: #e3e1d8;    /* 边框 */
  --accent: #2f6f5f;  /* 主强调（深绿） */
  --accent2: #c26a4a; /* 警示强调（赭橙） */
}
```

- 字体：`"Noto Sans SC", "Microsoft YaHei", "PingFang SC", sans-serif`；代码 `Consolas`；正文 16px / 行高 1.7；标题层级靠字重与留白，不靠多字体。
- 布局：`max-width: 1080px` 居中；sticky 顶部锚点导航；`section + section` 细分隔线；章节标题格式 = `编号章 No. + 大标题`（编号带 accent 下划线短杠）。

### 8.2 组件规范

| 组件 | 规则 |
|---|---|
| 章节标题 h2 | `<h2><span class="no">0N</span>标题</h2>`，编号 accent 色 + 3px 下边框 |
| 信息条 chip | 圆角胶囊；`acc`（accent 边）= 关键事实、`warn`（accent2 边）= 只读/风险声明 |
| 任务/摘要卡 | 白面 + 1px rule 边 + 10px 圆角；完成态右上角 accent 徽标（✓ 完成） |
| 目录树 | 等宽字体 + `├──` 结构；状态徽标：`new`（accent 实底）/ `mod`（accent2 实底）/ `keep`（rule 底灰字） |
| 表格 | `.table-wrap` 容器强制 `overflow: auto`（双向滚动 + max-height）；表头 accent 下边框；行 hover 浅底 |
| 状态 pill | `ok`=PASS/新增、`warn`=风险/既有、`mod`=修改、`new`=新建、`arch`=存档 |
| callout | 左 4px 边框：accent = 约束/结论，warn = 风险/既有问题披露 |
| 统计卡 statgrid | 大数字 accent（警示数字用 accent2）+ 小标签；一屏 4 枚 |
| 图表 | ECharts `renderer: 'svg'`、`animation: false`、`appendToBody` tooltip、颜色一律从 CSS 变量取值、必须有 `figcaption`（含「图 N：」编号）、resize 监听 |
| 页脚 | sources 有序清单（`id="cite-N"`）+ 免责/说明虚线上方分隔 |

### 8.3 重点信息突出规则

1. **关键数字前置**：总量、最大单文件、文件数、改动量 → 首屏统计卡，不让读者从表格里找。
2. **状态语义色**：绿色系（accent）只用于「完成/通过/新增」，赭橙（accent2）只用于「风险/警示/拆分前」，灰（muted）用于「未动/存档」——语义与颜色一一对应，不混用。
3. **必披露项**：零改动证据、既有问题（非本次引入）、导航层改动清单——分别用表格行、warn callout、正文加粗呈现。
4. **层级节奏**：每节 = 一句 `sec-sub` 导语 + 表格/卡片主体 + 收尾 callout 结论；避免无导语的密集罗列。

### 8.4 页面骨架模板

```
topnav（sticky 锚点）→ hero（kicker/标题/副标题/meta chips）
→ 01 任务完成状态（卡片 + 徽标）
→ 02 变更内容明细（全量文件表 + 链接改写明细 callout）
→ 03 拆分后目录结构（tree + 兼容性 callout）
→ 04 验证结果说明（statgrid + 验证方法表 + 披露 callout）
→ 05 前后对比（statgrid + ECharts 行数对比图）
→ 06 后续建议（表：事项/说明/优先级 pill）
→ footer（sources + disc）
```
