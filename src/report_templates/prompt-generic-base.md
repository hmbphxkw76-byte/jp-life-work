# 监测报告通用基座（类型中立）

> **用途**：本项目所有监测报告提示词的**第一层继承基座**。定义跨报告类型、跨业务线共享的质量规则、运行变量框架、来源分级框架与执行协议。本文件为通用模板，**不含任何业务限定性内容**（地区、物业类型、机构清单均由业务层配置实例化）。
>
> **继承体系（四层）**：业务提示词 = [本文件（通用基座）](./prompt-generic-base.md) × [监测报告通用规范](./monitoring-common-spec.md) × 报告类型模板（按 [类型注册表](./template-registry.md) 分目录存放）× 业务专属配置（`{地区}/{业务类型}/prompts/business-config.md`）。冲突优先级：**业务提示词 ＞ 类型模板 ＞ 本文件 ＞ 通用规范**。

## 一、文档体系与新增业务线指引

### 1.1 目录结构约定

```
macropulse-reports/
├── report_templates/                     # 通用层（本目录，禁止出现业务关键词）
│   ├── prompt-generic-base.md            # 通用基座（本文件，类型中立）
│   ├── monitoring-common-spec.md         # 监测报告通用规范（跨类型共享最低渲染标准）
│   ├── template-registry.md              # 类型注册表（分类架构接入点）
│   ├── market-monitoring/                # 类型：市场指标监测型
│   │   ├── prompt-baseline-setup-template.md
│   │   ├── prompt-monthly-monitor-template.md
│   │   ├── prompt-quarterly-analysis-template.md
│   │   └── prompt-annual-review-template.md
│   └── employment-research/              # 类型：职业就业调研型
│       ├── prompt-baseline-setup-template.md
│       └── prompt-update-template.md
└── {REGION}/{PROPERTY}/                  # 业务层（按「地区 / 业务类型」平铺）
    ├── prompts/
    │   ├── business-config.md            # 业务专属配置（变量 / 来源 / 口径 / 阈值）
    │   └── prompt-{cycle}.md             # 业务周期提示词（继承对应类型模板）
    ├── data/                             # 指标台账
    ├── script/                           # 业务专属脚本（可选）
    └── reports/                          # 报告产出
```

- `report_templates/` 内任何文件**严禁**出现具体地区名、业务类型名、专属机构名、专属指标数值。
- 通用逻辑修改只改通用层根部文件，自动对所有业务线生效；类型模板修改只对该类型业务线生效；业务线之间互不影响。类型清单与新增类型接入步骤见[类型注册表](./template-registry.md)。

### 1.2 新增业务线步骤（不改通用模板）

1. 复制 `{REGION}/{PROPERTY}/` 结构，建立 `prompts/`、`data/`、`reports/`（可选 `script/`）。
2. 撰写 `business-config.md`：填入变量区、来源优先级实例化、术语口径、受众定位、信号阈值。
3. 按业务类型注册的节拍设计建立周期提示词（头部继承声明指向 `../../../report_templates/<类型ID>/` 下对应类型模板，类型清单见[类型注册表](./template-registry.md)），正文只写业务专属内容。
4. 首期运行基线提示词，建立台账与基线锚。

## 二、通用运行变量框架

所有周期提示词的「运行变量」区必须包含以下变量（值由业务配置或运行时填写）：

```
{{REGION}}               = 报告覆盖地区（业务配置固定值）
{{TOPIC}}                = 监测主题 / 物业类型（业务配置固定值）
{{CURRENT_DATE}}         = 本次执行日期，格式 YYYY-MM-DD
{{CADENCE}}              = 周期：月 / 季 / 年（基线报告为机制建立期）
{{BASELINE_DATE}}        = 首期基线日期（仅基线报告必填）
{{REGISTRY_PATH}}        = 指标台账路径（业务配置固定值，业务目录相对路径）
{{REGISTRY_FORMAT}}      = 登记载体格式（如 xlsx-ledger）
{{BASELINE_REPORT_PATH}} = 首期基线报告路径（周期报告必填）
{{PREVIOUS_REPORT_PATH}} = 最近一期同周期报告路径（基线报告无此项）
{{OUTPUT_PATH}}          = 本期报告落盘路径
{{OUTPUT_REGISTRY}}      = 新版台账落盘路径（仅年度复盘必填）
{{REPORT_VERSION}}       = 本期版本号
{{FRESHNESS_PRIORITY}}   = 时效优先级（业务配置固定值，默认：最新官方页 > 上期值 > 预测值）
{{SOURCE_LANGUAGE_RULE}} = 来源语言规则（业务配置固定值，如：仅英文 / 仅日文官方+英文权威）
```

**变量纪律**：

- prompt 模板内严禁填写指标活值；运行前从 `{{REGISTRY_PATH}}` 读取、运行后回写。
- 路径变量一律使用业务目录相对路径（如 `reports/…`、`data/…`），保证业务线可整体迁移。
- 引用仓库原始文件链接时使用 `{{REPO_RAW_URL_BASE}}` 基址变量（值在业务配置中定义），不在通用模板硬编码仓库地址。

## 三、通用硬性约束（所有报告自动继承）

以下约束为最低标准，业务配置可加严、不得放宽：

1. **逐点引用**：每个关键数字、每条结论必须可回溯到「来源机构 · 统计周期 · 发布日期 · 核验状态」，正文以来源注承载。
2. **事实与推断分离**：事实（有来源）与推断（机制分析）明确区分；自算值标「自算」，预测值标「预测值（F）」，计划值标「计划值」。
3. **口径标注**：同一指标多口径并列呈现，不得静默择一或取均值；术语口径不得混用（具体口径清单由业务配置定义）。
4. **数据纪律**：不编造任何缺失数据、日期、URL、机构名；数据未发布时使用最近已发布值并注明，不补值、不外推；「没有数据」写成可核验的陈述。
5. **结论边界**：不给出具体买卖价位、杠杆比例、仓位建议；只给「条件 → 周期判读 → 框架性含义 → 风险提示」。
6. **受众定位**：由业务配置定义；通用层默认要求报告明确声明其受众与视角。
7. **模块边界声明集中**：报告 / 骨架中的「含 / 不含 / 口径」边界声明统一集中在单独章节（如「零、模块边界声明」），不在各节重复；由 `skeleton_builder.py` 生成时自动集中。

## 四、来源分级通用框架

通用分级为四层，具体机构清单由业务配置「来源优先级」实例化：

| 层级 | 范围 | 采信规则 |
|---|---|---|
| ① 官方一手 | 央行 / 统计局 / 主管部门 / 国际组织 | 唯一可直接采信层，标「已核验」 |
| ② 行业机构 | 权威研究机构官方研究页 / PDF | 可采信；PDF 须记录发布日期与页码；预测分歧并列 |
| ③ 挂牌门户 | 门户 / 中介挂牌数据 | 仅作卖方预期或市场情绪，不得替代成交 / 登记数据 |
| ④ 媒体转述 | 通讯社、媒体转载 | 只用于发现线索；数值标「需核实原文」，须回官方页校验 |

- 冲突时按业务配置的优先级链裁决；无法裁决时并列呈现并标注。
- `{{SOURCE_LANGUAGE_RULE}}` 强制执行；不符合语言规则的来源一律排除。

## 五、基线锚定协议（防已修正事实回退）

- 周期报告每次运行必须**读取 `{{PREVIOUS_REPORT_PATH}}`**（首期除外）与 `{{BASELINE_REPORT_PATH}}`，继承其结构、口径裁决与全部已核实结论。
- 每条已核实结论随「已修正事实清单」持续追加，格式：

```
【已修正事实清单 — 首期为空，产生修正后逐条补记，格式如下】
- ❌ 不得再称"…"——正确结论为…。[Source: URL, 年份]
```

- 后续报告如需修正，只能在自身周期内追加，不得回退基线或更早周期的修正记录。
- 基线报告的结构与结论一经产出即为锚，变更须走类型模板的维护规范并联动评估全部周期提示词。

## 六、更新协议框架

- **刷新窗口与差异对比**规则按报告类型模板执行。
- **重大事件触发器**：每条业务线在业务配置中维护触发器清单（格式：`事件 → 受影响模块`）。命中任一触发器即触发对应模块重点更新；**无触发则降级为核验 / 收敛型轻运行，不得为制造变化而虚构变化**。
- 与上期同日或仅隔 1 日时，明确写「本期为 T+1 刷新，官方发布窗口未开，价值在于核验、口径澄清与阈值距离」。
- 时效取舍遵循 `{{FRESHNESS_PRIORITY}}`；同一指标多版本并存时以官方最新发布为准，旧值仅作对比锚。

---

## 七、指标台账协议（登记载体）

- 活值统一维护于 `{{REGISTRY_PATH}}`：运行前读登记载体 → 核验 → 运行后回写登记载体 → 回写报告变更摘要；prompt 模板内不重复维护数值。
- 每期运行须逐项核对追踪表并填写「是否更新」；未变动项保留登记载体值并注明「截至 {{CURRENT_DATE}} 无更新」。
- 台账修改采用增量方式：复制旧版 → 修订 → 另存新版本，不覆盖历史值；报告层补充与台账更新严格区分。

## 八、通用 Agent 执行约定

- 所有步骤遵循「检查 → 执行 → 验证」；重复执行不产生副作用。
- 覆盖输出前先备份；不删除历史报告。
- 不修改只读附件；如需引用，先复制到可编辑目录。
- 不创建与任务无关的文件；中间脚本放在临时目录或 `.ref` 子目录。
- 所有计算必须有公式或口径说明；自算值标「自算」。
- 所有计划值、预测值不得与实绩混算；所有媒体转述必须标「需核实原文」。
- 所有口径冲突必须并列，不得静默择一。
- 报告完成后必须执行该报告类型模板的质量自检清单。
- **交付与审计协议（唯一口径，提示词 / AGENTS / CI 三体系一致）**：报告交付物 = `reports/YYYY-MM-<slug>.md` 源稿 + 同名自包含 `.html`。落盘后、提交前必须按序完成（缺一不得提交）：
  1. **HTML 生成**：`python src/prompts-tools/tools/md2html.py`（仓库根目录执行；任务工作树内运行，共享检出目录禁止），随后 `python src/prompts-tools/tools/lint_reports.py --new-only` 校验交付物；
  2. **落盘前自检**：`python src/prompts-tools/tools/audit_preflight.py --report <报告相对路径>`（P0/P1 必须修正）；
  3. **多层级校验**：`python src/prompts-tools/tools/audit_check.py --report <报告相对路径>`（L1–L5，P0/P1 必须修正）；
  4. **提交审计**：`python src/prompts-tools/tools/audit_pipeline.py --submit --report <报告相对路径>`（提交初审，进入审计状态机）。
  合并门禁：`python src/prompts-tools/tools/audit_pipeline.py --gate`（PR / main 推送；受检报告须 `audited` + 指纹匹配 + 有效 L5 证据）。CI 侧 `html-sync` 负责推送后确定性重生成，`audit-gate` 负责门禁与全量校验。流程与状态见《审计报告标准化管理体系》。

## 九、通用质量自检（各类型模板在此之上追加）

- [ ] 每个关键数字标注来源机构 · 统计周期 · 发布日期 · 核验状态
- [ ] 区分实际值 / 预测值（F）/ 计划值
- [ ] `{{REGISTRY_PATH}}` 已读已写；prompt 模板自身无硬编码活值
- [ ] 已修正事实清单已从上期 / 基线继承并续写
- [ ] 渲染与排版符合[监测报告通用规范](./monitoring-common-spec.md)
- [ ] 已产出「数据变更摘要」与「待复核清单」
- [ ] 已运行 `md2html.py` 生成同名 HTML 并通过 `lint_reports.py --new-only`
- [ ] 已运行 `audit_preflight.py --report` 且无 P0/P1
- [ ] 已运行 `audit_check.py --report` 并修正全部 P0/P1
- [ ] 已 `audit_pipeline.py --submit` 提交初审（未通过初审不得合并）
- [ ] 合并门禁 `audit_pipeline.py --gate` 通过（变更报告均已审计且证据有效）
