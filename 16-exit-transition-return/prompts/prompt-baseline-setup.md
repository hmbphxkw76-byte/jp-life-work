# 日本 退出·转型·回国 首期基线报告提示词（政策法规解读型）

> **用途**：执行「日本 退出·转型·回国 政策解读机制」的**机制建立**任务：产出首期监管框架基线报告与配套政策台账。
> **现状**：本业务线基线将于 2026-11 产出（[reports/{{YYYY-MM}}-<slug>.md](../reports/{{YYYY-MM}}-<slug>.md) + 同名 HTML，v1.0）。**正常运行永不重跑基线提示词**；仅在①报告与登记册全部丢失（灾难恢复），或②经维护规范批准的九节结构重排时启动。
> **产出**：md 源稿 + 同目录自包含 HTML，落盘 `{{OUTPUT_PATH}}`；政策台账回写 `{{REGISTRY_PATH}}`。
>
> **继承声明（四层体系）**：本文件 = [通用基座](../../src/report_templates/prompt-generic-base.md) × [监测报告通用规范](../../src/report_templates/monitoring-common-spec.md) × [基线报告类型模板（政策法规解读型）](../../src/report_templates/policy-analysis/prompt-baseline-setup-template.md) × [业务专属配置](./business-config.md)。冲突时以本文件为准。

**任务目标**：产出九节监管框架基线报告（执行摘要、政策台账与监测机制、监管框架总览、重点政策逐条解读、影响对象矩阵、合规应对建议、生效时间线、数据治理与局限、参考来源清单）与政策台账首建；**官方原文铁律**：全部引用回溯官方公报 / 法规数据库原文并附 URL；运行后回写 `{{REGISTRY_PATH}}`；基线报告**无上期报告**，不读取 `{{PREVIOUS_REPORT_PATH}}`。

## 一、项目专属硬性约束

1. **官方原文铁律**：媒体转述仅作线索；引用逐条附官方原文 URL 与版本日期。中文来源仅作线索定位，引用须回溯日 / 英原文。
2. **只盯官方文本**：不采集舆论反应；原文有歧义处并列多解，不静默择一。
3. **结论边界**：不构成法律意见或税务意见；合规应对建议标「建议」；重大合规决策提示咨询执业法律 / 税务专业人士。
4. **术语口径**：退職 ≠ 退去強制；在留資格取消 ≠ 在留資格変更；特定活動 ≠ 技能実習；再入国許可 ≠ みなし再入国；健康保険任意継続 ≠ 国民健康保険。
5. **边界纪律**：税制、年金制度、脱退金额计算口径归 07；永住、归化、在留资格取消 / 再入国制度正文归 08；赴日落地、保险加入、住房与行政 90 天清单归 14；现场层执行细节归 02；法规条文深度解读归 09。

## 二、来源优先级

见[业务配置第五节](./business-config.md)：① 出入国在留管理庁 / 法務省 / e-Gov ＞ ② 厚生労働省 / 日本年金機構 / ハローワーク ＞ ③ 国税庁 / 総務省 / 地方自治体 ＞ ④ 银行 / 运营商 / 运输 / 车辆相关机构官网（仅执行流程）＞ ⑤ 媒体（仅线索）。每条数据附官方原文 URL 与版本日期。

## 三、基线锚定与重启条件

- 基线报告一经产出即为对比锚：监管框架地图、解读规则与已核实结论由后续事件触发解读完整继承。
- **正常运行不重跑**。重启仅限两种情形：①灾难恢复（报告与登记册全部丢失）；②九节结构经维护规范批准重排。重排须在[业务配置](./business-config.md)第十二节版本记录留痕，并同步评估解读提示词。

## 四、报告结构

九节固定骨架见[基线类型模板第三节](../../src/report_templates/policy-analysis/prompt-baseline-setup-template.md)：

| 节 | 模块 |
|---|---|
| 1 | 执行摘要 |
| 2 | 政策台账与监测机制 |
| 3 | 监管框架总览 |
| 4 | 重点政策逐条解读 |
| 5 | 影响对象矩阵 |
| 6 | 合规应对建议（建议章） |
| 7 | 生效时间线 |
| 8 | 数据治理与局限 |
| 9 | 参考来源清单 |

- 九节标题为固化锚，逐字继承，不得增删节或调整顺序。
- 内容必须覆盖退出、转型、回国三段；不得把主题写成单纯回国清单。

## 五、追踪表与边界档案

按[业务配置第八节](./business-config.md)的 12+1 项追踪指标逐项核对并填写「是否更新」；运行后回写 `{{REGISTRY_PATH}}` 的核心指标与[研究边界档案](./business-config.md)（领域边界、三段分层、主体清单与入选标准、口径清单）。未核实项注明「待核实」，不补值、不外推；prompt 模板内不填活值。

## 六、执行方式（建议）

1. 原文回溯先行：逐渠道核对官方原文，完成台账登记后才进入解读环节。
2. 并行启动 2–4 个研究子代理：① 退出与保险；② 转型与在留资格；③ 回国与税务；④ 退室 / 车辆 / 通信。全部限定日 / 英来源、逐点引用，每条数据附可直接访问的 URL。
3. 主代理合并差异，冲突口径保留双份引用，无法核实项单列「待复核清单」。
4. 与现行制度冲突的解读须并列新旧对照；无法核实项单列「待复核清单」。

## 七、渲染与交付

- 交付格式：md + 同目录自包含 HTML（`python src/prompts-tools/tools/md2html.py`）；HTML 须通过 `python src/prompts-tools/tools/lint_reports.py`。
- 基线导航采用简化锚点目录，不强制 `.report-nav`。
- 落盘后将[业务配置第一节](./business-config.md)的 `{{BASELINE_REPORT_PATH}}` 指向本报告（重建场景）。

## 落盘后审计（提交前必做）

落盘后依次运行 `python src/prompts-tools/tools/audit_preflight.py --report <报告相对路径>`、`python src/prompts-tools/tools/audit_check.py --report <报告相对路径>`，修正全部 P0/P1 后执行 `python src/prompts-tools/tools/audit_pipeline.py --submit --report <报告相对路径>` 提交审计（未通过初审不得合并）。
